## 배경

사용자 요청(2026-09-19). "공방일지에서 발행한 글을 주요 SNS로 내보내기 할수있게
해줘."

글 아래 공유 줄(`IDE-029`)은 **방문자가** 누르는 버튼이다. 이번 요청은 반대편 —
**주인이 글을 낸 뒤 자기 SNS 계정에 알리는 일**이다. 지금은 글을 내고 나서 SNS
마다 앱을 열어 제목을 옮겨 적고, 대표 사진을 다시 고르고, 링크를 붙인다. 링크에
utm 을 붙이려면 `/admin/share` 로 따로 가야 하고, 안 붙이면 그 방문은 `IDE-033`
의 표에서 인앱 브라우저나 `direct` 로 흩어진다.

## 이미 있는 것

- 글마다 **제목 · 요약(`summary`) · 대표 사진(`cover_url`) · 발행 시각**이 있다
  (`db/migrations/007-posts.sql`). 공유 카드(OG · `summary_large_image`)도 이미
  글마다 선다(`blog/[slug]/page.tsx` 의 `generateMetadata`)
- utm 링크를 만드는 함수가 하나로 모여 있다 — `buildShareUrl`
  (`lib/analytics/shareLinks.ts`). 방문자 공유 줄도 이것을 쓴다(`lib/share/targets.ts`)
- 페이스북은 **주소만 열면** 공유 창이 뜬다(`facebookShareUrl`). 공유 줄이 이미 쓴다

## 무엇을 고르나

**궁극적으로는 API 자동 게시(B), 먼저 내보내기 꾸러미(A)**(2026-09-19 사용자
결정). 대상은 **페이스북 · 링크드인 · 인스타그램 · 네이버 블로그** 넷이다 —
앞의 둘은 사용자가 주로 쓰는 곳이고, 뒤의 둘은 이 사이트의 독자(아이와 종이
게임을 뽑는 부모)가 있는 곳이다.

| 플랫폼        | 한도  | 본문 주소 | 사진 | 글쓰기 창                                 |
| ------------- | ----- | --------- | ---- | ----------------------------------------- |
| 페이스북      | 5,000 | 눌린다    | 선택 | `sharer.php` — 주소만. 문구는 복사해 둔다 |
| 링크드인      | 3,000 | 눌린다    | 선택 | `feed/?shareActive&text=` — 문구까지 채움 |
| 인스타그램    | 2,200 | 안 눌림   | 필수 | 없음 — 사진 받아 앱에서 올린다            |
| 네이버 블로그 | 5,000 | 눌린다    | 선택 | `share.naver.com` — 제목·주소만           |

B 는 따로 이슈를 연다. 그때 걸리는 것:

- 플랫폼마다 **개발자 앱 등록 · OAuth 토큰 보관 · 갱신**. 메타 계열(인스타그램 ·
  페이스북 페이지)은 **앱 심사**를 거친다. 페이스북은 **개인 타임라인에 올리는
  API 가 없다** — 페이지여야 한다
- 인스타그램은 비즈니스/크리에이터 계정이어야 하고 사진이 필수다
- 링크드인은 개인 계정 게시(`w_member_social`)가 셀프 서비스로 열린다 — 넷 중
  가장 쉽다
- 네이버 블로그는 글쓰기 API 가 닫혀 있어 **B 에서도 수동**으로 남는다
- 예약 공개(`IDE-022`)된 글은 "발행 순간"에 서버가 깨어 있지 않다 — 크론이 필요하다

## 수용 기준

- [x] 낸 글의 편집 화면에서 플랫폼마다 문구 · 링크 · 대표 사진을 한 자리에서 얻는다
- [x] 조립한 문구가 그 플랫폼의 한도를 넘지 않고, 링크가 잘리지 않는다 — 요약
      5,000자 · 제목 3,000자로 시험했다. 손으로 고쳐 넘치면 글자 수가 빨갛게 된다
- [x] 내보낸 링크로 들어온 방문이 **소셜 · 해당 소스**로 잡힌다 — `channelOf` 로
      넷 다 확인. `naver_blog` 가 `naver.` 를 품고도 검색으로 새지 않는다
- [x] 안 낸 글 · 예약된 글 · 내린 글에서는 칸이 열리지 않는다
- [x] 외부 스크립트를 새로 싣지 않는다 — 창은 주소로만 연다
- [ ] ⚠︎ 네 플랫폼에 실제로 올려 카드(제목 · 요약 · 대표 사진)가 뜨고, 그 링크로
      들어온 방문이 대시보드의 소스 표에 잡히는지 확인

## 결정 기록

- **2026-09-19 — 이슈를 열었다.** 방식(A 꾸러미 / B 자동 게시)과 대상 플랫폼은
  사용자 답을 기다린다.
- **2026-09-19 — 사용자 결정: 궁극적으로 B, 먼저 A.** 주로 쓰는 SNS 는 페이스북과
  링크드인이고, 블로그 성격상 인스타그램과 네이버 블로그에도 내보내야 한다고 봤다.
- **2026-09-19 — 플랫폼 이름을 `SHARE_PRESETS` 에서 읽는다.** `/admin/share` 에서
  손으로 만든 페이스북 링크와 이 칸이 만든 링크가 다른 `source` 를 쓰면 같은 채널이
  표에서 두 줄이 된다. 베껴 적으면 언젠가 어긋나므로 **없으면 모듈이 뜨지 않게**
  했다(`preset()` 이 던진다).
- **2026-09-19 — 캠페인을 붙인다(`devlog-<슬러그>`).** 방문자 공유 줄의 페이스북
  링크도 `facebook / social` 이다. 캠페인이 없으면 "주인이 올린 글"과 "누군가 퍼
  나른 링크"가 표에서 구별되지 않는다. 슬러그를 넣어 **어느 글이** 데려왔는지도
  캠페인 표에서 읽힌다.
- **2026-09-19 — 인스타그램 본문에는 주소를 적지 않는다.** 눌리지 않는 주소는
  지저분하기만 하다. "프로필 링크" 안내를 적고, 프로필에 걸 utm 링크를 따로 준다.
- **2026-09-19 — 문구는 고칠 수 있게, 저장은 안 한다.** 조립한 것은 출발점이다.
  올리고 나면 쓸 데가 없는 값이라 DB 에 칸을 늘리지 않았다.
- **2026-09-19 — 창이 문구를 못 받는 곳은 복사한 뒤 연다.** 창을 먼저 열면 이
  화면이 포커스를 잃어 클립보드 쓰기가 막힌다.
- **2026-09-19 — 링크드인은 문서화되지 않은 `shareActive` 를 쓴다.** 공식 주소
  (`share-offsite`)는 주소만 받아 문구를 다시 붙여 넣어야 한다. 막히더라도 문구는
  이 화면에 있으니 붙여 넣으면 된다 — 잃는 것이 작다.
