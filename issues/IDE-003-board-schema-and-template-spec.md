## 배경

제품 방향은 **큐레이션 템플릿 + 사용자 커스터마이즈**로 정해졌다(2026-09-03). 즉
운영자가 만든 도안 안에 "사용자가 고칠 수 있는 자리"가 선언되어 있어야 한다. 축구
게임판이라면 선수 22명의 등번호, 양 팀 이름, 팀 색이 그 자리다.

그리고 **게임 하나가 종이 한 장이 아니다.** 축구 게임판은 핵심 게임판(운동장)과
오려 쓰는 부속(점수 기록칸, 게임 방법), 그리고 **접어서 세우는 조립물**(골대,
주사위)로 나뉜다. 사용자가 직접 만든 판에서 골대가 종이 상자였던 것이 이 구분의
근거다. 사용자는 이것들을 따로,
서로 다른 배율로 뽑을 수 있어야 한다. 모델이 이 분리를 표현하지 못하면 내보내기에서
특수 처리가 계속 생긴다.

이 규격이 흔들리면 게임을 추가할 때마다 에디터를 새로 짜게 된다. 도안이 늘어나기
전에 못을 박아둔다.

## 할 일

- [ ] 게임 메타데이터 스키마 정의 — id, 제목, 소개, 인원, 준비물, 썸네일
- [ ] **파트 구조 정의** — 게임 = 보드 파트 1개 + 부속 파트 N개. 파트별 역할, 기준 크기(mm), 기본 배율
- [ ] 파트 종류 구분 — 보드 / 오림용 부속 / 조립물(골대·주사위 전개도)
- [ ] 파트별 인쇄 방향(가로·세로) 속성 정의 — 축구 게임판의 보드는 가로다
- [ ] 커스터마이즈 슬롯 타입 정의 — 텍스트 · 숫자 · 색상 · 선택지와 각각의 제약
- [ ] **위치를 가진 슬롯** 정의 — 값뿐 아니라 좌표(x, y)가 사용자 편집 대상인 슬롯. 축구 게임판의 선수 22명이 그렇다
- [ ] **배치 프리셋** 정의 — 이름 + 슬롯 좌표 집합. 전술 대형(4-4-2 등)이 여기 담긴다
- [ ] **마커 스타일 변형** 정의 — 같은 슬롯을 원형 / 일러스트 두 가지로 렌더링할 수 있게
- [ ] 슬롯이 어느 파트에 속하는지 표현 (등번호는 보드, 팀명은 양쪽 모두에 나올 수 있다)
- [ ] 도안 작성 규약 정의 — 슬롯 표시 속성, 좌표계와 단위(mm) 기준
- [ ] 오림선 · 접는선 · 풀칠면 표시 규약 정의 (부속·조립물 파트용)
- [ ] 스키마 런타임 검증 도입 — 잘못된 도안은 빌드나 로딩에서 즉시 실패하게
- [ ] 축구 게임판을 예시 인스턴스로 작성해 규격이 실제로 표현 가능한지 확인
- [ ] 게임 자산 디렉터리 구조와 등록 방법 결정

## 수용 기준

- [ ] 스키마 타입 정의와 검증 코드가 있고 단위 테스트가 붙어 있다
- [ ] 축구 게임판이 보드 · 부속 · 조립물 파트로 나뉘어 스키마를 통과한다
- [ ] 파트마다 인쇄 방향이 선언되고, 가로 보드가 올바른 방향으로 렌더링된다
- [ ] 파트별로 따로 출력 대상을 고를 수 있는 정보가 모델에 들어 있다
- [ ] 슬롯이 없거나 · 중복이거나 · 타입이 틀리거나 · 어느 파트에도 속하지 않는 도안이 검증에서 오류로 걸러진다
- [ ] 축구 게임판의 선수 슬롯 22개가 좌표를 갖고, 대형 프리셋이 스키마로 표현된다
- [ ] 프리셋의 좌표가 필드 범위를 벗어나면 검증에서 걸러진다
- [ ] 새 게임을 추가하는 절차가 3단계 이내로 문서에 적혀 있다
