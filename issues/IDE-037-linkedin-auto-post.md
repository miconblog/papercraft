## 배경

`IDE-034` 의 사용자 결정은 "궁극적으로 API 자동 게시(B), 먼저 꾸러미(A)"였다.
A 가 들어간 뒤 2026-09-19 사용자가 "남은거 다 가자"로 B 의 첫 단추를 정했다. 넷
가운데 링크드인이 가장 쉽다 — 개인 계정 게시 권한(`w_member_social`)이 **앱 심사
없이** 열리고, 사용자가 주로 쓰는 둘 중 하나다. 페이스북은 개인 타임라인 게시
API 가 없고(페이지여야 한다), 인스타그램은 비즈니스 계정과 메타 앱 심사가, 네이버
블로그는 글쓰기 API 자체가 없다.

## 결정 기록

- **2026-09-19 — 올리기는 결과를 돌려주고 화면을 다시 그리지 않는다.** 다시
  그리면 카드에서 고친 문구가 처음 모양으로 돌아가, 무엇을 올렸는지가 화면에서
  사라진다.
- **2026-09-19 — 썸네일이 실패해도 글은 올린다.** 썸네일 하나 때문에 글을 못
  올리면 잃는 것이 더 크다. 없이 올라갔으면 화면이 그렇다고 말한다.
- **2026-09-19 — 올린 기록이 실패해도 "올렸습니다"다.** 글은 이미 링크드인에 있다
  — 실패로 돌려주면 주인이 한 번 더 올린다. 기록을 못 남겼다는 것만 덧붙인다.
- **2026-09-19 — 다시 올리기를 막지 않고 묻는다.** 고쳐서 다시 올리는 것은
  주인이 정할 일이다.
- **2026-09-19 — 토큰을 앱에서 암호화하지 않았다.** 표는 RLS 로 서비스 롤만
  닿는다. 서비스 롤 키가 새면 어차피 이 표도 열린다 — 같은 키로 푸는 암호화는
  지키는 것이 없다.
- **2026-09-19 — 콜백 주소를 요청의 호스트로 만든다.** 로컬과 운영이 각자
  돌아오게. 개발자 앱에 둘 다 적어 둔다.
- **2026-09-19 — 운영 DB 에 `013` 을 아직 적용하지 않았다.** 공유 Postgres 에
  표를 새로 만드는 일이라 사용자 확인을 받는다. 앱은 키가 없으면 이 표를 읽지
  않으므로, 적용 전에 머지·배포해도 아무것도 깨지지 않는다.
- **2026-09-19 — 사용자 확인을 받아 운영 DB 에 `013` 을 적용했다.** 적용 결과는
  할 일 칸에 적었다.
