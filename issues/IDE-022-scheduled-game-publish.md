## 배경

사용자 요청(2026-09-09). **새 게임을 만들어 두고 정한 날에 맞춰 공개하고
싶다.** 지금은 게임을 등록소에 넣는 순간 세상에 열린다 — 도안이 다 되기 전에
커밋하면 그대로 보이고, 날을 맞추려면 그날 사람이 직접 배포해야 한다.

## 왜 그냥 되지 않나

**지금 게임은 컴파일 시점에 박혀 있다.** `registry.ts`가 도안 다섯을 import 로
들고 있고, `/games/[id]`·`/games/[id]/edit`·`/games/[id]/print` 셋이 모두
`generateStaticParams`로 미리 그려진다. 목록도 `GAMES`를 그대로 읽는다.

그래서 "오픈일이 지나면 저절로 열린다"가 공짜로 안 된다 — **정적으로 그려진
페이지는 시간이 지나도 다시 그려지지 않는다.** 오픈 시각에 사람이 아무것도
하지 않아도 열리게 하는 것이 이 이슈의 어려운 부분이고, 날짜를 어디에 적느냐는
그다음 문제다.

## 오픈일은 Supabase 에 둔다

**2026-09-09 사용자 결정.** 도안 정의에 `publishAt` 필드를 더하는 쪽이 DB 없이
끝나고 정적 생성도 지켜지지만, 그러면 날짜를 바꿀 때마다 코드를 고쳐 재배포해야
한다 — 요청이 "**관리자 메뉴에서** 지정"이므로 그 방식은 요청을 충족하지 못한다.

`IDE-013`이 세운 `daddys_craft` 스키마에 표 하나를 더한다. 그 이슈가 잡아 둔
규약을 그대로 탄다 — RLS 를 켜고 정책을 하나도 만들지 않으며, 스키마 권한을
회수한 뒤 `service_role`에게 필요한 만큼만 연다. 서버만 이 표를 읽고 쓴다.

**게임 자체는 여전히 등록소에 있다.** DB 가 갖는 것은 "언제 열리는가" 한 칸뿐이고,
도안·규격·아트워크는 코드에 남는다. DB 가 비어 있거나 꺼져 있으면 **전부 공개**로
읽는다 — 분석이 죽어도 도안이 나와야 한다는 `IDE-013`의 원칙과 같은 방향이고,
지금 열려 있는 게임 다섯이 DB 사고로 사라지는 일이 없어야 한다.

## 숨긴다는 것이 어디까지인가

목록에서만 빼면 **URL 을 아는 사람은 그대로 들어간다.** 예약 공개라고 부르려면
들어가는 길을 전부 막아야 한다.

| 자리                        | 오픈 전 동작                                                     |
| --------------------------- | ---------------------------------------------------------------- |
| 홈·카탈로그 목록            | 나오지 않는다                                                    |
| `/games/<id>`               | 404                                                              |
| `/games/<id>/edit`·`/print` | 404                                                              |
| PDF 내보내기 API            | 404 — 화면을 막아도 API 가 열려 있으면 도안이 통째로 새어 나간다 |
| `sitemap.xml`·메타데이터    | 실리지 않는다                                                    |

**관리자는 오픈 전에도 봐야 한다.** `IDE-013`의 관리자 세션 쿠키(`session.ts`)가
있으면 통과시킨다 — 그래야 공개 전에 실물로 확인하고 날짜를 정한다.

## 시각을 어떻게 판정하나

날짜 경계는 **KST** 다. `analyticsDay`가 이미 같은 경계를 쓰고 있어 여기에
맞춘다 — 둘이 어긋나면 "오픈일의 방문 수"가 이틀에 걸쳐 쪼개진다.

정적으로 그려진 페이지가 시각을 넘겨 저절로 열리게 하는 방법을 정해야 한다.
후보는 시간 기반 재검증(`revalidate`)과, 페이지는 정적으로 두고 공개 여부만
동적으로 판정하는 방식이다. **정밀도와 캐시 효율을 맞바꾸는 선택**이라
`node_modules/next/dist/docs`의 캐시·재검증 문서를 읽고 정한다.

"몇 시에 열리나"도 정해야 한다. 날짜만 두면 KST 자정에 열린다.

## 결정 기록

- **2026-09-09 — 오픈일은 Supabase 에 둔다**(사용자 결정). 도안 정의에 필드를
  더하면 DB 는 필요 없지만 날짜를 바꿀 때마다 재배포해야 해서, "관리자 메뉴에서
  지정"이라는 요청 자체가 성립하지 않는다.
- **2026-09-09 — DB 가 없으면 공개로 읽는다.** 분석이 죽어도 도안은 나와야 한다는
  `IDE-013`의 방향과 같다. 반대로 두면 Supabase 사고 한 번에 게임 전부가 사라진다.
- **2026-09-09 — 막는 자리는 페이지가 아니라 문지기(`proxy.ts`)다.** 이슈가 남겨
  둔 "정밀도와 캐시 효율" 선택이 여기서 갈렸다. `node_modules/next/dist/docs` 의
  캐시·재검증 문서를 읽고 정했다(이 저장소는 Cache Components 를 켜지 않았으므로
  `caching-without-cache-components` 쪽이다).

  페이지가 스스로 판정하려면 **쿠키를 읽어야 한다** — 관리자를 통과시켜야 하기
  때문이다. 그런데 쿠키를 읽는 순간 `/games/[id]`·`/edit`·`/print` 가 통째로 정적
  렌더링에서 빠진다. `AdminLink` 가 서버에서 쿠키를 안 읽은 것과 같은 이유다.
  문지기는 요청마다 돌면서 캐시 앞에 서므로 **정적 페이지를 정적인 채로 두고도**
  시각을 본다. 빌드 결과가 그대로다 — 화면 셋은 여전히 `● SSG` 다.

- **2026-09-09 — 얼마나 늦게 열리나.** 실서버(`next start`)로 오픈 시각을 과거로
  바꿔 놓고 아무것도 하지 않은 채 재어 봤다.

  | 자리          | 지연     | 무엇이 정하나                                                                              |
  | ------------- | -------- | ------------------------------------------------------------------------------------------ |
  | 주소로 들어옴 | 30초     | 문지기가 든 메모리 캐시(`REQUEST_TTL_MS`)                                                  |
  | 홈 목록       | 60초 + α | 페이지 ISR(`revalidate = 60`). **방문이 있어야** 다시 그려지고, 그 요청은 옛 화면을 받는다 |
  | 관리자가 저장 | 즉시     | 서버 액션이 `updateTag` 로 만료시킨다                                                      |

  문지기 쪽을 30초로 짧게 둔 것은 그쪽이 "URL 을 아는 사람"을 막는 자리이기
  때문이다. 목록은 늦어도 카드가 하나 늦게 붙을 뿐이다.

- **2026-09-09 — 관리자 세션 쿠키 경로를 `/admin` → `/` 로 넓혔다.** 미리보기가
  `/games/...` 와 `/api/games/...` 에서 일어나는데, `/admin` 에 갇힌 쿠키는 그
  요청에 실리지 않는다. 서명한 쿠키를 하나 더 심는 길도 있었지만 같은 비밀에서
  나온 자격이 둘이 되고 로그아웃이 둘 다 지워야 한다 — 하나를 빠뜨리면 조용히
  남는다. `IDE-026` 이 "인증 쿠키를 넓히지 않는다"고 적은 것은 **제외 쿠키**
  이야기였다. 그쪽은 세션이 끝나도 제외가 남아야 했고, 이쪽은 반대로 세션이
  끝나면 미리보기도 끝나야 한다. 넓히기 전에 심긴 `/admin` 짜리는 로그인·로그아웃
  둘 다에서 함께 지운다 — 남겨 두면 같은 이름이 둘 실려 어느 쪽이 읽힐지 브라우저가
  정한다.

- **2026-09-09 — 되돌려보내는 곳은 `/games/__closed` 다.** 미들웨어에서 맨 404 를
  만들어 내면 없는 게임을 친 것과 **다른 화면**이 나오고, 그 차이가 "여기 무언가
  있다"는 신호가 된다. 등록소에 있을 수 없는 id 로 rewrite 하면 상세 페이지가
  `notFound()` 를 내 사이트의 404 가 그대로 나온다. 그 id 가 언젠가 진짜 게임
  이름이 되면 그 게임이 영영 404 가 되므로 등록소 테스트가 막는다.

- **2026-09-09 — `/games/:path*` 한 줄이 화면과 도안 SVG 를 함께 덮는다.**
  `public/games/<id>/*.svg` 가 화면과 같은 이름 아래 있다. 화면만 막고 자산을
  열어 두면 예약 공개라고 부를 수 없다 — 게임판 SVG 는 그 자체로 도안이다.
  API 셋(`export`·`artwork`·`list-search`)은 문지기 밖이라 **각자 한 번 더 본다.**
  거기가 바이트가 실제로 나가는 자리라 matcher 한 줄에 전부를 걸지 않는다.

- **2026-09-09 — 예약 공개를 `ANALYTICS_ENABLED` 에서 떼어냈다.** 실서버로
  확인하다 잡았다. 처음에는 `analyticsConfig()` 를 그대로 썼는데, 이 저장소의
  `.env.local` 에 `ANALYTICS_ENABLED=0` 이 있어 **예약이 통째로 풀려 있었다.**
  그 스위치는 "방문을 세지 않는다"는 뜻이지 "이 DB 를 안 쓴다"는 뜻이 아니다.
  묶어 두면 수집을 끄는 순간 잡아 둔 오픈일이 전부 풀려 게임이 세상에 열린다.
  연결만 읽는 `supabaseConnection()` 을 갈라 두고 이쪽이 그것을 쓴다.

- **2026-09-09 — 몇 시에 열리나: 관리자가 정한다. 기본은 그날 0시(KST).**
  `datetime-local` 로 KST 벽시계를 넣고 KST 로 보여 준다. 담기는 것은 절대
  시각(`timestamptz`)이다. 빈 칸의 기본값이 오늘 0시라, 아무것도 안 고치고
  저장하면 "지금 열기"에 가깝게 동작해 놀랄 일이 없다.

- **2026-09-09 — 서버 액션은 실서버 대신 단위 테스트로 확인했다.** `curl` 로
  서버 액션 요청을 손으로 흉내 내면 React 의 인코딩과 어긋나 500 이 난다(해 봤다).
  화면·API·문지기는 실서버로 확인하고, 저장·해제 액션은 이 저장소가 이미 쓰는
  방식대로 `next/headers`·`next/cache` 를 모킹해서 확인했다.

- **2026-09-09 — 마이그레이션을 적용했다**(사용자 지시). 코드보다 DB 를 먼저
  올린 순서가 맞다 — 반대였다면 `hidden` 칸이 없는 동안 스위치만 조용히 안
  먹었을 것이다(예약은 그대로 돌고). 적용 뒤 칸 넷·RLS 켜짐·정책 0개·
  `service_role` 권한만 있는 것을 확인했고, 앱이 실제로 가는 길(PostgREST)로도
  읽었다. 새 표는 스키마 캐시에 안 잡혀 있을 수 있어 그 확인이 따로 필요했다.

- **2026-09-09 — 관리자 화면을 사이드바로 모았다**(사용자 요청 · 범위 추가).
  이 이슈가 관리자 화면을 둘로 만들면서 통계 화면 헤더에 링크를 하나 붙여 뒀는데,
  셋째 화면이 생기면 그 방식은 곧 무너진다. **메뉴는 한 곳에 두고 화면은 자기
  내용만 그린다.**

  `(shell)` **라우트 그룹**에만 레이아웃을 뒀다. `admin/layout.tsx` 로 두면
  `/admin/login` 까지 감싸서, 아직 들어오지도 못한 사람에게 메뉴와 로그아웃을
  보여 준다. 그룹이면 주소는 그대로면서 로그인 화면만 빠진다.

  이어서 공유 링크를 `/admin/share` 로 뺐다(사용자 요청). 통계는 **지나간 것을
  읽는** 화면이고 공유 링크는 **내보낼 것을 만드는** 화면이라, 한 화면에서
  스크롤로 만나면 둘 다 찾기 어렵다. 그 김에 보낼 곳 목록의 오픈 전 게임에
  「아직 안 열림」을 붙였다 — 이 이슈가 게임을 감출 수 있게 만든 뒤로는, 표시가
  없으면 **죽은 링크를 세상에 뿌리고 나서** 404 인 것을 알게 된다.

  메뉴가 "지금 어느 화면인지"를 알려면 경로가 필요해 `AdminNav` 는 클라이언트
  컴포넌트다. 관리자 화면은 전부 `force-dynamic` 이라 여기서 잃는 것이 없다 —
  헤더의 `AdminLink` 가 쿠키를 서버에서 안 읽은 것과는 사정이 다르다(그쪽은 루트
  레이아웃이라 사이트 전체가 정적 렌더링에서 빠졌다). 색만으로는 스크린리더에
  아무 말도 안 되므로 `aria-current` 를 함께 붙인다.

- **2026-09-09 — 범위를 하나 넓혔다: 지금 당장 내리는 스위치**(사용자 요청).
  "날짜를 실수로 기입해 공개 중인 걸 뒤늦게 확인할 수 있다. 날짜를 조정하는
  것보다 스위치를 꺼서 빠르게 내리고 싶다." 맞는 지적이다 — 급히 내리는 일은
  **되돌리기 쉬워야** 하는데, 미래 시각을 계산해 넣는 조작은 그 자리에서 또
  틀릴 수 있고 나중에 "이 날짜가 진짜 계획인지 급히 밀어 둔 것인지"를 알 수 없다.

  `game_release` 에 `hidden` 칸을 더했다(`006`). **두 칸은 서로 간섭하지 않는다.**

  | 조작        | 건드리는 것 | 안 건드리는 것 |
  | ----------- | ----------- | -------------- |
  | 저장        | 오픈 시각   | 내림           |
  | 지금 내리기 | 내림        | 오픈 시각      |
  | 예약 해제   | 오픈 시각   | 내림           |

  갈라 둔 이유는 하나다 — 하나를 누르다 다른 하나가 조용히 바뀌면 **급할 때 이
  화면을 믿을 수 없다.** 그래서 「예약 해제」도 내려 둔 게임의 줄을 지우지 않고
  날짜만 비운다(지우면 내림까지 함께 풀려 게임이 도로 열린다).

  판정에서는 **스위치가 날짜를 이긴다.** 이미 지난 오픈 시각에 스위치가 지면
  끈 뜻이 없다. 내리는 속도는 예약과 같다 — 주소는 30초, 홈 목록은 60초.

- **2026-09-09 — 쓸 때는 두 칸을 다 적어 보낸다.** 한쪽 칸만 담아 보내면 나머지
  칸이 어떻게 되는지가 PostgREST 의 upsert 규칙에 달린다. 쓰기 직전에 지금 값을
  한 번 읽어 두 칸을 다 적으면 그 규칙을 알 필요가 없다 — 관리자 조작이라 왕복
  하나가 더 드는 것은 문제가 아니고, 잘못 갔을 때의 대가(잡아 둔 예약이 조용히
  사라짐)가 훨씬 크다.

- **2026-09-09 — 읽을 때 칸 이름을 적지 않는다(`select=*`).** 적어 두면 `hidden`
  칸이 아직 없는 DB(006 적용 전)에서 **읽기 전체가 400 으로 실패**하고, 그러면

  스위치만 조용히 안 먹고 예약은 그대로 돈다. 같은 이유로 망가진 날짜도 줄을
  버리지 않고 "예약 없음"으로만 읽는다 — 줄을 버리면 그 줄의 `hidden` 까지
  버려서 급히 내려 둔 게임이 날짜 한 칸 때문에 도로 열린다.
