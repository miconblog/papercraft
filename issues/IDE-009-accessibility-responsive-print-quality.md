## 배경

인쇄가 목적인 사이트라도 고르고 채우는 과정은 전부 화면에서 일어난다. 모바일에서
등번호 22개를 입력하는 경험, 키보드만으로 완주하는 경험이 여기서 갈린다.

출력물 자체의 품질도 함께 본다 — 흑백 프린터나 잉크 절약 모드에서 양 팀이 구분되지
않으면 게임이 성립하지 않는다.

## 할 일

- [x] 모바일·태블릿 레이아웃 정리 — 특히 에디터의 폼과 미리보기 배치.
      코드 점검 결과 이미 반응형(뷰포트 높이 기준 미리보기 폭 계산 ·
      `flex-wrap` · `sm:`/`lg:` 그리드)이라 360px 폭에서 깨지는 고정 크기를
      찾지 못했다 — 추가 수정 없이 통과로 표시한다
- [x] 키보드만으로 전체 흐름 완주 확인, 포커스 표시 정비 — 마커 드래그는
      이미 화살표 키 대안이 있었다(IDE-012). `<button>`이 아닌 원시 버튼
      (파트 탭·프리셋·배율 버튼·색상 팔레트 스와치)에 `focus-visible`
      아웃라인을 추가해 `rounded-full`이 기본 포커스 링을 가리는 문제를
      고쳤다
- [x] 스크린리더 라벨 — 어떤 슬롯을 편집 중인지 전달. 마커·에러·필드 라벨은
      이미 있었다. 파트 탭 묶음에 `role="group"` + `aria-label`, 파트 전환
      시 `role="status"` 알림을 추가해 시각적으로만 드러나던 전환을
      소리로도 전달한다
- [x] 색상 대비 검사 — 사용자가 고른 팀 색이 대비를 깨뜨릴 수 있다.
      `src/lib/customization/contrast.ts`(WCAG 상대 휘도·명암비)로 팀 색
      쌍의 명암비가 1.6 미만이면 에디터에 경고 배너를 띄운다
- [x] 도안·미리보기 로딩 성능 점검. 마커 아트워크 fetch가 파트를 바꿀
      때마다(컴포넌트 리마운트) 컴포넌트 로컬 상태라 매번 다시 일어나던
      것을 모듈 레벨 캐시로 옮겨 게임당 한 번만 받도록 고쳤다
- [x] 흑백 출력과 잉크 절약 모드에서 결과물 가독성 재확인 — 위 명암비 검사가
      바로 이 acceptance criteria를 겨눈다. 마커 위 글자는 기존
      `readableTextColor`가 배경 밝기로 흑/백을 고르므로 별도 수정 없음

## 수용 기준

- [ ] ⚠︎ 360px 폭에서 에디터와 내보내기를 끝까지 수행할 수 있다 —
      코드(반응형 클래스·뷰포트 기준 계산)로는 깨질 자리를 못 찾았지만,
      실제 360px 기기·브라우저로 눈으로 확인한 적은 없다. 이 저장소엔
      headless 브라우저(Playwright 등)가 없어 자동화도 못 붙였다
- [ ] ⚠︎ 마우스 없이 키보드만으로 커스터마이즈부터 내보내기까지 완주된다 —
      코드상 모든 조작(입력·버튼·마커 이동)이 네이티브 엘리먼트거나 명시적
      키 핸들러(화살표 키 nudge)를 갖고 있어 완주 가능해 보이지만, 실제
      키보드만으로 처음부터 끝까지 눌러 확인하지는 못했다
- [ ] ⚠︎ UI 텍스트가 WCAG AA 대비 기준을 충족한다 — 자주 쓰는 조합(본문
      zinc-500/흰 배경, 오류 red-600, 경고 amber-700)만 계산기로 짚어 통과를
      확인했다. 페이지 전체 텍스트 스타일을 자동 스캔하지는 않았다
- [x] 흑백 출력에서도 양 팀이 구분된다 — `findIndistinguishablePair`로
      팀 색 쌍의 WCAG 명암비가 1.6 미만이면 에디터가 경고한다(단위 테스트로
      검증). 경고일 뿐 강제 차단은 아니라 사용자가 무시하고 비슷한 색을
      그대로 쓸 수는 있다

## 결정 기록

**2026-09-05** — 코드 점검 결과 모바일 레이아웃·키보드 조작·스크린리더
라벨의 기반은 IDE-006/007/010/012에서 이미 갖춰져 있었다. 이번에 실제로
고친 것은 셋이다: (1) `rounded-full` 원시 버튼들이 기본 포커스 링을 가려
포커스 표시가 약했던 것 — `focus-visible:outline`을 명시로 추가, (2) 팀
색이 흑백에서 구분되는지 검증하는 장치가 전혀 없었던 것 —
`src/lib/customization/contrast.ts`(WCAG 명암비, 임계값 1.6)로 에디터에
경고 배너를 추가, (3) 마커 아트워크가 파트를 바꿀 때마다 다시 fetch되던
것 — 모듈 레벨 캐시로 게임당 한 번만 받게 고침.

`review`로 올리는 이유: 위 세 가지는 자동 테스트(`contrast.test.ts`,
`BoardPreview.test.tsx`)로 검증됐지만, 나머지 수용 기준(360px 실기기·키보드
전체 완주·WCAG AA 전수 스캔)은 이 저장소에 headless 브라우저 도구가 없어
코드 리뷰로만 확인했다 — 사람이 실제 화면에서 한 번 더 훑어야 `done`으로
닫을 수 있다.
