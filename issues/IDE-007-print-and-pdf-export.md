## 배경

제품의 결승선이다. 커스터마이즈한 도안을 **원하는 크기로 정확히** 받아야 비로소
종이 게임이 된다. `IDE-002`에서 정한 파이프라인 규격을 실제 기능으로 옮긴다.

내보내기는 세 가지를 지원해야 한다:

- **배율 자유 선택** — 기준 100%(운동장 210×297mm)에서 확대도 축소도 된다.
  아이와 크게 놀려면 확대, 휴대하려면 축소
- **파트별 출력** — 핵심 게임판과 오림용 부속을 따로 뽑는다. 부속만 다시 뽑는 것도 된다
- **A4 타일 분할** — 확대하면 A4 한 장을 넘으므로 여러 장으로 나눠 붙일 수 있게 낸다
- **여러 벌 인쇄** — 공을 연필로 튕기는 실물 도구라 반복해 쓰면 접히거나 해질 수
  있고, 작은 부속(공)은 잃어버리기 쉽다. 여벌을 미리 뽑아 두거나 형제·친구와
  나눠 쓸 수 있어야 한다

## 할 일

- [x] 파트 선택 UI — 보드 / 부속 / 전체, 각각이 무엇인지 알 수 있게
  - `/games/<id>/print`에 파트마다 한 줄(체크박스 · 종류 · 100%에서의 크기)을 두고,
    위에 `전체 · 게임판만 · 부속만` 빠른 선택을 붙였다. 파트마다 하한이 달라
    (운동장 50% · 게임 방법 85%) 배율·벌 수도 줄 단위로 준다
- [x] 배율 선택 UI — 프리셋(50% · 100% · 200%)과 임의 배율, "A4 몇 장에 걸침"을 실시간으로 표시
  - 프리셋 + `%` 입력 + "A4 한 장 맞춤"(줄일 때만 노출)이고, 장수는 입력 즉시
    `A4 8장 · 4×2 · 594×420mm`로 바뀐다. 100%가 아닌 배율에는 "원본 크기가 아니다"를 적는다
- [x] 채택한 방식으로 PDF 생성 또는 인쇄 시트 렌더링
  - `pdf-lib` 벡터 PDF를 **서버 라우트**(`POST /api/games/<id>/export`)에서 만든다.
    글자는 Noto Sans KR 윤곽선. 200% 보드 8장이 260KB다
- [x] A4 타일 분할 — 겹침 · 재단선 · 조립 표식 · 장 번호 삽입
  - `docs/print-spec.md` §5 그대로. 배율별 장수 표를 테스트로 고정했다.
    표식이 인쇄 불가 여백으로 밀려나던 문제는 하단 표식 띠로 고쳤다(§11.1)
- [x] 조립 안내 시트 생성 — 몇 장을 어떤 순서로 붙이는지
  - 첫 장에 붙는다. 인쇄 설정 · 파트별 장 배치도(번호가 든 격자) · 붙이는 순서 ·
    오림선/접는선/풀칠면 뜻풀이. 넘치면 다음 장으로 이어진다
- [x] 부속 파트에 오림선·접는선 렌더링
  - 도안이 적어 둔 굵기를 버리고 `MARK_STYLES` 규약 값을 다시 입힌다.
    배율을 먹지 않아 200%로 뽑아도 오림선은 0.25mm다
- [x] 인쇄 미리보기 — 실제 출력물과 같은 비율, 타일 경계선 표시
  - 에디터의 `BoardPreview`를 그대로 쓰고 그 위에 타일 경계(빨간 파선)와 장 번호를
    얹었다. 도안을 두 번 그리지 않으므로 미리보기와 인쇄물이 어긋날 자리가 없다
- [x] "배율 100%로 인쇄" 안내를 사용자에게 노출 (프린터의 자동 맞춤이 치수를 망친다)
  - 세 곳에 같은 문구를 둔다 — 내보내기 화면 · 조립 안내 시트 · **모든 장의 하단 띠**.
    인쇄 대화상자 앞에서 잊히는 안내라 종이에도 박았다
- [x] `IDE-004`가 정한 최소 배율 아래로는 경고하거나 막기
  - `part.minScale` 아래는 **막는다**(UI에서 버튼이 꺼지고 서버도 400을 낸다).
    권장 상한 위는 알리기만 한다 — 크게 뽑는 것 자체는 이 제품이 하려던 일이다
- [x] 보드 여러 벌 인쇄 — 몇 벌 뽑을지 지정하면 그만큼 반복된 PDF가 나오게
  - 파트마다 1–20벌. 한 벌씩 이어 붙이고 장 번호에 `3벌 중 2벌째`를 적어 섞이지 않게 했다
- [x] 조립물 파트에 접는선·풀칠면 렌더링 (골대·주사위 전개도)
  - 산접기 일점쇄선·풀칠면 45° 해칭까지 낸다. 처음에는 통째로 빠져 있었다(§11.5)
- [x] 파일명 규칙 정의 — 게임명 · 파트 · 배율이 구분되게
  - `soccer-field-200pct.pdf` · `soccer-accessories-100pct.pdf` ·
    `soccer-field-100pct-x3.pdf` · 배율이 섞이면 `mixed`. 게임·파트 id가 이미
    ASCII 슬러그라 한글을 섞지 않았다 — 한글 파일명은 지나는 곳마다 깨질 자리가 생긴다

## 수용 기준

디지털 실측은 `npm run print:verify`로 언제든 다시 돌린다(`docs/print-spec.md` §11.6).
**종이 실측은 사람 몫이고 아직 남아 있다** — `IDE-002`가 남긴 체크리스트
([spikes/print-pipeline/README.md](../spikes/print-pipeline/README.md))와 같은 일이다.

- [ ] ⚠︎ 배율 100%로 뽑은 보드의 운동장 실측이 210×297mm이고 오차가 ±1mm 이내다
  - 디지털 실측 **오차 0.000mm** — 초록 터치라인이 281.500×180.500mm로 도안이
    말하는 값과 같고, 두 장을 붙인 보드 바깥 테두리는 계획상 297×210mm다
    (타일 합이 파트 크기와 같음을 테스트로 고정). PDF 페이지 상자도
    210.000×297.000mm다. **남은 것: 종이에 뽑아 자로 재기**
- [ ] ⚠︎ 확대·축소한 출력이 지정한 배율대로 나온다
  - 50% 0.083mm(측정 해상도 한 픽셀) · 100% 0.000mm · 200% 0.000mm. **종이 실측 대기**
- [ ] ⚠︎ 확대 출력한 타일들을 붙였을 때 필드 라인이 이어진다
  - 200% 8장을 **계획대로 붙여** 타일 없이 그린 기준 시트와 픽셀 단위로 맞춰
    **차이 0픽셀**(304.8dpi = 12px/mm). 50%·100%도 같다.
    **남은 것: 실제로 뽑아 붙여 보기** — 종이 신축과 재단 오차는 실물에서만 나온다
- [x] 보드와 부속을 따로 뽑을 수 있고, 부속만 다시 뽑는 것도 된다
  - 파트별 선택이라 부속 하나만도 된다. 화면·라우트 양쪽에 테스트가 있다
- [ ] ⚠︎ 부속을 오림선대로 잘라 바로 쓸 수 있고, 조립물은 접어서 세워진다
  - 오림선·산접기·풀칠면이 규약대로 나오는 것까지 확인했다(`goals.pdf` 렌더 확인).
    **남은 것: 오려 접어 세워 보기** — `IDE-004`의 종이 확인과 같은 일이다
- [x] 보드를 3벌로 지정해 뽑으면 같은 보드가 3장 나온다
  - 100% 보드 2장 × 3벌 = 6장. 장마다 `3벌 중 2벌째`가 찍힌다
- [x] 커스터마이즈한 등번호와 팀명이 출력물에 그대로 나온다
  - 팀 이름·등번호·팀 색·마커 자리·마커 스타일 전부. 등번호 글자색은 팀 색 밝기를
    보고 정하는데, 미리보기와 **같은 함수**를 쓴다(`src/lib/customization/render.ts`)
- [ ] ⚠︎ 지원 브라우저 전부에서 내보내기가 성공한다
  - PDF를 서버가 만들어 브라우저는 내려받기만 한다 — 구조적으로 브라우저 차이가
    결과에 닿지 않는다. Chrome에서 확인했다.
    **남은 것: Safari·Firefox 실기 확인**(이 환경에 없다) — `IDE-002`와 같은 항목이다

- 2026-09-05 · **구현 완료, `doing` → `review`.** `docs/print-spec.md`를 그대로
  옮기고, 규격이 정하지 않았거나 실제로 돌려 보니 틀렸던 자리를 채웠다. 상세한
  이유는 같은 문서 §11에 남겼다. 요지만 옮기면:
  - **표식 띠 7mm를 새로 뒀다.** 스파이크는 장 번호를 용지 아래 1.6mm에 두었는데
    거기는 인쇄 불가 여백이라 종이에서 사라진다. 다만 띠가 **장수를 늘리지는
    않게** 했다 — 도안을 놓고 남은 여유에서만 가져간다. 처음엔 띠를 장수 계산에
    넣었더니 무여백에 가까운 프린터에서도 100% 보드가 두 장이 됐다
  - **이웃 장 번호를 겹침 띠에서 하단 띠로 옮겼다.** 겹침 띠는 붙인 뒤에도 종이에
    남아, 완성된 게임판에 `▶ 3번 오른쪽`이 찍힌 채로 남는다
  - **재단선은 여러 장일 때만 그린다.** 한 장짜리 부속에 그렸더니 도안이 이미 가진
    오림선 바깥에 네모가 하나 더 생겨 어디를 자를지 헷갈렸다
- 2026-09-05 · **도안 SVG 파서는 모르는 것을 만나면 예외를 던진다.** 속성 이름
  정규식이 숫자를 빼먹어(`x1`·`y2`) 좌표가 전부 0이 되는 버그가 있었고, 그 결과
  **골대 전개도의 접는선과 풀칠면이 통째로 사라졌다.** 화면 미리보기는 멀쩡했고
  PDF에서만 빠졌다 — 렌더링해 눈으로 보지 않았으면 못 잡았을 종류다. 같은 일이
  다시 일어나지 않게 ① 모르는 요소·색·변환은 예외 ② 배포된 도안 전부를 읽고
  좌표가 0이 아닌지 보는 테스트를 뒀다.
