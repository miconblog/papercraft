# IDE-016 · 지도 위 도시 토글과 경로 편집

| 항목        | 값        |
| ----------- | --------- |
| 상태        | `blocked` |
| 영역        | frontend  |
| 우선순위    | P1        |
| 마일스톤    | M2        |
| 추정        | 4d        |
| 추천 모델   | Opus 5    |

| 후행        | `IDE-011` |

## 배경

`IDE-015`(세계일주)에서 사용자가 요구한 두 가지다(2026-09-08):

- 지도 위 주요 도시를 **토글로 켜고 꺼서** 판의 도시 수를 늘리고 줄인다.
- 이동 경로는 추천선을 기본으로 그리되, **점과 점 사이 간선을 지우거나 두 점을
  드래그해 이을 수 있다.**

`IDE-015`에서 뗀 이유는 성격이 다르기 때문이다. 저쪽은 도안 데이터와 SVG고,
이쪽은 **에디터 조작과 저장 규격**이다. 도시·경로 데이터가 없으면 편집할 대상이
없으므로 `blocked`으로 둔다.

## 이것이 스키마의 첫 번째 확장이다

`IDE-011`은 야구를 넣고도 **스키마를 한 줄도 고치지 않았다.** 이 이슈는 다르다.
현행 `GameCustomization`(`src/lib/schema/customization.ts`)이 드는 것은 둘뿐이다:

- `values` — 슬롯 id → 값 (`text` · `number` · `color` · `choice`)
- `positions` — 마커 슬롯의 좌표

**켜고 끈 도시 집합도, 사용자가 고친 간선 목록도 여기 들어갈 자리가 없다.**
`choice` 슬롯으로 프리셋(50·60·70·80)까지는 표현되지만 개별 토글은 안 된다 —
선택지를 2^108개 만들 수는 없다. 좌표를 옮기는 것이 아니라 **원소를 넣고 빼는**
편집이라 `positions`도 맞지 않는다.

그러므로 새 슬롯 종류를 하나 만든다. 이름은 구현하며 정하되 성질은 이렇다:

- 값이 **id 집합**이다(켜진 도시들, 이어진 간선들).
- 도안이 **후보 전체와 기본 집합**을 선언하고, 사용자는 그 안에서만 고른다.
- 검증이 **집합의 성질**을 본다 — 세계일주라면 "서울에서 서울로 이어지는 한
  바퀴인가". 이건 게임마다 다르므로 스키마가 아니라 도안이 규칙을 준다.

여기에 하나 더 — **파트의 크기가 선택을 따라 바뀐다.** `IDE-015`가 도시 수에
따라 판을 A4 · A3 · A2로 키우기로 했다(50 / 60·70 / 80 이상). 지금 파트는
`widthMm`·`heightMm`가 상수라, 도시를 켜고 끄면 판 크기도 같이 정해지는 것을
표현할 자리가 없다. `dimensions.ts`의 `paperFor(도시 수)`가 그 규칙이고,
인쇄 쪽은 파트 크기만 받으면 A4 여러 장으로 나누는 일을 이미 한다.

마지막 항목이 이 이슈에서 가장 되돌리기 비싼 결정이다. 스키마가 그래프를 알게
하면 세계일주 전용 코드가 근간에 박히고, 도안이 검사 함수를 주면 저장 검증이
게임 코드를 실행하게 된다. **후자를 기본으로 잡되** 판단은 구현 때 남긴다.

## 조작

- **도시 토글** — 지도 위 도시 점을 누르면 켜지고 꺼진다. 꺼진 도시도 옅게 보여야
  다시 켤 수 있다. 프리셋(50·60·70·80)은 출발점이고, 누른 뒤로는 자유롭게 고친다.
  프리셋 버튼을 다시 누르면 그 집합으로 되돌아간다.
- **고정 도시** — 서울·제주는 끌 수 없다. 누르면 왜 안 되는지 알려 준다.
- **간선 지우기** — 경로 선을 누르면 지워진다.
- **간선 잇기** — 도시에서 도시로 드래그하면 이어진다. 이미 있는 간선이면 지운다.
- **키보드로도 된다.** `IDE-009`가 마커 이동에서 확인한 것과 같은 요구다 —
  드래그만 되는 조작은 키보드 사용자에게 없는 기능이다.
- **끊긴 경로를 그 자리에서 알려 준다.** 인쇄 버튼을 눌러야 알게 되면 어디가
  끊겼는지 되짚어야 한다. 이어지지 않은 도시를 지도 위에 표시한다.

도시를 끄면 그 도시에 붙은 간선도 함께 사라지고, 앞뒤 도시가 자동으로 이어진다
— 끄는 순간 판이 깨지면 토글이 쓸 수 없는 기능이 된다.

## 결정 기록

### 2026-09-08 — 1단계: 파트 변형으로 도시 수부터 고르게 했다

사용자가 "도시가 50개로 고정되어 바꿀 옵션이 없어 테스트하기 어렵다"고 해서
(2026-09-08) 토글보다 **수 선택**을 먼저 냈다. 방법은 스키마의 첫 확장인
**파트 변형**이다:

- `part.variants = { selectorSlotId, options[{ value, title?, widthMm, heightMm, artwork }] }`.
  파트 하나에 아트워크 하나라는 규약은 그대로다 — 변형은 "지금 값에서 어느
  아트워크가 그 하나인가"를 정한다. 변형은 판의 **크기까지** 바꾼다. 도시 수를
  따라 종이가 A4 → A3 → A2로 커지는 것이 `IDE-015`의 결정이라 크기가 값에 매여야
  했다.
- 파트를 읽는 코드는 전부 `resolvePart(game, part, customization)`를 거친다 —
  인쇄 렌더러(`compose.ts`)·인쇄 옵션 검증(`options.ts`, `customization` 인자
  추가)·에디터 미리보기와 파트 버튼(`EditorClient`)·인쇄 화면(`ExportClient`).
  소개 페이지는 기본값 치수 옆에 "고르는 값에 따라 …"를 적는다.
- 검증 셋: 선택지 = 변형 값(마커 스타일 세트와 같은 규칙) · **기본값 변형 = 파트
  자체**(선택 슬롯을 모르는 카탈로그 썸네일이 보는 것이 곧 기본값이어야 한다) ·
  변형은 인쇄 방향을 못 바꾼다.
- 모르는 값(옛 저장값)은 파트 자체, 곧 기본값으로 푼다. 에디터가 깨지지 않는다.

### 2026-09-08 — 미리보기 확대·축소·이동

같은 날 사용자가 "구글맵과 같은 지도 UX"를 요구했다 — A4에 도시 50개, A2에
100개라 화면 미리보기에서는 칸이 손톱만 하다. `useMapViewport` 훅을 두고
`BoardPreview`가 쓴다(게임을 모른다 — 축구·야구 미리보기도 같이 된다):

- 휠 — 커서 자리를 중심으로 확대·축소(페이지 스크롤을 막는다).
- 빈 곳 드래그 — 이동. 마커 위에서 시작한 드래그는 마커를 옮기는 것이라
  `data-marker` 표식을 보고 비켜 준다.
- 두 손가락 — 핀치 확대·축소와 이동. 더블클릭 — 그 자리 두 배.
- `+` `-` `0` 키와 우하단 버튼(확대·축소·원래 크기).
- 배율 1~8. 배율 1 아래로는 안 줄이고, 판이 상자를 늘 덮도록 이동을 묶는다.

배경 SVG와 마커 오버레이를 한 무대(`div`)에 놓고 무대를 CSS transform으로
움직인다 — 둘이 따로 움직이면 마커가 판에서 미끄러진다. 마커 드래그는 화면
좌표를 surface의 실제 사각형으로 되돌리므로 확대해도 그대로 맞는다. 인쇄
미리보기(보기 전용)에서는 끈다 — 타일 경계 오버레이가 무대 밖에 있다.

### 2026-09-08 — 2단계: 목록 슬롯과 동적 파트

사용자가 "전체 도시 목록을 지도 아래 보여주고, 체크한 도시만, 조정한 차례대로"
를 요구했다(같은 날, 규칙 변경·제주 삭제·지도만 출력과 함께). 설계는 아래
예고대로 갔다:

- **`list` 슬롯** — 값이 항목 id의 차례 있는 배열. `fixed`(서울)·`min`(5)·
  `presets`(50~100). 배치는 `control`뿐이다. `SlotValue`에 `string[]`이 더해졌다.
- **동적 파트(`dynamic`)** — 크기는 데이터(`sizeSteps`: 켠 수 → A4·A3·A2,
  `frameSlotId`가 `map`이면 지도 높이)로 스키마가 계산하고, 그림은 게임 id별
  렌더러(`lib/games/dynamic-artwork.ts`)가 **서버에서만** 그린다. 미리보기는
  `POST /api/games/[id]/artwork`(값이 도시 id 100개라 GET에 안 담긴다),
  내보내기는 같은 함수. 렌더러가 그린 크기와 스키마 크기가 다르면 둘 다 막는다.
- **간선 편집은 차례 편집이다.** "간선을 지우고 두 점을 이어라"는 요구는 결국
  경로의 차례를 바꾸는 것이다 — 목록에서 끌어 옮기면(또는 ▲▼) 그 도시 앞뒤의
  간선이 함께 바뀐다. 끊긴 경로는 생길 수 없고, 별도의 "이음" 검증이 필요 없다.
- **1단계의 변형은 걷어냈다.** 도시 수 프리셋은 목록 슬롯의 `presets`가 됐고,
  정적 판은 썸네일용 기본 판 하나만 남았다. 스키마의 `variants`는 문서와 함께
  남겨 두었다 — 미리 그린 SVG 몇 벌 사이를 오갈 때 쓰라고.
- **1단계 예고와 달라진 것** — "땅은 정적으로 두고 칸·화살표만 그때 그린다"는
  안 했다. 서버가 판 전체(232KB)를 그려도 100ms 안이라 나눌 이유가 없었다.

### 2026-09-08 — 검색해서 더하기

사용자가 "원하는 도시를 검색해서 추가"하길 원했다. 풀(112개)에 없는 도시라
좌표가 필요하다:

- **외부 지오코더 대신 Natural Earth `ne_10m_populated_places`**(7,342곳, 한국어
  이름 포함, 퍼블릭 도메인). 외부 서비스에 기대지 않고, 같은 질의에 늘 같은
  답이 나오며, 테스트에서도 돌아간다. 19MB 원본에서 필요한 것만 뽑아 452KB로
  두고(`npm run fetch:cities`) 서버에서만 읽는다.
- **값에 항목을 싣는다.** 목록 슬롯의 `custom: true`면 값에 `{ id, label, data }`가
  올 수 있다 — 저장값만으로 다시 그릴 수 있어야 하므로 이름과 경위도를 값에
  둔다. `data`의 뜻은 게임 렌더러가 안다(스키마는 모른다).
- 풀의 도시와 같은 곳(이름이 같거나 0.5° 안)은 풀의 옵션으로 접는다 — 파리가
  둘 나오면 안 된다.
- 더한 도시는 목록 끝(서울 앞)에 붙는다. 어디에 끼울지는 사용자가 차례를 바꿔
  정한다.

### 2026-09-08 — 새로고침하면 경로가 초기화되던 것

사용자가 만든 경로가 새로고침마다 사라졌다. 원인 둘:

- **하이드레이션 전 저장.** 서버 렌더 직후 첫 화면은 기본값인데, 그때 "값이
  바뀌면 저장" 효과가 기본값을 로컬 저장소에 덮어쓴 뒤에야 복원이 시작됐다.
  테스트(클라이언트 렌더뿐)는 하이드레이션 단계가 없어 잡지 못했다. 이제
  복원이 끝난 폼(`persist`)만 저장하고, `useHydrated`를 거짓으로 고정한
  테스트가 이 순서를 지킨다.
- **낡은 저장값 통째 폐기.** 저장값이 지금 도안과 조금이라도 안 맞으면(오늘만
  슬롯이 세 번 바뀌었다) 전부 버리고 기본값으로 시작했다. 이제 슬롯마다 맞는
  값만 살리고 빠진 것은 기본값으로 채운다(`restoreCustomization`). 축구·야구도
  같은 혜택을 본다 — 도안을 손봐도 사용자의 대형·색이 남는다.

### 2026-09-08 — 1단계에서 남긴 설계 (참고)

**변형은 미리 만든 SVG를 고르는 것이라 2^113개 집합을 담을 수 없다.** 그때 적어
둔 설계:

- 새 슬롯 종류(id 집합 + 차례)와 그 검증(서울→서울 한 바퀴).
- **아트워크를 값에서 그때 그린다.** 도안 정의는 서버→클라이언트로 그대로
  넘어가는 데이터라 함수를 실을 수 없으므로, 게임 id별 렌더러 등록소와
  `/api/games/<id>/artwork/<part>?…` 같은 동적 아트워크 경로가 필요하다.
  미리보기는 그 경로를 fetch하고, 내보내기는 서버에서 같은 렌더러를 부른다.
  `layoutCities(임의의 도시 목록, 지도 상자)`·`resolveSpecials`는 그때 쓰라고
  이미 프리셋과 떼어 두었다(`IDE-015`).
- 땅(`land.json` 243KB)은 정적으로 두고 칸·화살표만 그때 그리는 것이 무게를
  줄인다 — 파트 아트워크 위에 게임이 주는 **동적 레이어**를 얹는 모양이 된다.
