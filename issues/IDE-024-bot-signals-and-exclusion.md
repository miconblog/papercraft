## 배경

사용자가 통계를 비운 뒤 들어온 **첫 방문 한 줄**에서 나왔다(2026-09-09).
오스트리아(`AT`)에서 `direct` 로 홈에 들어와 페이지 하나만 보고 끝났다.
한국어 사이트에 홍보도 없는데 들어온 것이라 **사람인지 자동화인지 궁금한데,
지금 저장하는 값으로는 가릴 수가 없다.**

## 그 한 줄로 말할 수 있었던 것

- **검색 유입이 아니다.** `referrer_host` 가 비었고 `channel` 이 `direct` 다.
  검색이면 `channel.ts` 의 `SEARCH_HOSTS` 에 걸려 `organic` 이 됐다.
- **단순 크롤러도 아니다.** 페이지뷰는 `PageViews.tsx` 의 `fetch` 로만 들어온다 —
  이 방문자는 React 를 하이드레이션하고 JS 를 실행해 수집 API 를 직접 불렀다.
  `curl` · `python-requests` · 일반 검색 크롤러는 이 줄을 만들 수 없다.
- **남는 후보 둘을 못 가른다.** 진짜 사람인지, UA 를 위장한 헤드리스
  브라우저인지. UA 원본도 IP 도 저장하지 않기 때문이다(의도한 것이다).

`direct` 를 "주소창에 직접 입력"으로 읽으면 안 된다는 것도 함께 확인했다 —
메신저·앱 안 브라우저에서 온 클릭과 `referrer-policy` 로 잘린 링크가 전부
`direct` 로 떨어진다.

## 그래서 무엇을 더 보나

IP 도 UA 원본도 저장하지 않고 쓸 수 있는 헤더 신호가 있다.

| 신호                 | 점수 | 왜 갈리나                                                        |
| -------------------- | ---- | ---------------------------------------------------------------- |
| `no-accept-language` | 2    | 진짜 브라우저는 늘 보낸다. 이번 건도 이것 하나로 거의 판가름난다 |
| `no-client-hints`    | 1    | UA 는 Chrome 인데 Chromium 이 늘 붙이는 `sec-ch-ua` 가 없다      |
| `bad-fetch-metadata` | 3    | 우리 `fetch` 라면 `same-origin`/`cors` 여야 한다                 |

**가중치는 틀렸을 때의 대가로 정했다.** 진짜 사람을 봇으로 만들 위험이 큰
신호일수록 낮게 준다 — 숫자가 조금 부푸는 것보다 사람이 통계에서 사라지는 쪽이
나쁘다. 문턱은 2다.

## 처분이 기존 필터와 달라야 하는 이유

`request.ts` 의 UA 정규식은 **줄을 아예 안 만든다.** UA 에 `bot` 이라 적어 둔
크롤러에는 맞는 처분이다. 하지만 위 신호는 확률적이라 같은 방식으로 다루면
**진짜 사람을 조용히 지워 놓고 알아채지 못한다.**

그래서 **줄은 남기고 점수를 매겨, 집계(`rollup_daily`)에서만 뺀다.** 대시보드
숫자는 깨끗해지고, 원본을 열어 무엇이 걸렸는지 감사할 수 있다.

문턱을 앱에 두고 `is_bot` 을 저장하지 않은 것도 같은 이유다. 그러면 이미 쌓인
줄의 판정이 옛 기준에 굳어 다시 계산해도 안 바뀐다. **점수를 남기고 문턱을
`rollup_daily` 의 인자로 쥐면**, 기준을 고쳐 다시 돌리는 것만으로 지난 날짜까지
새 기준으로 따라온다.

## 결정 기록

- **2026-09-09 — 봇은 지우지 않고 표시만 한다.** 확률적 판정으로 줄을 지우면
  오탐이 영영 안 보인다. UA 정규식(확정적)과 점수(확률적)의 처분을 다르게 둔다.
- **2026-09-09 — 문턱은 SQL 이 쥔다.** 앱이 `is_bot` 을 정해 저장하면 판정이
  옛 기준에 굳는다. 점수만 남기면 기준을 나중에 바꿔도 지난 날짜가 따라온다.
- **2026-09-09 — `Accept-Language` 는 첫 태그의 언어 코드만**(사용자 결정).
  전체 문자열은 언어 목록과 가중치까지 실려 오는 지문이라, UA 원본을 안 남기기로
  한 것과 같은 이유로 남기지 않는다.
- **2026-09-09 — `no-client-hints` 는 1점이다.** `sec-ch-ua` 가 브라우저의
  `fetch` 요청에도 실리는지 실물로 확인하지 않았다. 가정이 틀렸다면 이 신호
  하나로 Chrome 사용자 전부가 봇이 되므로, 혼자서는 문턱을 못 넘게 뒀다.

## 안 한 것

- **대시보드에 "봇으로 제외된 수"를 보여 주는 것.** `service_role` 은 집계
  표만 읽을 수 있고 원본 `events` 는 못 읽는다(`IDE-013` 이 일부러 그렇게 잠갔다).
  보여 주려면 집계 표에 칸을 더하거나 잠금을 풀어야 해서, 필요해지면 그때 한다.
- **이미 쌓인 줄의 소급 판정.** 판정에 쓸 헤더를 그때는 저장하지 않았다.
  그 오스트리아 방문 한 줄은 `bot_score` 가 0(기본값)으로 남아 사람으로 센다.
