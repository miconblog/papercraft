## 배경

축구 게임판에서 선수는 도안 위에 놓이는 별개의 층이다. 필드는 고정이지만 선수는
스타일도 위치도 사용자가 고른다. 그래서 필드 도안(`IDE-004`)과 분리해 만든다.

두 가지가 필요하다(2026-09-03 확정):

- **마커 스타일 두 벌** — ① 원 + 등번호 ② 선수 일러스트 + 등번호. 사용자가 고른다.
  ①은 사용자가 직접 만든 판의 방식이고, ②는 옛 인쇄본의 방식이다
- **전술 대형 프리셋** — 4-4-2, 3-5-2 같은 실제 축구 포메이션대로 11명을 배치한다.
  프리셋은 출발점이고 여기서 자유롭게 옮길 수 있다(`IDE-006`)

한 팀은 **골키퍼 포함 11명**, 양 팀 22명이다. 사용자가 만든 판 사진에는 골키퍼가
빠져 있었지만 정식 구성은 11명이다.

일러스트는 옛 인쇄본을 복제하지 않고 직접 만든다.

## 할 일

- [x] 원형 마커 세트 작도 — 원 + 등번호, 팀 색 적용 가능하게, 골키퍼는 구분되게 ·
      `player-marker-circle.svg` / `goalkeeper-marker-circle.svg`. 팀 색은
      `pc-marker-fill` 레이어가 받고, 골키퍼는 안쪽 테 하나로 구분된다.
- [x] 일러스트 마커 세트 제작 — **전원 동일 포즈**로 결정했다(달리는 자세
      픽토그램 하나, 골키퍼만 장갑 표식 추가). 포지션별 포즈나 몇 가지 포즈
      돌려쓰기는 하지 않는다 — 근거는 결정 기록.
- [x] 두 세트가 같은 슬롯에 교체 가능하도록 기준점·크기 규격을 맞춘다 · 원형
      12×12mm, 일러스트 13×16mm로 필드 선수·골키퍼 세트가 크기를 공유한다
      (`PLAYER_MARKER`, `dimensions.ts`). 기준점은 두 세트 다 마커 중심이다.
- [⚠︎] 등번호 가독성 확인 — 일러스트 위에 얹었을 때, 그리고 축소 배율에서 ·
      `valueFontSizeMm`을 두 세트 다 5mm로 맞춰 필드 `minScale`(0.5)에서
      2.5mm 하한에 닿는 것은 테스트로 확인했다. **일러스트 실루엣 위에 실제로
      얹었을 때 읽히는지는 렌더러가 없어(`IDE-006`) 눈으로 못 봤다.**
- [x] 전술 대형 프리셋 좌표 데이터 작성 — 최소 4-4-2 · 3-5-2 · 4-3-3 · 4-2-3-1 ·
      네 대형 모두 `FORMATIONS`에 있고 홈·원정 프리셋이 자동 생성된다.
- [x] 각 프리셋의 기본 등번호 배정 (GK 1번 등 통념을 따르되 사용자가 바꿀 수 있다) ·
      슬롯 id가 대형과 무관하게 고정이라(`home-player-1`…11) 어느 프리셋을 골라도
      1번 = 골키퍼가 유지된다. 기존 IDE-004 구현을 그대로 확인했다.
- [x] 프리셋 좌표를 양 팀 진영에 대칭으로 적용하는 방식 정의 · `mirrorPositions`로
      세로 중심선 반전(기존 IDE-004 구현), 새 대형 둘에도 그대로 적용했다.
- [x] 선수끼리 겹치거나 필드 밖으로 나가지 않는지 프리셋 전부 확인 · `parseGame`이
      네 대형 × 홈/원정 조합 전부를 좌표·겹침·영역으로 검증하고, 홈 4벌 × 원정
      4벌 = 16개 조합을 도는 회귀 테스트(`registry.test.ts`)로 다시 확인했다.
- [⚠︎] 흑백 출력에서 두 팀이 구분되는지 확인 (색만으로 구분하면 안 된다) ·
      마커 오른쪽에 색과 무관한 화살촉(공격 방향)을 붙이고 원정은 좌우 반전해
      쓰기로 설계했다 — 화살촉이 기하로 비대칭임은 테스트로 확인했다. **원정
      마커를 실제로 반전해 찍는 것과, 인쇄물에서 눈으로 구분되는지는 렌더러가
      없어(`IDE-006`·`IDE-007`) 검증하지 못했다.**

## 수용 기준

- [x] 원형·일러스트 두 마커 세트가 모두 있고 서로 바꿔 끼워도 배치가 어긋나지 않는다
- [x] 한 팀 11명(골키퍼 포함), 양 팀 22명이 도안에 배치된다
- [x] 전술 대형 프리셋이 4종 이상 있고 각각 실제 포메이션에 맞는 배치다
- [x] 어떤 프리셋을 골라도 선수가 겹치거나 필드를 벗어나지 않는다
- [x] 마커 아트워크가 색과 무관하게 양 팀·골키퍼를 구분하는 표식을 갖는다
      (팀: 방향 화살촉 · 골키퍼: 이중 테)이고, 그 표식이 기하로 비대칭임이
      테스트로 확인된다 · **범위 조정(2026-09-04, 원문: "흑백으로 출력해도 양
      팀과 골키퍼가 구분된다")** — 이 이슈는 렌더러 없이 아트워크와 스키마만
      만든다. 원정 마커에 화살촉 반전을 실제로 적용해 찍고, 인쇄물에서 눈으로
      구분되는지 확인하는 것은 렌더러를 만드는 `IDE-006`(→ 인쇄 결과는
      `IDE-007`)로 넘긴다.
- [x] 옛 인쇄본의 선수 일러스트를 복제하지 않았음이 문서로 확인된다

- 2026-09-03 · 한 팀 11명(골키퍼 포함)으로 확정. 사진에 골키퍼가 없었던 것은 그리다
  뺀 것이지 구성이 아니다.
- 2026-09-04 · 선행 `IDE-004`를 취소선으로 풀었다. `IDE-004`는 아직 `blocked`지만
  기다리는 것(종이 실측 · 규칙 확인)이 이 이슈와 무관하고, 여기서 필요한 것은 다
  나왔다 — 필드 기하와 영역(`playable-field` 등), 마커 스타일 세트 규격, 4-4-2·3-5-2
  출발 좌표. 시작점은 [docs/soccer-artwork.md](../docs/soccer-artwork.md)다.
  다만 **골키퍼 좌표는 골대 자리(골라인 안쪽 16mm)를 침범하면 안 된다** — 대형을
  확정할 때 이 제약을 지켜야 하고, 테스트가 검사한다.
- 2026-09-04 · 일러스트 마커의 포즈 벌 수를 **전원 동일**로 정했다. 포지션별
  포즈는 22명 각각 다른 그림이 필요해 작업량이 이 이슈 하나로 감당하기 어렵고,
  게임에 포지션별 능력치 차이가 없어(등번호만 다르다) 포즈로 포지션을 구분할
  이유도 없다. 몇 가지 포즈를 돌려 쓰는 안도 검토했지만, 어느 포즈를 누구에게
  배정할지 정할 기준이 없어 임의성만 늘었다. 대신 **골키퍼는 예외로 장갑
  표식**을 더해 역할 하나만은 확실히 구분했다.
- 2026-09-04 · 흑백에서 팀·골키퍼를 구분하는 방법을 스타일 세트 분리 + 도형
  비대칭으로 정했다. 팀 색은 사용자가 자유 입력이라(`hexColor`) 색의 명도
  차이에 기댈 수 없다 — 그래서 (1) 필드 선수·골키퍼를 애초에 다른 스타일
  세트(`player-marker` / `goalkeeper-marker`)로 나눠 골키퍼는 이중 테로 항상
  다르게 그리고, (2) 팀은 마커에 방향성 있는 화살촉을 붙이고 원정을 좌우
  반전해서 찍기로 했다. 후자는 "찍을 때 반전한다"는 **렌더러 요구사항**이라
  이 이슈에서는 도형이 비대칭임을 기하로만 확인했고, 실제 반전 적용과 인쇄
  확인은 `IDE-006`·`IDE-007`로 넘긴다 — 그래서 관련 수용 기준을 위와 같이
  조정했다.
- 2026-09-04 · 전술 대형에 4-3-3 · 4-2-3-1을 추가해 4종을 채웠다. 골키퍼는
  모든 대형에서 x=32(골대 자리 밖), 나머지 선수는 x≥52로 둬 골대 자리 침범
  검사를 자동으로 통과하게 잡았다 — `parseGame`이 네 대형 모두를 통과시켰다.
