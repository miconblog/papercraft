## 배경

`IDE-019`에서 뗀 것이다. 저쪽이 **사진에서 점·번호를 뽑는 일**이라면 이쪽은
**사용자가 사진을 넣고 결과를 고치고 다시 여는 일**이다. 뽑는 쪽이 없으면 넣을
곳이 없으므로 `blocked`으로 둔다.

`IDE-015`와 `IDE-016`을 뗀 이유와 같다 — 도안 데이터와 에디터 조작은 실패하는
방식이 다르다.

## 에디터가 지금까지 다뤄 온 것과 다르다

지금 에디터(`src/components/editor/`)가 아는 입력은 세 가지다 — 글자·숫자·색을
넣는 칸(`SlotField`), 마커 드래그(`useMarkerDrag`), 대형 고르기
(`FormationPicker`). **파일을 받는 자리가 없다.**

그리고 받은 것을 **둘 곳도 없다.** `GameCustomization`이 드는 것은
`values`(슬롯 값)와 `positions`(마커 좌표)뿐이다(`src/lib/schema/customization.ts`).
사진도, 거기서 뽑은 점 좌표 배열도 들어갈 자리가 없다.

`IDE-016`도 같은 벽을 만났고 거기서는 **id 집합**을 담을 슬롯 종류를 새로 만들기로
했다. 이쪽이 필요한 것은 그것과 다르다 — **사용자 입력에서 생성된 기하 데이터**이고
도안이 후보를 미리 선언해 둘 수 없다. 두 확장이 한 종류로 합쳐지는지는
`IDE-016`이 먼저 착수하면 그 결과를 보고 정한다. **먼저 하는 쪽에 맞춘다** —
선행으로 걸지 않는 이유는 어느 쪽이 먼저일지 아직 정해지지 않았기 때문이다.

## 사진을 어디까지 간직하나

이게 이 이슈에서 제일 먼저 정할 것이다. 세 갈래고, 사용자가 무엇을 기대하는지에
달렸다.

| 갈래                   | 다시 열면                        | 대가                                                         |
| ---------------------- | -------------------------------- | ------------------------------------------------------------ |
| 점 좌표만 저장         | 점 개수를 못 바꾼다(다시 올려야) | 가볍다. 사진이 어디에도 안 남는다                            |
| 사진도 브라우저에 저장 | 점 개수를 다시 굴릴 수 있다      | `localStorage` 5MB 한도에 사진 한 장이 다 들어간다           |
| 사진을 줄여서 저장     | 같음                             | 긴 변 512px JPEG면 100KB쯤. 다시 딴 윤곽이 미세하게 달라진다 |

**세 번째를 기본으로 잡는다.** 점 개수를 바꿔 가며 여러 장 뽑는 것이 이 놀이의
쓰임인데(같은 사진, 다른 난이도) 첫째 갈래는 그때마다 사진을 다시 찾게 만든다.
다만 줄인 사진에서 다시 딴 윤곽이 처음과 다르면 사용자가 보기에 도안이 저 혼자
바뀐 것이므로, **점 좌표도 함께 저장해 두고 개수를 바꿀 때만 다시 딴다.**

`localStorage`가 꽉 차는 경우도 처음 생긴다(`src/lib/customization/storage.ts`).
저장에 실패하면 조용히 넘기지 말고 알린다.

## 조작

- **사진 넣기** — 파일 고르기 · 끌어다 놓기 · 모바일에서 카메라. 만들기 페이지에
  드래그 안내가 이미 있다(`IDE-006`).
- **점 개수** — 프리셋 단추(10 · 20 · 30 · 50 · 100)와 직접 입력. 프리셋은 나이대
  안내를 붙인다(10~~20은 만 3~~4세, 50 이상은 만 6세 이상). 개수를 바꾸면 다시
  따지 않고 **점만 다시 배분한다** — 윤곽선은 그대로다.
- **상한 안내** — 넣은 개수가 상한을 넘으면(`IDE-019`) 왜 못 넣는지와 최대치를
  말한다. 입력 칸을 막지 않고, 넘은 값을 넣으면 최대치로 잡아 준다.
- **밝기·임계값** — 자동 이진화가 실패한 사진을 사용자가 민다. 슬라이더 하나다.
- **돌리기·뒤집기** — 가로 사진을 세로 판에 맞출 때. 90° 단위와 좌우 반전.
- **다시 따기** — 같은 사진으로 처음부터.
- **키보드로도 된다.** 슬라이더·프리셋·개수 입력 전부. `IDE-009`가 마커 이동에서
  확인한 것과 같은 요구다.

## 미리보기

윤곽선과 점·번호를 **판 위에 그대로** 보여 준다. 사진은 미리보기에서도 배경에
깔지 않는다 — 인쇄물에 없는 것이 화면에 있으면 사용자가 뽑고 나서 놀란다.
대신 딴 윤곽이 사진과 맞는지 보라고 **원본 대조 보기**를 따로 둔다(누르는 동안만
사진이 겹쳐 보이는 식).

`BoardPreview`가 `fetch(part.artwork)`로 정적 SVG를 읽고 있으므로, 생성된 SVG를
받는 길이 필요하다. 그 접점은 `IDE-019`가 낸다.

## 실패했을 때

사진이 안 되는 경우가 흔하다 — 배경이 복잡하거나, 역광이거나, 피사체가 작거나.
`IDE-019`가 사유를 돌려주므로 **무엇을 하면 되는지로 옮겨 적는다**: "배경이 단순한
곳에서 찍은 사진이 잘 됩니다", "밝기를 조절해 보세요". 빈 판이 나오고 마는 것이
제일 나쁘다.

## 수용 기준

- [ ] 사진을 넣고 점 개수를 고르면 미리보기에 점·번호가 바로 보인다
- [ ] 점 개수를 바꾸면 윤곽선은 그대로고 점만 다시 배분된다
- [ ] 브라우저를 닫았다 열어도 같은 도안이 나오고, 점 개수를 다시 바꿀 수 있다
- [ ] 저장 한도를 넘으면 사용자가 그 사실을 안다
- [ ] 윤곽을 못 딴 사진에서 빈 판이 아니라 무엇을 하면 되는지가 나온다
- [ ] 마우스 없이 키보드만으로 사진 넣기부터 인쇄까지 간다
- [ ] 사진이 서버로 가지 않는다
- [ ] 다른 네 게임의 에디터가 그대로 동작한다
