## 배경

여섯 번째 놀이다. 사용자가 요청했다(2026-09-15).

> 골프 게임을 추가하고 싶어. 홀 1개를 A4 용지로 출력하고, 홀은 총 18개 맵이
> 필요해. 게임방식은 축구와 야구게임과 유사하게 연필로 튕겨서 홀구멍에 정확히
> 넣는거야. 파와 버디, 이글 같은 규칙은 골프 규칙과 동일하고, 아이들이 기록표에
> 직접 기록해서 숫자쓰기과 합산을 통해 덧셈도 같이 공부했으면 좋겠어.

손놀림은 축구·야구에서 그대로 온다 — 연필로 공을 튕긴다. 다른 것은 **목표가
상대가 아니라 자기 타수**라는 점이고, 그래서 혼자서도 놀 수 있는 두 번째
게임이다(점 잇기에 이어).

작도를 마친 뒤 사용자가 하나를 더 청했다(같은 날).

> A4 용지를 최대한 활용해서 골프장을 만들고 싶거든. 그래서 골프장 밖에
> 표현하는 모든것들을 골프장 안에 있는 빈 공간으로 이동시키고 싶어.

첫 판은 위에 머리띠(홀 번호·이름·파·거리), 아래에 타수 이름 한 줄을 두고 그
사이를 코스로 썼다 — 띠 둘이 세로 50mm를 먹고 있었다. 지금은 **종이 전체가
골프장**이고, 홀 정보는 코스 안 빈 자리에 얹힌 카드 한 장이다. 코스도
그만큼 커졌다(세로 1.25배).

그다음 청한 것이 하나 더 있다(같은 날) — "1번홀부터 18번홀까지 홀 선택은
셀렉트 박스로 바꿔줘." 만들기 화면의 파트 줄이 단추 스무 개였다. 규격에
`series`(파트 묶음 이름)를 더해 **같은 묶음을 단 파트는 셀렉트 하나로
접히게** 했다. 인쇄 화면은 건드리지 않았다 — 사용자가 고른 처분이 "만들기
화면만 셀렉트"였고, 그래야 열여덟 장을 한 번에 뽑는 길이 남는다.

## 이 놀이가 규격에서 처음 밟는 것

**판이 열여덟 장이다.** 지금까지 게임 하나는 "보드 1장 + 부속 N장"이었고,
`parseGame`이 **보드는 정확히 1개**를 강제한다. 골프는 홀 하나가 A4 한 장이고
열여덟 장이 다 인쇄돼야 한 라운드가 되므로, 나머지 열일곱 장을 담을 자리가
없었다.

고를 수 있는 길이 셋이었다.

1. **판 하나 + 홀 선택 슬롯** — 파트 변형(`IDE-016`)이나 동적 파트로 홀을 골라
   그린다. 파트는 하나로 끝나지만 **한 번에 한 홀만 인쇄된다.** 열여덟 장을
   받으려면 홀을 바꿔 가며 PDF를 열여덟 번 내려받아야 한다.
2. **홀 열일곱 장을 `cutout`으로** — 오릴 데가 없는 판에 오림선을 그려야 한다.
   규격이 `cutout`에 `cut` 표시를 요구하기 때문이다.
3. **파트 종류를 하나 더 세운다** — `sheet`. 보드처럼 그냥 쓰는 낱장이되 보드는
   아닌 것.

3을 골랐다. 사용자가 청한 것은 "18개 맵"이고, 한 라운드를 치려면 그 열여덟 장이
**한 번에** 나와야 한다. 규격 변경은 `partKind`에 값 하나를 더하고 보드와 같은
표시 규칙(오림선·접는선 없음)을 적용한 것이 전부다.

쓰는 쪽에서는 **가위가 드는가**로 갈린다(`isBoardLike`). 인쇄 화면의 '게임판만 ·
부속만'과 PDF 파일 이름이 그 선을 쓴다 — 골프에서 '게임판만'은 홀 열여덟 장과
기록표뿐이다 — 부속은 없다(`IDE-032`). 앞선 다섯 게임은 `sheet` 파트가 없으므로
동작이 그대로다.

## 코스

파 72다(전반 36 · 후반 36, 파3 넷 · 파4 열 · 파5 넷). 홀마다 성격을 하나씩 주었다
— 연못을 건너는 홀, 섬 그린, 강이 가로지르는 홀, 모래가 많은 홀, 두 번 굽는 홀.

**홀 하나는 중심선(`spine`) 하나에서 나온다.** 첫 점이 티, 마지막 점이 그린
중심이고 페어웨이는 그 선을 부풀린 띠다. 가장자리를 따로 적지 않는 이유는
어긋나지 않기 위해서다 — 티가 페어웨이 밖에 서는 어긋남은 종이에 뽑기 전에는
보이지 않는다.

작도 근거는 [docs/golf-artwork.md](../docs/golf-artwork.md)에 있다.

## 기록표 — 사용자가 함께 청한 것

"숫자쓰기와 합산"이 요청의 절반이었다. 그래서 기록표는 점수를 남기는 자리가
아니라 **셈이 일어나는 자리**로 만들었다.

- 표가 둘이다 — 전반 아홉 홀(OUT), 후반 아홉 홀(IN). 열여덟 칸을 한 줄로
  늘어놓으면 칸이 12mm로 좁아지고, 무엇보다 아홉씩 끊어 더하는 골프의 셈이
  사라진다.
- 합산 칸에 `+`와 `=`를 **미리 인쇄**했다. 빈칸 셋만 있으면 아이는 그것이
  덧셈인 줄 모른다.
- 마지막 열이 `− 72 =`다. 덧셈 두 번 다음에 뺄셈 한 번이 온다.
- 파와 거리만 인쇄되어 있고 이름과 타수는 비어 있다. 아이가 직접 쓴다(축구
  게임판의 점수 기록칸과 같은 규칙, 2026-09-08).

홀 판 바닥에도 한 줄이 있다 — 그 홀의 파에서 **몇 타가 무엇인지**다. 파 4홀이면
"3타 버디 · 4타 파 · 5타 보기". 점수의 이름은 실제 골프와 같다(사용자 요청).

## 수용 기준

- [x] 홀 열여덟 장이 각각 A4 한 장이고 배율 100%에서 한 장에 담긴다
- [x] 코스 영역이 종이의 92% 이상 — 가장자리 6mm만 남긴다
- [x] 홀 정보 카드가 코스 안에 있고, 코스 요소에서 4mm 떨어져 앉는다
- [x] 나무가 카드 밑에 깔리지 않는다
- [x] 카드 안의 글자가 카드 폭을 넘지 않는다(홀 이름·타수 이름)
- [x] 만들기 화면에서 홀 열여덟 장이 셀렉트 하나로 접힌다
- [x] 기록표는 묶이지 않고 단추로 남는다
- [x] 인쇄 화면은 그대로 — 파트마다 한 줄이라 한 번에 스무 장을 뽑는다
- [x] 파 72 — 전반 36 · 후반 36
- [x] 코스의 모든 요소가 O.B. 선 안에 있다
- [x] 홀이 그린 안에 있고, 벙커가 그린을 덮지 않는다
- [x] 티가 페어웨이 안에 있고 해저드와 겹치지 않는다
- [x] 페어웨이 가장자리가 스스로를 넘지 않는다(굽은 홀의 자기교차)
- [x] 공(지름 12mm)이 홀 원(지름 16mm)보다 작다
- [x] 기록표의 표 둘과 합산 칸이 A4 가로 한 장에 앉는다
- [x] 이름 슬롯 넷이 세 표의 같은 줄에 찍힌다
- [x] 커밋된 SVG 스무 장이 생성기와 같다
- [x] 규칙문이 벌타 셋과 덧셈 절차, 점수의 이름을 말한다
- [ ] ⚠︎ 종이 실측 — 배율 100%에서 홀 판·기록표의 글자가 읽히는지
- [ ] ⚠︎ 놀아 보기 — 연필로 튕겨 홀 원에 멈추는 맛, 홀 원 지름 16mm가 맞는지
- [x] ⚠︎ 깃대와 공 — 쳐 보고 **뺐다**(`IDE-032`). 인쇄물은 판과 기록표뿐이다

## 남은 물음

- **벙커 1벌타.** 실제 골프에는 없는 벌타다. 모래를 피해 치는 재미를 주려고
  두었고, 하우스 룰 절에 "빼고 쳐도 된다"를 적었다. 놀아 보고 정한다.
- **홀 원 지름 16mm.** 공이 12mm라 "닿아 멈추면 홀아웃"이다. 너무 쉬우면 원을
  줄이고, 어리면 그린 안에 멈추는 것으로 친다(하우스 룰).
- **열여덟 장을 한 번에 뽑을 때 스무 장짜리 PDF**가 된다. 인쇄 상한
  (`MAX_PAGES` 200)에는 여유가 있지만, 기본 선택을 '게임판만'으로 둘지는
  써 보고 정한다.
