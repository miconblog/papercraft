# 야구 — 실제 야구 규칙 영역 목업 (IDE-044)

지금 야구장(`public/games/baseball/field.svg`)을 그대로 깔고 그 위에 제안 영역을
얹은 **설명용 그림**이다. 오른쪽 패널에 영역별 면적과 몫이 적혀 있다.

| 스크립트             | 산출                             | 무엇                                                     |
| -------------------- | -------------------------------- | -------------------------------------------------------- |
| `render-defense.mjs` | `out/baseball-defense-zones.svg` | **지금 안** — 수비 배치에서 영역을 뽑는다                |
| `render.mjs`         | `out/baseball-rule-zones.svg`    | 첫 안 — 홈에서의 거리로 나눈다. **되돌렸다**(2026-09-20) |

첫 안은 파울라인 안쪽 쐐기가 1루 베이스를 품어 땅볼 구간에 멈춘 공이 선상 2루타가
됐다. 견주어 보라고 남겨 둔다.

## 능력치 배분을 바꿔 가며 본다

기본 내야 20 · 외야 28mm에서 **팀 능력치 10mm**를 나눠 준다(한 자리 최대 6mm).
인자로 배분을 주면 판과 면적 표가 함께 바뀐다 — 면적은 하드코딩이 아니라 그때
적분한다.

    node render-defense.mjs                    # 중견수=6,유격수=4 (기본 예시)
    node render-defense.mjs 중견수=6,유격수=4
    node render-defense.mjs 좌익수=3,중견수=4,우익수=3
    node render-defense.mjs 기본               # 배분 없음

예산을 넘기거나 한 자리 상한(내야 26 · 외야 34)을 넘기면 그 자리에서 멈춘다.

**도안 생성기가 아니다.** 치수를 베껴 적었고 `dimensions.ts`가 원본이다.

## 구현은 들어갔다 (2026-09-20)

실제 판은 `src/assets/games/baseball/artwork/rule-zones.ts`가 그린다. 야구장이
동적 파트가 되어 **값에서 그때 그리므로** `field-real.svg` 같은 파일은 나오지
않는다 — 커밋되는 정적 파일은 기본 규칙 한 벌뿐이다.

여기 목업과 실제 판이 **한 군데 다르다.** 목업은 선상 쐐기에서 수비 범위 원을
SVG 마스크로 오려 냈는데, 인쇄 경로(`lib/print/artwork.ts`)가 마스크도 클립도
받지 않는다. 비영 감기로 구멍을 내는 수법도 원이 쐐기 밖으로 걸치면 그 바깥이
칠해져 못 쓴다. 그래서 판에서는 **범위 원을 쐐기 위에 그리고 판정 차례를 종이에
찍는다** — 겹친 자리는 그림이 아니라 차례가 가른다.

면적 몫을 다시 재 볼 때는 이 스크립트가 여전히 가장 빠르다. 판정 차례대로
적분하므로 「수비가 이긴다」가 숫자에는 그대로 반영된다.

PNG로 보려면:

    rsvg-convert -d 150 -p 150 out/baseball-defense-zones.svg -o out/preview-defense.png
