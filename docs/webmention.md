# 웹멘션 · 핑백 — 블로그끼리 "이야기했다"를 주고받기

글에 남의 블로그 링크를 걸면 그 블로그에 알리고, 남이 이 사이트의 글 · 게임을
가리키면 받아서 승인한 것만 글 아래에 세운다.

이슈: `issues/IDE-046-webmention-pingback.md`

## 두 규약

|             | 웹멘션                                  | 핑백                                        |
| ----------- | --------------------------------------- | ------------------------------------------- |
| 무엇        | W3C 권고(2017)                          | XML-RPC 규약(2002)                          |
| 누가 쓰나   | 인디웹 · 정적 블로그 · 플러그인         | 워드프레스(기본으로 켜져 있다)              |
| 싣는 방식   | 폼 — `source` · `target`                | XML — `pingback.ping(source, target)`       |
| 실패를 말함 | HTTP 상태 코드                          | 200 에 실은 `<fault>` 의 번호               |
| 우리 주소   | `/api/webmention`                       | `/api/pingback`                             |
| 알리는 방법 | `Link` 헤더 · `<link rel="webmention">` | `X-Pingback` 헤더 · `<link rel="pingback">` |

싣고 오는 봉투만 다르고 안에 든 것은 같다 — **출처**(가리킨 글)와 **대상**(가리켜진
글). 그래서 받는 길도 보내는 길도 하나이고 봉투만 갈아 끼운다.

## 어디에 있나

| 무엇                | 자리                                                   |
| ------------------- | ------------------------------------------------------ |
| 받는 주소           | `src/app/api/webmention` · `src/app/api/pingback`      |
| 받는 길             | `src/lib/mentions/receive.ts`                          |
| 보내는 길           | `src/lib/mentions/send.ts`                             |
| 밖으로 나가는 요청  | `src/lib/mentions/fetchPublic.ts` · `address.ts`       |
| 받는 주소 알리기    | `next.config.ts`(헤더) · `MentionEndpoints`(`<link>`)  |
| 글 · 게임 아래의 칸 | `src/components/mentions/MentionSection.tsx`           |
| 관리자 화면         | `/admin/mentions`                                      |
| 표                  | `daddys_craft.mentions` · `daddys_craft.mentions_sent` |

## 처음 한 번만 하는 설정

```bash
npm run db:migrate -- --dry   # 017-mentions.sql 한 건이 대기 중인지 본다
npm run db:migrate
```

환경변수는 **넣을 것이 없다.** 운영 배포에서는 기본으로 켜져 있다.

표가 없는 동안에도 사이트는 그대로 뜬다 — 받는 주소는 "나중에 다시"(503)로
답하고, 보내기는 아무것도 하지 않는다.

## 받기

멘션을 받는 화면은 둘이다 — **글 하나**(`/blog/<슬러그>`)와 **게임 하나**
(`/games/<id>`). 목록이나 게임 방법 화면은 받지 않는다.

받는 주소는 누구나 부를 수 있어서 믿을 것이 없다. 순서대로 본다.

1. 주소 둘이 웹 주소인가, 출처가 우리 사이트는 아닌가
2. 대상이 **지금 열려 있는** 글 · 게임인가 — 안 낸 글과 없는 글은 같은 답을
   받는다(갈라 답하면 "여기 안 낸 글이 있다"를 알려 주게 된다)
3. 저장소에 닿나, 대기 줄에 자리가 있나(호스트당 10 · 전체 200)
4. **출처에 직접 가서** 우리로 오는 `<a href>` 가 정말 있나

4번을 지나야 담긴다. 주소를 글자로만 적었거나 주석 속에 숨긴 것은 링크가 아니다.
링크는 글자가 아니라 **대상으로 읽은 뒤에** 견준다 — `www` · 스킴 · 끝의 `/` ·
`?utm_source=…` 가 달라도 같은 글이다.

담긴 멘션은 **대기**다. `/admin/mentions` 에서 승인해야 글 · 게임 아래에 선다
(사이드 메뉴에 대기 숫자가 붙는다). 승인하면 그 화면이 곧바로 다시 그려진다.

### 같은 멘션이 다시 오면

보낸 쪽이 글을 고치면 같은 멘션을 다시 보내는 것이 규약이다.

| 출처의 상태                     | 하는 일                       |
| ------------------------------- | ----------------------------- |
| 링크가 그대로, 내용도 그대로    | 그대로 둔다(승인도 그대로)    |
| 제목이나 링크 둘레가 바뀌었다   | 고치고 **다시 대기로** 내린다 |
| 링크를 뺐다 · 글이 사라졌다     | 지운다                        |
| 잠깐 안 닿는다(시간 초과 · 5xx) | 건드리지 않는다               |

내용이 바뀌면 승인이 풀리는 것은, 멀쩡한 글로 승인받은 뒤 광고로 바꿔 다시 보내는
길을 막으려는 것이다.

### 세우는 것은 글자뿐이다

제목과 발췌는 **남의 서버가 준 값**이다. 댓글과 같은 잣대로 서식을 해석하지 않고
글자로만 그린다. 링크에는 `rel="nofollow ugc"` 를 붙인다 — 멘션이 검색 순위를 얻는
길이 되면 스팸이 몰린다.

## 보내기

본문에 **링크 서식으로 건 바깥 주소**가 대상이다(사진 주소는 아니다). 한 글에서
스무 곳까지, 앞에서부터 보낸다.

링크마다 그 글에 가서 **받는 주소를 찾는다** — `Link` 헤더, 문서의
`<link>`/`<a rel="webmention">`, 없으면 핑백(`X-Pingback` · `<link rel="pingback">`).
웹멘션을 받는 곳에는 웹멘션만 보낸다. 둘 다 안 받는 곳에는 아무것도 가지 않는다.

### 언제 나가나

| 때                             | 무엇을 보내나                                           |
| ------------------------------ | ------------------------------------------------------- |
| 공개 중인 글을 **저장**        | 처음 보는 링크 · 실패했던 링크. 뺀 링크에는 뺐다고 알림 |
| 「발행하기」로 지금 냄         | 위와 같다. 다만 **30초쯤 뒤에** 나간다(아래)            |
| **예약 글**이 시각이 지나 열림 | 열린 뒤 화면이 처음 그려질 때, 한 번도 안 보낸 링크만   |
| 관리자 화면의 「다시 보내기」  | 지금 걸린 링크 전부                                     |

저장은 기다리지 않는다 — 보내기는 **응답 뒤에** 돈다. 결과는 `/admin/mentions`
아래쪽 「보낸 멘션」에 남는다(보냄 · 실패 · 받는 곳 없음).

**한 번 보낸 링크는 다시 보내지 않는다.** 오타 하나 고칠 때마다 남의 서버를
두드리지 않으려는 것이다. 슬러그를 고쳐 우리 글의 주소가 달라졌으면 다시 보낸다.

**방금 낸 글은 30초쯤 기다렸다 보낸다.** 받는 쪽은 받자마자 우리 글에 와서 링크를
확인하는데, 문지기가 "낸 글 목록"을 30초 메모해 두기 때문에 그 사이에는 아직
404 일 수 있다.

**안 낸 글의 멘션은 나가지 않는다.** 받는 쪽이 확인하러 와도 글이 없고, 아직
세상에 안 낸 글의 주소를 남의 서버에 알려 주게 된다.

### 운영 배포에서만 나간다

로컬과 미리보기 배포는 운영과 **같은 글**을 읽는다. 거기서 저장한 글이 남의
블로그에 진짜 멘션을 쏘면 되돌릴 수 없다.

| `WEBMENTION_SEND` | 뜻                                     |
| ----------------- | -------------------------------------- |
| (비어 있음)       | `VERCEL_ENV=production` 일 때만 보낸다 |
| `off`             | 운영에서도 끈다                        |
| `on`              | 어디서든 켠다 — 로컬에서 시험할 때만   |

받기는 스위치가 없다. 받는 주소가 서 있으면 받는다.

## 밖으로 나가는 요청

이 기능은 **남이 적어 준 주소로 우리 서버가 요청을 건다.** 받을 때는 출처 주소로,
보낼 때는 남의 글이 알려 준 받는 주소로. 그 주소가 `http://169.254.169.254/` 나
`http://localhost:5432/` 면 우리 서버가 바깥사람 대신 안쪽을 두드리게 된다.

그래서 멘션이 거는 요청은 전부 `fetchPublic` 을 지난다.

- **세상에 열린 주소로만** — 사설 · 루프백 · 링크 로컬 · IPv4 를 품은 IPv6 를 막는다.
  검사는 **연결이 쓰는 이름 풀이**에 끼워 둔다. 먼저 풀어 보고 요청을 걸면 그
  사이에 이름이 다른 곳을 가리키게 바꿀 수 있다
- `http` · `https` 의 **기본 포트만**, 계정이 실린 주소는 안 간다
- 넘겨 주기(3xx)는 다섯 번까지, **따라갈 때마다 처음부터 다시 본다**
- 1MB 까지만 읽고, 넘겨 주기를 합쳐 8초 안에 끝낸다

HTML 과 XML 은 파서 없이 읽는다. 필요한 것이 태그의 속성과 문자열 둘뿐이고,
XML 을 진짜로 해석하지 않으면 엔티티 선언을 따라갈 일도 없다. 큰 문서를 훑는
자리는 정규식이 아니라 앞으로만 가는 스캐너다 — 닫히지 않은 태그를 십만 번 적은
문서에도 느려지지 않는다.

## 로컬에서 시험하기

밖으로 나가는 요청은 `127.0.0.1` 을 막으므로, 로컬의 다른 서버를 상대로 시험하려면
스위치를 켠다. **개발 서버에서만 먹는다** — 운영 빌드에서는 무엇으로 주든 꺼져
있다.

```bash
MENTIONS_ALLOW_LOCAL=1 WEBMENTION_SEND=on NEXT_PUBLIC_SITE_URL=http://localhost:3000 npm run dev
```

```bash
# 받기 — 웹멘션
curl -i http://localhost:3000/api/webmention \
  --data-urlencode "source=http://127.0.0.1:8080/post-that-links-here" \
  --data-urlencode "target=http://localhost:3000/blog/<슬러그>"
```

> **`.env.local` 이 운영 DB 를 가리키고 있으면 조심한다.** 위처럼 켜고 글을
> 저장하면 그 글의 바깥 링크에 진짜 멘션이 나가고, 받은 멘션도 운영 표에 담긴다.
> 시험은 받는 곳이 로컬인 링크로만 하거나 `SUPABASE_URL` 을 다른 곳으로 돌려서
> 한다.

## 하지 않는 것

- **글을 내리거나 지울 때 알리지 않는다.** 본문에서 링크를 빼고 저장하면 알리지만,
  글 자체가 사라질 때는 보내지 않는다
- **트랙백은 받지 않는다.** 출처를 확인하는 절차가 없는 규약이다
- **멘션의 종류(좋아요 · 답글 · 리포스트)를 가리지 않는다.** 전부 "이야기한 곳"
  한 가지로 세운다
