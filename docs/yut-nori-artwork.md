# 윷놀이 도안

`IDE-017`(말판·말·게임 방법)과 `IDE-018`(윷가락)의 작도 결과다. 치수의 **원본은 코드**
(`src/assets/games/yut-nori/dimensions.ts`)이고 이 문서는 왜 그 값이 되었는지를
적는다. 둘이 어긋나면 코드가 맞다.

인쇄 규격은 [`print-spec.md`](print-spec.md), 도안 데이터 모델은
[`game-authoring.md`](game-authoring.md)를 따른다. 앞선 게임들과 겹치는 규약
(레이어 id·표시선·텐트형 부속)은 [`soccer-artwork.md`](soccer-artwork.md)와
[`baseball-artwork.md`](baseball-artwork.md)에 먼저 적혀 있다.

---

## 1. 만드는 법

```
src/assets/games/yut-nori/
  dimensions.ts      ← 모든 실측 치수와 29밭 그래프. 고칠 곳은 여기 하나다
  rules.ts           ← 게임 방법 텍스트
  artwork/
    board.ts         ← 말판 198×198
    tokens.ts        ← 말 — 4편 × 넷, 텐트형
    sticks.ts        ← 윷가락 — 반육각기둥 넉 장 (IDE-018)
    rules-sheet.ts   ← 게임 방법 부속 (규칙문을 두 단으로 조판)
  index.ts           ← 도안 정의
public/games/yut-nori/*.svg   ← 산출물. 커밋한다
```

```bash
npm run artwork yut-nori   # 이 게임의 SVG만 다시 만든다
npm run test:run           # 커밋된 SVG가 생성기와 같은지까지 본다
```

좌표는 **격자에서 계산해 뽑는다.** 밭 스물아홉의 자리를 손으로 적은 곳이 한
군데도 없고, 도안 테스트가 그것을 **판 중심에 대한 180° 회전 대칭**으로
확인한다 — 어느 한 밭이라도 손으로 밀어 두면 그 검사가 깨진다.

## 2. 판이 정사각이다

| 게임     | 보드 치수 | `orientation` |
| -------- | --------- | ------------- |
| 축구     | 285×198   | `landscape`   |
| 야구     | 210×297   | `portrait`    |
| 세계일주 | 297×210   | `landscape`   |
| 윷놀이   | 198×198   | `landscape`   |

파트 검증은 `widthMm >= heightMm`를 가로로 읽는다
(`src/lib/schema/parts.ts`). **정사각 보드는 그래서 `landscape`로 선언해야
통과한다.** 규칙이 이미 그렇게 정해져 있었고 이 게임이 처음 밟았다 — 스키마는
한 줄도 고치지 않았다.

한 변 198mm인 것은 두 가지 때문이다.

- A4 세로(210×297)의 **폭 안에** 들어간다. 배율 100%에서 한 장이다.
- 축구 운동장의 짧은 변(198)과 **같다.** 두 게임을 100%로 뽑으면 밭·선이 같은
  굵기로 읽힌다.

정사각이 카탈로그에서 줄을 늘리지 않는 것은 카드가 도안 비율이 아니라 **A4
가로 크기의 자리를 늘 같게 잡고** 그 안에 그림을 통째로 담기 때문이다
(`object-contain`, `IDE-011` 2026-09-08 결정). 랜딩 히어로는 그림의 실제
비율을 그대로 쓰므로 정사각이면 정사각으로 앉는다.

## 3. 밭 스물아홉

**5칸 × 5칸이 아니라 6점 × 6점이다.** 바깥은 각 변에 여섯 점씩, 모서리를
공유해 `6 × 4 − 4 = 20`밭. 대각선은 네 모서리에서 방(가운데)까지 두 밭씩
여덟에 방 하나를 더해 아홉. 합쳐 **29밭**이 전통 윷판의 수다.

```
격자 여백 19mm · 한 칸 32mm (= (198 − 19×2) / 5)
큰 밭 지름 30mm (네 모서리와 방)
작은 밭 지름 22mm (나머지 스물넷)
```

- **32mm 간격**은 큰 밭과 작은 밭이 이웃해도 6mm가 남는 값이다. 밭이 서로
  닿으면 말을 어느 밭에 세운 것인지 다투게 된다. 도안 테스트가 모든 쌍의
  간격이 1mm를 넘는지 본다.
- **여백 19mm**는 모서리 큰 밭(반지름 15)에서 종이 끝까지 4mm를 남긴다.
  가정용 프린터의 인쇄 불가 영역(보통 3mm대)을 넘긴다.
- **작은 밭 지름 22mm**가 말 카드 폭(20mm)의 상한을 정한다. 말이 밭보다 넓으면
  이웃 밭을 가린다.

### 큰 밭이 규칙을 말한다

전통 윷판이 네 모서리와 방을 크게 그린다. **지름길이 갈라지고 만나는 자리가
곧 큰 밭**이라, 밭 이름을 적지 않는 이 도안에서 크기가 규칙의 유일한 안내다.
큰 밭은 겹원으로 그려 멀리서도 갈림길이 보인다.

### 밭 이름을 적지 않는다

전통 윷판에 이름이 없다. 도·개·걸은 **윷가락이 내는 값**이지 밭 이름이 아니고,
밭 이름(참먹이·쨀밭·날밭…)은 지역마다 달라 하나를 고르면 틀린 쪽이 생긴다.
판에 적는 글자는 출발점의 `출발`·`도착` 둘뿐이고, 그마저 큰 밭 **안**에 넣었다
— 판 가장자리에는 자리가 없고(4mm다) 밭 밖 안쪽은 이웃 밭과 대각선이 이미
차지했다.

규칙을 설명하려면 자리를 가리킬 말이 있어야 하므로, **게임 방법 부속에서는**
"오른쪽 위 큰 밭"처럼 위치로 부르고 전통 이름을 괄호에 넣는다.

### 바깥 밭에는 잇는 선이 없다

전통이 그렇고, 그 덕에 **판에서 선으로 보이는 것은 대각선 넷뿐**이다. 지름길이
어디서 갈라지는지가 그림만 보고 읽힌다. 바깥까지 선으로 이으면 판이 선
무더기가 되어 그 대비가 사라진다. 진행 방향은 각 변 한가운데, 밭과 밭 사이
빈자리에 앉는 작은 세모가 말한다.

대각선은 밭 **아래**에 깔린다 — 밭 원을 흰색으로 채워 선이 밭 안을 가로지르지
않는다.

## 4. 경로가 갈라진다 — 한 줄이 아니라 그래프

세계일주(`IDE-015`)의 경로는 서울에서 서울로 이어지는 **순환 목록**이었다.
윷판은 모서리에서 갈라져 방을 지나 나오므로 목록으로 적을 수 없다. 밭마다
나가는 간선이 있고, 갈라지는 자리에서는 둘이다.

| `EdgeKind` | 언제 쓰나                                |
| ---------- | ---------------------------------------- |
| `next`     | 늘 쓰는 기본 진행. 밭마다 하나씩 있다    |
| `shortcut` | 모서리 밭에 **정확히 멈췄을 때만**       |
| `through`  | 방을 **지나칠 뿐일 때** 곧게 건너가는 길 |

"정확히 멈췄는가"는 놀이하는 사람이 판단하고 **도안은 길만 그린다.**

### 네 갈래

바깥 밭은 `o0`(출발·도착, 오른쪽 아래) … `o19`이고 번호가 진행 차례다. 모서리는
`o0`·`o5`·`o10`·`o15`, 진행은 반시계다.

| 경로                          | 밟는 칸 수 |
| ----------------------------- | ---------- |
| 바깥길만                      | 20         |
| `o5`에서 지름길 → 방에 멈춤   | **11**     |
| `o5`에서 지름길 → 방을 지나침 | 16         |
| `o10`에서 지름길 → 방에 멈춤  | 16         |

- **방에 멈추면** 참먹이 쪽 대각선으로 질러 나온다. 이것이 가장 짧은 길(11칸)
  이고, 윷놀이의 승부가 여기서 갈린다.
- **방을 지나칠 뿐이면** 들어온 대각선을 곧게 건너 반대편 모서리로 나간다.
- **왼쪽 아래 모서리(`o15`)에는 지름길이 없다.** 그 대각선은 방에서 _나오는_
  길이라, 거기로 들어가면 방까지 3칸 + 방에서 참먹이까지 3칸 = 6칸으로 바깥길
  5칸보다 오히려 길다. 전통 윷판이 그 모서리를 입구로 삼지 않는 이유가 그것이다.

네 경로를 합치면 **29밭이 빠짐없이** 나온다. 어느 경로에도 없는 밭이 있으면 그
밭은 판에 그려져 있으면서 갈 수 없는 자리다 — 지름길이 두 갈래로 나뉘어 있어
눈으로는 잘 안 보이므로 도안 테스트가 본다. 규칙문이 적은 11칸·20칸도 같은
테스트가 실제 경로와 맞춰 본다.

## 5. 말 — 텐트형 카드 열여섯

4편 × 넷이다. 카드 한가운데를 산접기로 접으면 두 면이 마주 보며 ∧ 로 선다
(야구 선수 스탠드와 같은 수법, `IDE-014`). 풀도 칼도 탭도 없다.

```
카드 20 × 52mm (한 면 26mm) · 격자 4열 × 4행 (한 줄이 한 편) · 시트 112 × 252mm
접는선에서: 그림 8mm · 색 띠 14.9mm · 편 이름 18.5mm · 업기 숫자 23mm
```

세계일주의 말은 **눕혀 쓰는 원판**이었다(칸 지름 6.6mm에 세운 말이 이웃 칸을
가렸다). 윷판은 밭이 지름 22mm로 넓어 세워도 되고, **세운 말이라야 업힌 수가
옆에서 보인다.**

시트가 A4를 채우지 않는 것은 카드가 커질 수 없기 때문이다 — 밭 지름이 상한이다.
늘리면 남는 것은 빈 종이뿐이라 종이를 아끼는 쪽을 골랐다.

### 편을 가르는 것 — 색과 그림 양쪽

색만으로 가르면 흑백 출력에서 누구 말인지 알 수 없다(`IDE-009`가 축구 팀
색에서 확인한 것). 그림(동그라미·세모·네모·별)은 **고정**이다 — 고를 수 있게
하면 두 편이 같은 그림을 고를 수 있다. 색은 레이어 `pc-side-<n>`이 받고
사용자가 고친다.

### 업은 말을 세는 법

같은 편 말이 한 밭에서 만나면 업어 한 몸이 되는데, 텐트형 말을 그냥 포개면
옆에서 몇이 업혔는지 보이지 않는다. 그래서 말 넷 가운데 **셋의 밑동에
`2`·`3`·`4`를 적어 두고, 업으면 그 수의 말 하나로 바꿔 세운다.** 말이 따로
서 있을 때는 숫자를 보지 않는다 — 어느 말이든 한 마리다.

실물로 놀아 봐야 정해지는 자리라 이슈(`IDE-017`)에 미완으로 남겼다.

### 위쪽 면을 돌려 그린다

접으면 위쪽 면이 뒤로 넘어가 뒤집히므로 미리 180° 돌려 그려야 세웠을 때
양쪽에서 다 바로 보인다. 야구 스탠드는 그림만 돌리고 이름표는 앞면에만
넣었는데, 윷놀이의 **업기 숫자는 어느 쪽에서 보든 읽혀야 하는 값**이라 글자도
돌린다(`transform="rotate(180 …)"`). 편 이름은 슬롯이라 배치의 `rotationDeg`가
돌린다.

> **인쇄 렌더러를 한 줄 고쳤다.** SVG 파서가 글자의 자리를 평행이동·배율로만
> 계산해, 회전이 걸린 글자가 대칭점이 아니라 원래 자리에 남았다
> (`src/lib/print/artwork.ts`). 화면은 브라우저가 SVG를 그대로 그려 맞고
> PDF만 틀리는 종류의 결함이라 눈에 띄지 않는다. 회전한 정적 글자를 쓴 도안이
> 이 게임이 처음이라 여태 드러나지 않았다.

## 6. 게임 방법 부속

규칙의 **진짜 자리는 도안 정의의 `rules` 필드**이고 소개 페이지가 그것을
그린다. 이 시트는 같은 값을 종이로 낸 것이라, 규칙을 인쇄 파트에 매지 않는다는
결정(2026-09-05)과 어긋나지 않는다 — [`game-authoring.md`](game-authoring.md)가
"규칙 카드를 원하는 게임은 이 값을 읽어 부속을 그리면 된다"고 적어 둔 자리다.

윷놀이가 그것을 원하는 이유는 **규칙이 길고 놀면서 자꾸 되짚기 때문**이다.
지름길이 열리는 조건, 업은 말을 세는 법, 백도를 쓸지가 다 적혀야 형제끼리
싸우지 않는다.

```
시트 190 × 266mm · 두 단 79mm씩 · 본문 2.9mm / 줄 간격 4.2mm
```

- **두 단인 이유** — 한 단으로 흘리면 A4를 넘긴다. 두 단이면 줄 길이도 79mm로
  짧아져 눈이 줄을 놓치지 않는다.
- **높이는 두 단이 고르게 차는 값**이다. 더 길면 첫 단만 꽉 차고 둘째
  단 아래가 비고, 더 짧으면 둘째 단이 넘친다. 240 → **266mm**(`IDE-018`) —
  윷가락 접는 법 네 줄이 들어오면서 240에서는 둘째 단이 넘쳤다. 폭 190은
  그대로라 인쇄 여백 10mm까지 A4 한 장인 것도 그대로다(폭이 한계다).
- **덩어리는 단을 넘어가지 않는다.** 절 제목은 첫 항목과 붙어 다닌다 — 제목만
  단 끝에 남으면 그 아래가 무엇에 대한 규칙인지 알 수 없다.
- 글이 늘어 넘치면 도안 테스트가 잡는다. **넘치면 글자를 줄이는 게 아니라 글을
  줄인다**(축구 게임판의 옛 규칙 카드와 같은 규약).

### 백도는 선택 규칙으로 적는다

윷가락 하나의 배에 과녁 표식이 있고 그 하나만 배로 나오면 뒤로 한 칸이다. 표식은
§7의 넉 장 가운데 한 장에만 인쇄된다. 다만 **안 쓰는 고장이 많아** "빼고 놀아도
놀이는 그대로 된다"고 적는다.

## 7. 윷가락 — 던져서 구르는 물건 (IDE-018)

말판까지는 **인쇄물**이라 종이에 대고 재면 끝난다. 윷가락은 다르다 — 눈이 나오는
비율이 한쪽으로 쏠리거나, 가벼워서 튀거나, 모서리로 서 버리면 도안이 틀린 것인데
그건 그려 놓고는 알 수 없다. 그래서 이 절은 **종이 위에서 따질 수 있는 것과
던져 봐야 아는 것**을 갈라 적는다.

```
단면  배 16 · 등 8mm씩 · 높이 6.93mm (= √3/4 × 16)
길이  110mm
전개도 한 벌  110 × 61mm + 양 끝 마구리·탭 (좌우 12.5mm씩)
시트  194 × 281mm — 넉 장을 눕혀 넉 줄, 오른쪽에 도해 넉 컷
```

### 반원기둥이 아니라 반육각기둥이다

실제 윷은 통나무를 반으로 쪼갠 반원기둥이라 평평한 배와 둥근 등이 있다. 종이로
곡면을 감으면 눌리고, 접는 선이 전부 직선이어야 자 없이 손톱으로 접힌다. 그래서
**정육각형을 가로로 자른 아래 절반**으로 근사한다(2026-09-08 결정) — 배 한 면과
등 세 면이고, `배 = 등면 × 2`가 곧 "반으로 쪼갰다"는 뜻이다. 도안 테스트가 이
관계와 높이 `(√3/4)·배`를 지킨다.

실물과 다른 것은 등이 세 면으로 각졌다는 것뿐인데, **그 각이 오히려 굴러 멈추는
자리를 안정시킨다**(아래 "모서리로 서지 않는다").

### 띠 일곱이 한 방향으로 감기는 나선

```
등1 → 등2(마루) → 등3 → 배 │ 속대 → 속대 → 갈고리
└──── 관 바깥 (인쇄면이 밖) ┘ └── 그대로 안으로 들어간다 ──┘
```

바깥 넷이 단면의 둘레이고, 배에서 모서리를 한 번 더 돌면 종이가 **안으로** 들어가
속대가 된다. 나선이라 **접는 방향이 여섯 줄 모두 같다** — "전부 같은 쪽으로 만다"
한 줄로 설명이 끝나는 것이 이 차례를 고른 이유다(골대가 "전부 골접기"였던 것과
같은 판단).

이음매는 **배–등1 모서리**다. 등1의 자유변이 거기서 맞대어지고 속대가 그 밑을
가로지르므로, 이음매를 종이 한 장이 이어 준다.

### 속대는 강성이 아니라 무게중심 때문에 있다

종이 한 겹짜리 관은 가벼워 튀고 쥐면 찌그러진다 — 골대 뚜껑을 두 겹으로 되돌린
것과 같은 지적이다. 윷가락에는 하나가 더 걸린다.

**겹을 배에 넣으면 무게중심이 내려가 배를 깔고 눕기만 한다.** 배는 이 단면에서
가장 넓은 면이라 그러잖아도 배로 눕기 쉬운데, 거기에 무게까지 실으면 배가 위로
오는 일이 드물어져 놀이가 늘어진다. 그래서 속대를 **등 쪽에** 넣었다.

| 어디까지 세었나         | 배 면에서 잰 무게중심 |
| ----------------------- | --------------------- |
| 관 바깥면만 (속대 없이) | 2.77mm (높이의 0.40)  |
| 속대까지 (지금 도안)    | 3.57mm (높이의 0.52)  |

종이는 속이 빈 껍데기라 무게가 면을 따라 붙는다. 띠 폭을 그 띠가 놓이는 자리에
얹어 평균한 값이고, 셈은 `stickBalance()`에 있다.

갈고리는 속대 끝이 **등3 모서리를 하나 더 넘는** 5mm다. 넘어간 종이는 120°로 꺾여
있어 빼내려면 펴야 하므로, 풀 없이도 속대가 관 안에 갇힌다.

### 잠금 셋 — 풀도 칼도 쓰지 않는다

골대와 같이 이름이 아니라 **번호**로 부른다. 좁은 면(마구리는 폭 6.5mm)에도 크게
넣을 수 있고, 사슬처럼 물리는 구조에서는 "무엇이 무엇을 먼저 무는가"가 이름보다
먼저 읽혀야 하기 때문이다.

| 번호 | 이름   | 하는 일                                                      |
| ---- | ------ | ------------------------------------------------------------ |
| 1    | 속대   | 이음매를 안에서 받치고, 갈고리로 모서리를 넘어 스스로 갇힌다 |
| 2    | 마구리 | 관 끝에서 단면을 붙들어 이음매가 밀려나지 못하게 한다        |
| 3    | 탭     | 마구리 위에서 꺾여 **속대 밑으로** 들어가 마구리를 붙든다    |

마구리는 배 띠 끝에 붙은 사다리꼴이고, 빗변 기울기가 단면의 빗면과 같아 세우면
등1·등3 안쪽에 딱 맞는다. 윗변은 마루(8mm)보다 조금 넓은 8.46mm인데, **마루보다
낮은 자리에서 자른 단면**이라 그렇다 — 마루와 같게 두면 헐거워 관이 찌그러진다.
높이를 단면보다 `capClearanceMm`(0.4mm) 낮춘 것은 그 자리에 속대가 한 겹 깔려
있기 때문이다.

**홈이 없다.** 골대는 뚜껑 귀·모서리 탭·옆벽이 전개도에서 위아래로 맞닿아 홈을
넷 파야 했는데, 여기 마구리는 배 띠의 끝에만 붙어 이웃 띠와 **꼭짓점 하나로만**
만난다 — 접을 때 서로를 잡아당길 변이 아예 없다. 도안 테스트가 띠 블록 밖의 윤곽점
y가 모두 배 띠 안쪽인지로 확인한다.

접는선은 열 줄이다. **산접기 여덟**(띠 사이 여섯 + 마구리 밑동 둘)에 **골접기
둘** — 탭 밑동만 반대로 접는다. 탭은 마구리의 인쇄면 쪽으로 꺾여 축을 따라
들어가야 속대 밑으로 들어가기 때문에 방향을 고를 수 없다.

### 배·등 인쇄 — 배는 민짜, 등에는 결

쪼갠 통나무의 겉이 등이고 쪼갠 자리가 배다. 그 대비를 그대로 옮겨 **등 세 면에만
나뭇결을 치고 배는 비워 둔다** — 접기 전에는 어느 띠가 배인지, 접고 나서는 어느
면이 위인지가 이것으로 갈린다. 결은 한 줄로 잇지 않고 **끊어 그린다**. 이으면
자로 그은 괘선이 되어 접는선과 헷갈리고 종이가 노트처럼 보인다.

배 면의 `배` 글자는 양 끝에 하나씩이고 **한쪽은 180° 돌려** 둔다. 상에 놓인
가락은 마주 앉은 사람에게 거꾸로 보이므로, 두 방향을 다 두어야 누구나 읽는다.

### 백도 가락

넷 중 한 장의 **배 면**에만 표식이 있다. 백도는 "그 가락만 배로 나왔을 때"라
표식은 배가 위로 왔을 때 보여야 한다.

**과녁(겹동그라미)**으로 그렸다. 던진 가락은 좌우가 뒤집혀 떨어지므로 방향이 있는
그림은 절반이 거꾸로 읽히는데, 과녁은 어느 쪽으로 누워도 같은 모양이다. `백도`
글자는 배 글자와 마찬가지로 양 끝에 하나씩, 한쪽을 돌려 넣는다. **색을 쓰지
않는다** — 흑백으로 뽑아도 나머지 셋과 갈려야 한다(`IDE-009` 규약).

### 넉 장을 눕혀 넉 줄로

속대가 붙으면서 전개도 폭이 40mm에서 **61mm**로 늘었다. 네 벌을 세워 나란히
늘어놓으면 244mm라 A4 폭을 넘는다. 눕히면 한 벌이 110mm뿐이라 **오른쪽에 도해를
놓을 단**이 남는다 — 골대가 전개도 아래에 도해를 깐 것과 같은 자리 배분이다.

194×281은 **인쇄 여백 8mm까지 한 장을 지키는** 크기다(골대 시트와 같은 기준).
인쇄 여백은 사용자가 고르는 값이라 A4 그대로 잡으면 여백을 조금만 줘도 두 장으로
쪼개지는데, **조립물이 두 장으로 쪼개지면 이어 붙인 자리에서 전개도가 어긋난다.**

배율도 좁게 열어 둔다(0.9~1.3). 던져서 구르는 물건이라 **배율이 곧 놀이의
성질**이기 때문이다 — 100%가 원칙이고, 종이가 얇아 자꾸 튀면 조금 키워 무게를
벌라고 위쪽만 열었다.

### 던져 봐야 아는 것 — 종이 위에서는 어디까지 따졌나

`stickBalance()`는 **던져 보는 것을 대신하지 않는다.** 튐·구름·손버릇이 다 빠진
정적 모형이고, 하는 일은 하나다 — 치수를 고쳤을 때 누가 봐도 한쪽으로 쏠리는
단면을 도안 테스트가 미리 잡아 주는 것.

무게중심에서 각 면의 양 끝을 본 각을 센다. 넷을 더하면 360°이고, 넓은 각을 가진
면으로 눕기 쉽다 — 주사위의 공평함을 재는 것과 같은 어림이다.

| 눕는 면        | 각도  | 무엇이 위로 오나 |
| -------------- | ----- | ---------------- |
| 배 (가장 넓다) | 132°  | 등               |
| 마루 (등2)     | 100°  | **배**           |
| 빗면 등1 · 등3 | 64°씩 | 마루로 넘어간다  |

**모서리로 서지 않는다.** 빗면에 얹히기는 하지만 무게중심이 빗면 위에서 마루 쪽
끝에서 0.9mm밖에 안 떨어진 자리에 내려앉아, 조금만 흔들려도 마루로 넘어간다.
넘어가면 배가 위다.

그 빗면의 몫이 실제로 얼마나 넘어오는지는 던져 봐야 아므로 **한 값이 아니라
구간**을 낸다 — 하나도 안 넘어오면 배가 **0.28**, 다 넘어오면 **0.63**이고 실제는
그 사이다. 지금 단면은 이 구간이 0.5를 품는다. 종이 위에서 확인할 수 있는 것은
거기까지이고, **40~60%인지는 100번 던져야 정해진다.**

**고칠 나사는 `bellyMm` 하나다.** 배가 넓을수록 배를 깔고 눕기 쉬우므로 배가
위로 오는 비율이 떨어진다 — 배가 덜 나오면 줄이고, 지나치게 나오면 늘린다. 등면
폭은 고정이고 높이와 기울기가 두 값에서 따라 나오므로, 이 값 하나만 고치면
전개도·마구리·무게중심 셈이 모두 따라온다. 다만 `배 = 등면 × 2`가 깨지면 더는
"반으로 쪼갠 윷"이 아니므로 그때는 이 문서의 근거도 함께 고쳐야 한다.

튐은 다른 나사다. 종이 윷은 가벼워 맨 상에서 튀므로 **담요나 방석을 깔고 던지라고
규칙문이 이른다** — 전통 윷도 멍석 위에 던졌다. 그래도 모자라면 배율을 조금
키우거나 길이를 줄인다.

## 8. 이 게임이 규격에서 확인한 것

| 확인한 것                                | 결과                                                               |
| ---------------------------------------- | ------------------------------------------------------------------ |
| 정사각 보드                              | `landscape`로 선언해 통과. 스키마 변경 없음                        |
| 마커·프리셋·스타일 세트가 모두 없는 게임 | 에디터가 옵션 줄을 통째로 비우고 미리보기·파트 선택은 남는다       |
| 보드 파트에 슬롯이 하나도 없는 경우      | `slotsAffectingPart`가 빈 배열. 폼이 아무것도 그리지 않는다        |
| 갈라지는 경로                            | 도안 데이터에 그래프를 두고 규칙문의 칸 수를 테스트가 맞춰 본다    |

| 한 게임에 조립물이 둘                    | `buildable` 파트 둘(말·윷가락). 스키마 변경 없음                   |
| 산접기와 골접기를 같이 쓰는 부속         | 골대에 이어 둘째다. 방향이 반대인 선은 층을 따로 둔다              |
| 던져서 구르는 부속                       | 치수가 곧 놀이의 성질이라 배율 범위를 0.9~1.3으로 좁혔다           |
