# 윷놀이 도안

`IDE-017`의 작도 결과다. 치수의 **원본은 코드**
(`src/assets/games/yut-nori/dimensions.ts`)이고 이 문서는 왜 그 값이 되었는지를
적는다. 둘이 어긋나면 코드가 맞다.

인쇄 규격은 [`print-spec.md`](print-spec.md), 도안 데이터 모델은
[`game-authoring.md`](game-authoring.md)를 따른다. 앞선 게임들과 겹치는 규약
(레이어 id·표시선·텐트형 부속)은 [`soccer-artwork.md`](soccer-artwork.md)와
[`baseball-artwork.md`](baseball-artwork.md)에 먼저 적혀 있다.

---

## 1. 만드는 법

```
src/assets/games/yut-nori/
  dimensions.ts      ← 모든 실측 치수와 29밭 그래프. 고칠 곳은 여기 하나다
  rules.ts           ← 게임 방법 텍스트
  artwork/
    board.ts         ← 말판 198×198
    tokens.ts        ← 말 — 4편 × 넷, 텐트형
    rules-sheet.ts   ← 게임 방법 부속 (규칙문을 두 단으로 조판)
  index.ts           ← 도안 정의
public/games/yut-nori/*.svg   ← 산출물. 커밋한다
```

```bash
npm run artwork yut-nori   # 이 게임의 SVG만 다시 만든다
npm run test:run           # 커밋된 SVG가 생성기와 같은지까지 본다
```

좌표는 **격자에서 계산해 뽑는다.** 밭 스물아홉의 자리를 손으로 적은 곳이 한
군데도 없고, 도안 테스트가 그것을 **판 중심에 대한 180° 회전 대칭**으로
확인한다 — 어느 한 밭이라도 손으로 밀어 두면 그 검사가 깨진다.

## 2. 판이 정사각이다

| 게임     | 보드 치수 | `orientation` |
| -------- | --------- | ------------- |
| 축구     | 285×198   | `landscape`   |
| 야구     | 210×297   | `portrait`    |
| 세계일주 | 297×210   | `landscape`   |
| 윷놀이   | 198×198   | `landscape`   |

파트 검증은 `widthMm >= heightMm`를 가로로 읽는다
(`src/lib/schema/parts.ts`). **정사각 보드는 그래서 `landscape`로 선언해야
통과한다.** 규칙이 이미 그렇게 정해져 있었고 이 게임이 처음 밟았다 — 스키마는
한 줄도 고치지 않았다.

한 변 198mm인 것은 두 가지 때문이다.

- A4 세로(210×297)의 **폭 안에** 들어간다. 배율 100%에서 한 장이다.
- 축구 운동장의 짧은 변(198)과 **같다.** 두 게임을 100%로 뽑으면 밭·선이 같은
  굵기로 읽힌다.

정사각이 카탈로그에서 줄을 늘리지 않는 것은 카드가 도안 비율이 아니라 **A4
가로 크기의 자리를 늘 같게 잡고** 그 안에 그림을 통째로 담기 때문이다
(`object-contain`, `IDE-011` 2026-09-08 결정). 랜딩 히어로는 그림의 실제
비율을 그대로 쓰므로 정사각이면 정사각으로 앉는다.

## 3. 밭 스물아홉

**5칸 × 5칸이 아니라 6점 × 6점이다.** 바깥은 각 변에 여섯 점씩, 모서리를
공유해 `6 × 4 − 4 = 20`밭. 대각선은 네 모서리에서 방(가운데)까지 두 밭씩
여덟에 방 하나를 더해 아홉. 합쳐 **29밭**이 전통 윷판의 수다.

```
격자 여백 19mm · 한 칸 32mm (= (198 − 19×2) / 5)
큰 밭 지름 30mm (네 모서리와 방)
작은 밭 지름 22mm (나머지 스물넷)
```

- **32mm 간격**은 큰 밭과 작은 밭이 이웃해도 6mm가 남는 값이다. 밭이 서로
  닿으면 말을 어느 밭에 세운 것인지 다투게 된다. 도안 테스트가 모든 쌍의
  간격이 1mm를 넘는지 본다.
- **여백 19mm**는 모서리 큰 밭(반지름 15)에서 종이 끝까지 4mm를 남긴다.
  가정용 프린터의 인쇄 불가 영역(보통 3mm대)을 넘긴다.
- **작은 밭 지름 22mm**가 말 카드 폭(20mm)의 상한을 정한다. 말이 밭보다 넓으면
  이웃 밭을 가린다.

### 큰 밭이 규칙을 말한다

전통 윷판이 네 모서리와 방을 크게 그린다. **지름길이 갈라지고 만나는 자리가
곧 큰 밭**이라, 밭 이름을 적지 않는 이 도안에서 크기가 규칙의 유일한 안내다.
큰 밭은 겹원으로 그려 멀리서도 갈림길이 보인다.

### 밭 이름을 적지 않는다

전통 윷판에 이름이 없다. 도·개·걸은 **윷가락이 내는 값**이지 밭 이름이 아니고,
밭 이름(참먹이·쨀밭·날밭…)은 지역마다 달라 하나를 고르면 틀린 쪽이 생긴다.
판에 적는 글자는 출발점의 `출발`·`도착` 둘뿐이고, 그마저 큰 밭 **안**에 넣었다
— 판 가장자리에는 자리가 없고(4mm다) 밭 밖 안쪽은 이웃 밭과 대각선이 이미
차지했다.

규칙을 설명하려면 자리를 가리킬 말이 있어야 하므로, **게임 방법 부속에서는**
"오른쪽 위 큰 밭"처럼 위치로 부르고 전통 이름을 괄호에 넣는다.

### 바깥 밭에는 잇는 선이 없다

전통이 그렇고, 그 덕에 **판에서 선으로 보이는 것은 대각선 넷뿐**이다. 지름길이
어디서 갈라지는지가 그림만 보고 읽힌다. 바깥까지 선으로 이으면 판이 선
무더기가 되어 그 대비가 사라진다. 진행 방향은 각 변 한가운데, 밭과 밭 사이
빈자리에 앉는 작은 세모가 말한다.

대각선은 밭 **아래**에 깔린다 — 밭 원을 흰색으로 채워 선이 밭 안을 가로지르지
않는다.

## 4. 경로가 갈라진다 — 한 줄이 아니라 그래프

세계일주(`IDE-015`)의 경로는 서울에서 서울로 이어지는 **순환 목록**이었다.
윷판은 모서리에서 갈라져 방을 지나 나오므로 목록으로 적을 수 없다. 밭마다
나가는 간선이 있고, 갈라지는 자리에서는 둘이다.

| `EdgeKind` | 언제 쓰나                                |
| ---------- | ---------------------------------------- |
| `next`     | 늘 쓰는 기본 진행. 밭마다 하나씩 있다    |
| `shortcut` | 모서리 밭에 **정확히 멈췄을 때만**       |
| `through`  | 방을 **지나칠 뿐일 때** 곧게 건너가는 길 |

"정확히 멈췄는가"는 놀이하는 사람이 판단하고 **도안은 길만 그린다.**

### 네 갈래

바깥 밭은 `o0`(출발·도착, 오른쪽 아래) … `o19`이고 번호가 진행 차례다. 모서리는
`o0`·`o5`·`o10`·`o15`, 진행은 반시계다.

| 경로                          | 밟는 칸 수 |
| ----------------------------- | ---------- |
| 바깥길만                      | 20         |
| `o5`에서 지름길 → 방에 멈춤   | **11**     |
| `o5`에서 지름길 → 방을 지나침 | 16         |
| `o10`에서 지름길 → 방에 멈춤  | 16         |

- **방에 멈추면** 참먹이 쪽 대각선으로 질러 나온다. 이것이 가장 짧은 길(11칸)
  이고, 윷놀이의 승부가 여기서 갈린다.
- **방을 지나칠 뿐이면** 들어온 대각선을 곧게 건너 반대편 모서리로 나간다.
- **왼쪽 아래 모서리(`o15`)에는 지름길이 없다.** 그 대각선은 방에서 _나오는_
  길이라, 거기로 들어가면 방까지 3칸 + 방에서 참먹이까지 3칸 = 6칸으로 바깥길
  5칸보다 오히려 길다. 전통 윷판이 그 모서리를 입구로 삼지 않는 이유가 그것이다.

네 경로를 합치면 **29밭이 빠짐없이** 나온다. 어느 경로에도 없는 밭이 있으면 그
밭은 판에 그려져 있으면서 갈 수 없는 자리다 — 지름길이 두 갈래로 나뉘어 있어
눈으로는 잘 안 보이므로 도안 테스트가 본다. 규칙문이 적은 11칸·20칸도 같은
테스트가 실제 경로와 맞춰 본다.

## 5. 말 — 텐트형 카드 열여섯

4편 × 넷이다. 카드 한가운데를 산접기로 접으면 두 면이 마주 보며 ∧ 로 선다
(야구 선수 스탠드와 같은 수법, `IDE-014`). 풀도 칼도 탭도 없다.

```
카드 20 × 52mm (한 면 26mm) · 격자 4열 × 4행 (한 줄이 한 편) · 시트 112 × 252mm
접는선에서: 그림 8mm · 색 띠 14.9mm · 편 이름 18.5mm · 업기 숫자 23mm
```

세계일주의 말은 **눕혀 쓰는 원판**이었다(칸 지름 6.6mm에 세운 말이 이웃 칸을
가렸다). 윷판은 밭이 지름 22mm로 넓어 세워도 되고, **세운 말이라야 업힌 수가
옆에서 보인다.**

시트가 A4를 채우지 않는 것은 카드가 커질 수 없기 때문이다 — 밭 지름이 상한이다.
늘리면 남는 것은 빈 종이뿐이라 종이를 아끼는 쪽을 골랐다.

### 편을 가르는 것 — 색과 그림 양쪽

색만으로 가르면 흑백 출력에서 누구 말인지 알 수 없다(`IDE-009`가 축구 팀
색에서 확인한 것). 그림(동그라미·세모·네모·별)은 **고정**이다 — 고를 수 있게
하면 두 편이 같은 그림을 고를 수 있다. 색은 레이어 `pc-side-<n>`이 받고
사용자가 고친다.

### 업은 말을 세는 법

같은 편 말이 한 밭에서 만나면 업어 한 몸이 되는데, 텐트형 말을 그냥 포개면
옆에서 몇이 업혔는지 보이지 않는다. 그래서 말 넷 가운데 **셋의 밑동에
`2`·`3`·`4`를 적어 두고, 업으면 그 수의 말 하나로 바꿔 세운다.** 말이 따로
서 있을 때는 숫자를 보지 않는다 — 어느 말이든 한 마리다.

실물로 놀아 봐야 정해지는 자리라 이슈(`IDE-017`)에 미완으로 남겼다.

### 위쪽 면을 돌려 그린다

접으면 위쪽 면이 뒤로 넘어가 뒤집히므로 미리 180° 돌려 그려야 세웠을 때
양쪽에서 다 바로 보인다. 야구 스탠드는 그림만 돌리고 이름표는 앞면에만
넣었는데, 윷놀이의 **업기 숫자는 어느 쪽에서 보든 읽혀야 하는 값**이라 글자도
돌린다(`transform="rotate(180 …)"`). 편 이름은 슬롯이라 배치의 `rotationDeg`가
돌린다.

> **인쇄 렌더러를 한 줄 고쳤다.** SVG 파서가 글자의 자리를 평행이동·배율로만
> 계산해, 회전이 걸린 글자가 대칭점이 아니라 원래 자리에 남았다
> (`src/lib/print/artwork.ts`). 화면은 브라우저가 SVG를 그대로 그려 맞고
> PDF만 틀리는 종류의 결함이라 눈에 띄지 않는다. 회전한 정적 글자를 쓴 도안이
> 이 게임이 처음이라 여태 드러나지 않았다.

## 6. 게임 방법 부속

규칙의 **진짜 자리는 도안 정의의 `rules` 필드**이고 소개 페이지가 그것을
그린다. 이 시트는 같은 값을 종이로 낸 것이라, 규칙을 인쇄 파트에 매지 않는다는
결정(2026-09-05)과 어긋나지 않는다 — [`game-authoring.md`](game-authoring.md)가
"규칙 카드를 원하는 게임은 이 값을 읽어 부속을 그리면 된다"고 적어 둔 자리다.

윷놀이가 그것을 원하는 이유는 **규칙이 길고 놀면서 자꾸 되짚기 때문**이다.
지름길이 열리는 조건, 업은 말을 세는 법, 백도를 쓸지가 다 적혀야 형제끼리
싸우지 않는다.

```
시트 190 × 240mm · 두 단 79mm씩 · 본문 2.9mm / 줄 간격 4.2mm
```

- **두 단인 이유** — 한 단으로 흘리면 A4를 넘긴다. 두 단이면 줄 길이도 79mm로
  짧아져 눈이 줄을 놓치지 않는다.
- **높이 240mm는 두 단이 고르게 차는 값**이다. 더 길면 첫 단만 꽉 차고 둘째
  단 아래가 비고, 더 짧으면 둘째 단이 넘친다.
- **덩어리는 단을 넘어가지 않는다.** 절 제목은 첫 항목과 붙어 다닌다 — 제목만
  단 끝에 남으면 그 아래가 무엇에 대한 규칙인지 알 수 없다.
- 글이 늘어 넘치면 도안 테스트가 잡는다. **넘치면 글자를 줄이는 게 아니라 글을
  줄인다**(축구 게임판의 옛 규칙 카드와 같은 규약).

### 백도는 선택 규칙으로 적는다

윷가락 하나에 표식이 있고 그 하나만 배로 나오면 뒤로 한 칸이다. 표식은
`IDE-018`(종이 윷가락)이 그 가락에 인쇄한다. 다만 **안 쓰는 고장이 많아** "빼고
놀아도 놀이는 그대로 된다"고 적는다.

## 7. 이 게임이 규격에서 확인한 것

| 확인한 것                                | 결과                                                               |
| ---------------------------------------- | ------------------------------------------------------------------ |
| 정사각 보드                              | `landscape`로 선언해 통과. 스키마 변경 없음                        |
| 마커·프리셋·스타일 세트가 모두 없는 게임 | 에디터가 옵션 줄을 통째로 비우고 미리보기·파트 선택은 남는다       |
| 보드 파트에 슬롯이 하나도 없는 경우      | `slotsAffectingPart`가 빈 배열. 폼이 아무것도 그리지 않는다        |
| 갈라지는 경로                            | 도안 데이터에 그래프를 두고 규칙문의 칸 수를 테스트가 맞춰 본다    |
| 규칙문을 인쇄 부속으로 조판              | `rules` 필드를 읽어 그린다. 규칙은 여전히 파트에 매이지 않는다     |
| 회전한 정적 글자                         | 인쇄 렌더러의 좌표 계산 결함을 드러냄. 고치고 회귀 테스트를 남겼다 |
