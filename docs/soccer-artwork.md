# 축구 게임판 도안

`IDE-004`(필드·부속·골대)와 `IDE-010`(선수 마커·전술 대형)의 작도 결과다. 치수의
**원본은 코드**(`src/assets/games/soccer/dimensions.ts`)이고 이 문서는 왜 그
값이 되었는지를 적는다. 둘이 어긋나면 코드가 맞다.

인쇄 규격은 [`print-spec.md`](print-spec.md), 도안 데이터 모델은
[`game-authoring.md`](game-authoring.md)를 따른다.

---

## 1. 만드는 법

도안 SVG는 **손으로 쓰지 않고 코드가 만든다.** 슬롯 좌표(도안 정의)와 그림(SVG)이
같은 치수 상수를 읽어야 어긋나지 않기 때문이다.

```
src/assets/games/soccer/
  dimensions.ts      ← 모든 실측 치수. 고칠 곳은 여기 하나다
  rules.ts           ← 게임 방법 텍스트
  artwork/           ← 파트별 SVG 생성기
  index.ts           ← 도안 정의 (dimensions.ts를 읽는다)
public/games/soccer/*.svg   ← 산출물. 커밋한다
```

```bash
npm run artwork     # SVG를 다시 만든다
npm run test:run    # 커밋된 SVG가 생성기와 같은지, 기하가 맞는지 검사
```

산출물이 낡으면 테스트가 어느 파일인지 알려 준다.

## 2. 파트와 치수

| 파트           | 종류        | 크기(mm)    | 배율 범위 | 표시                 |
| -------------- | ----------- | ----------- | --------- | -------------------- |
| `field`        | `board`     | 297 × 210   | 0.5–4     | 없음                 |
| `score-sheet`  | `cutout`    | 210 × 148.5 | 0.7–2     | 오림선               |
| `rules-card`   | `cutout`    | 148.5 × 210 | 0.85–2    | 오림선               |
| `goals`        | `buildable` | 210 × 148.5 | 0.8–2     | 오림선·산접기·풀칠면 |
| `ball-markers` | `cutout`    | 105 × 85    | 0.8–2     | 오림선               |

`goals`와 `ball-markers`는 **같은 배율로 뽑아야 한다.** 골대 입구와 공의 크기
관계가 게임의 성립 조건이라, 한쪽만 줄이면 공이 안 들어가거나 너무 헐거워진다.
그래서 두 파트의 배율 범위를 같게 두었다(테스트가 검사한다).

## 3. 운동장

- 종이 297×210mm 안에서 **터치라인 사각형은 285×198mm**, 원점 (6, 6)
- 가로세로비 1.439 — 실제 축구장 100×69.5m에 해당한다. 국제 규정 범위
  (길이 90–120m · 폭 45–90m) 안이면서 종이를 가장 꽉 채우는 비율이다
- **사방 6mm 여백뿐이다.** 재단 오차에도 라인이 잘리지 않을 만큼만 남긴다
- 필드 안 표시는 실제 치수를 약 2.85mm/m로 줄이되 좌표가 소수로 흩어지지 않게
  정수로 맞췄다: 센터서클 r26 · 페널티 에어리어 47×115 · 페널티 스팟 31 ·
  코너 아크 r3
- **골 에어리어만 실제보다 크다(32×80).** 골키퍼 마커가 그 안에 서야 하기
  때문이다 — 아래 참고

### 운동장에는 글자를 두지 않는다 (2026-09-05)

처음에는 위아래 15mm를 띠로 떼어 팀 이름 두 개와 팀 색 막대(위), 제목과 배율
안내(아래)를 넣었다. 그 30mm가 **놀 면을 좁히고 있었다** — 사용자 요청으로 전부
뺐고, 터치라인이 281×180에서 285×198로 12% 넓어졌다.

뺀 것들이 어디로 갔는지:

| 뺀 것            | 지금 있는 곳                                               |
| ---------------- | ---------------------------------------------------------- |
| 팀 이름 · 팀 색  | 점수 기록칸(`score-sheet`). 팀 색은 선수 마커에도 칠해진다 |
| 제목 · 배율 안내 | 인쇄물 하단 표식 띠 — 장마다 찍힌다(`IDE-007`)             |

어느 팀이 어느 쪽인지는 마커 색과 **화살표 방향**이 말해 준다(11절).

### 골 에어리어는 골키퍼가 들어갈 만큼 깊다

골키퍼는 **골대를 세운 뒤 그 앞에** 선다. 종이 골대가 골라인 안쪽으로 16mm를
차지하므로, 골키퍼 마커(폭 13mm)가 골 에어리어를 벗어나지 않으려면 깊이가 최소
16 + 13 = 29mm여야 한다. 실제 축구의 5.5m(≈16mm)로는 골키퍼가 자기 구역 밖에
서게 된다.

그래서 깊이 32mm로 잡았다(실제 11.2m). 폭도 80mm로 맞춰 페널티 에어리어와
비슷한 인상(1:2.5)을 남긴다. `__tests__/formations.test.ts`가 "골키퍼가 골
에어리어 안에 온전히 들어가는가"를 지킨다.

**필드를 초록으로 칠하지 않는다.** 잉크를 크게 먹고, 공이 미끄러지는 면이라
잉크가 두꺼우면 연필 자국이 더 남는다. 사용자가 만든 판처럼 라인만 초록이다
(#2f7d32 — 흑백으로 뽑아도 회색 선으로 남는다).

## 4. 골대 — 왜 이 구조인가

```
       ┌──────┐          지붕 40×16 (+ 좌우 풀칠탭 6mm)
  ┌────┼──────┼────┐     옆벽 16×14 · 뒷벽 40×14 · 옆벽 16×14
  └────┘      └────┘     발 16×8 둘
```

전개도 한 벌 72×38mm. 접으면 **입구 40×14mm, 깊이 16mm**의 터널이 선다.

세 가지가 이 형태를 강제했다:

1. **바닥이 없다.** 공이 종이 위를 미끄러져 들어오는데 바닥을 깔면 종이 두께만큼
   턱이 생겨 입구에서 걸린다. 대신 옆벽 아래 발을 **바깥으로** 눕혀 세운다 —
   안쪽으로 접으면 같은 턱이 생긴다.
2. **골라인 안쪽에 세운다.** 골라인 바깥 여백은 8mm뿐이라 뒤로 나갈 자리가 없다.
   종이 밖 책상 위에 두면 종이 가장자리 턱을 공이 넘어야 한다. 그래서 골대 깊이
   (16mm)를 골 에어리어 깊이(20mm) 안에 들어가게 잡고, 운동장에 파선으로 자리를
   표시했다.
3. **접는선은 전부 산접기다.** 인쇄면이 골대 바깥을 향해야 하고, 지붕 탭도 아래로
   접혀 벽 안쪽에 붙으므로 인쇄면이 바깥을 본다. 골접기(`fold-valley`)를 쓰는
   자리가 없어 파트의 `marks`에서 뺐다.

조립이 성립하는지는 테스트가 기하로 확인한다 — 지붕 깊이 = 옆벽 깊이, 지붕 폭 =
뒷벽 폭, 세 벽의 높이가 같음, 발 깊이 = 옆벽 깊이, 풀칠탭 ≤ 벽 높이, 면끼리 겹치지
않음. **⚠︎ 실제로 오려 접어 보는 것은 남아 있다.**

## 5. 공

- **지름 12mm**, 한 시트에 24개(6×4, 중심 간격 16mm)
- 골대 입구 폭 40mm의 **3분의 1 이하** — "뚜렷이 작게"를 테스트가 강제한다
  (`지름 × 2 < 입구 폭`)
- 입구 높이 14mm보다도 작아 납작한 종이 공이 미끄러져 들어간다
- 12mm는 **가위로 오릴 수 있는 하한**과 **골대에 들어갈 상한** 사이에서 잡았다.
  ⚠︎ 연필로 튕기는 맛은 종이에 뽑아 봐야 안다

24개는 잃어버리거나 찢어질 때를 위한 여분이다. `defaultCopies`가 2라 기본으로
48개가 나온다.

## 6. 가독성 최소 배율

기준을 이렇게 정했다 — **그 파트를 쓰는 데 꼭 읽혀야 하는 글자가 종이 위에서
2.5mm 이상**. 2.5mm는 가정용 프린터에서 한글이 뭉개지지 않는 하한으로 잡은 값이다.

| 파트           | 필수 글자            | 크기  | minScale | 그 배율에서 |
| -------------- | -------------------- | ----- | -------- | ----------- |
| `field`        | 등번호               | 5mm   | 0.5      | 2.5mm       |
| `score-sheet`  | 판 번호              | 3.6mm | 0.7      | 2.52mm      |
| `rules-card`   | 규칙 본문            | 3mm   | 0.85     | 2.55mm      |
| `goals`        | 조립 안내            | 3.2mm | 0.8      | 2.56mm      |
| `ball-markers` | (글자에 기대지 않음) | —     | 0.8      | 골대와 맞춤 |

부차적인 글자(운동장의 "골대" 라벨 3mm, 골대 면 이름 2.6mm, 시트 부제 2.6mm)는
최소 배율에서 2.5mm 아래로 내려간다. 그것들 없이도 도안을 쓸 수 있어 하한을
정하는 데 넣지 않았다.

> **⚠︎ 이 표는 디지털 기준이다.** 2.5mm라는 하한 자체를 종이로 확인하지 못했다
> (이 환경에 프린터가 없다 — `IDE-002`와 같은 사유). 실측하면 값이 바뀔 수 있고,
> 바뀌면 `dimensions.ts`가 아니라 각 파트의 `minScale`을 고친다.

## 7. 용지

운동장은 공을 반복해서 튕기고 미끄러뜨리는 면이다. 게임 방법 카드와 파트 설명에
**120g/m² 이상**을 권한다. ⚠︎ 일반 복사용지(80g/m²)가 실제로 얼마나 빨리 해지는지는
실물로 확인하지 못했다 — 권장값은 안전한 쪽으로 잡은 것이다.

## 8. 게임 방법 텍스트

`src/assets/games/soccer/rules.ts`에 있다. **사용자가 확인한 규칙만** 규칙 절에
넣는다:

- 패스 시도는 한 턴에 최대 3번, 성공하면 3번으로 초기화
- 3번 안에 연결 못 하면 턴오버, 상대 선수에 닿으면 즉시 턴오버
- 슛은 공이 자기 팀 선수 위에 있을 때만, 패스 시도 중 전환 불가
- 점수 계산은 목표 점수제·시간제 **둘 다 선택지로** 안내(기본값 없음)
- 말미에 "기본 규칙이니 자유롭게 바꿔서 즐기세요"

아직 확인되지 않은 것(**공이 밖으로 나갔을 때 · 핸들링의 정확한 적용 조건 · 그 밖의
파울**)은 규칙으로 단정하지 않고 마지막 "시작 전에 정해 두면 좋은 것"에 넣었다.
확인이 오면 규칙 절로 올린다. 테스트가 이 경계를 지킨다.

## 9. 참고 자료와 저작권

작도의 바탕이 된 자료는 두 개다.

| 자료                        | 출처                                                                  | 저작권                   |
| --------------------------- | --------------------------------------------------------------------- | ------------------------ |
| ① 옛 인쇄본 게임판 스크린샷 | 사용자가 2026-09-03 대화에 첨부. **원 발행처·연도는 확인되지 않았다** | 불분명 — 복제하지 않는다 |
| ② 사용자가 만든 스케치북 판 | 사용자가 직접 그려 만든 판을 찍은 사진. 2026-09-03 대화에 첨부        | 사용자 본인의 것         |

두 자료 모두 저장소에 두지 않았다. ①은 권리가 불분명하고, ②는 사용자 개인의
사진이라 공개 저장소에 올릴 이유가 없다.

**②를 기준으로 삼았다** — 가로 방향, 원 + 등번호 마커, 종이로 접은 입체 골대.
①의 세로 구성은 따르지 않았다.

### 옛 인쇄본을 복제하지 않았음

- 필드 라인은 실제 축구 경기장 규격(FIFA 경기 규칙의 표준 치수)을 비례로 줄인
  것이다. 어느 인쇄본에서 옮긴 값이 아니다
- 프레임(점수 트랙·게임 방법)은 ①의 배치를 따르지 않고 별지 부속으로 분리했다
  (`IDE-002`가 정한 보드/부속 분리 규격을 따른 결과다)
- 게임 방법 문장은 사용자가 구술한 규칙을 옮겨 쓴 것이다
- **선수 일러스트(`IDE-010`)도 새로 그렸다.** ①을 참고하지 않았다 — 저장소에
  두지도 않았으니 옮겨 그릴 자료 자체가 없었다. 아래 11절의 픽토그램은 옛
  인쇄본의 인물 그림과 무관한, 이 도안만의 단순 도형이다

## 11. 선수 마커와 전술 대형 (`IDE-010`)

마커는 `src/assets/games/soccer/artwork/player-markers.ts`가 짓는다. 필드
선수·골키퍼가 스타일 세트를 따로 쓴다(`player-marker` · `goalkeeper-marker`) —
크기는 같고 실루엣만 다르다. 각 세트 안에서 원형·일러스트를 고르는 건
`marker-style` 슬롯 하나가 두 세트를 동시에 바꾼다.

### 흑백에서 팀·골키퍼가 구분되는 이유

팀 색은 사용자가 자유롭게 고르는 값이라(`hexColor`), 두 팀이 명도가 비슷한 색을
고르면 색만으로는 흑백에서 구분되지 않는다. 그래서 색에 기대지 않는 표식을
아트워크 자체에 박아 뒀다:

- **팀** — 마커 오른쪽에 작은 화살촉을 붙였다(공격 방향 표시). 원정 마커는
  이것을 세로 중심선 기준으로 **좌우 반전**해서 쓴다 — 대형 좌표를
  `mirrorPositions`로 뒤집는 것과 같은 이치다. 이 파일은 파일을 두 벌 만들지
  않고 **비대칭 도형 하나**만 낸다.
  반전은 도안이 `group.mirrorMarkers`로 선언하고 렌더러가 수행한다(2026-09-05
  구현) — 미리보기는 `transform="scale(-1,1)"`, 인쇄는 좌표를 뒤집는다
  (`src/lib/print/draw.ts`의 `mirrorDrawsX`). 등번호는 뒤집지 않는다.
  두 팀이 필드 전체에 섞여 서기 때문에 **위치로는 팀을 알 수 없고**, 이 화살촉이
  흑백에서 팀을 가르는 유일한 단서다.
- **골키퍼** — 원형은 안쪽에 테를 하나 더 둘러 과녁 모양을 만든다. 일러스트는
  장갑을 낀 손 모양을 더한다. 필드 선수와 다른 실루엣이라 색이 같아도 흑백에서
  구분된다. 팀 화살촉은 골키퍼 마커에도 똑같이 붙는다.

두 표식 다 `src/assets/games/soccer/__tests__/player-markers.test.ts`가 기하로
확인한다(비대칭인지, 골키퍼 원이 하나 더 있는지). **⚠︎ 실제 인쇄물에서 눈으로
구분되는지는 프린터가 없어 확인하지 못했다.**

팀 색을 받을 레이어 id는 `pc-marker-fill`이다. `pc-team-<그룹 id>`(보드·점수
기록칸이 쓰는 파트 레벨 규약)와 다른 새 규약이다 — 마커 아트워크는 `part`가
아니라 아직 검증기가 닿지 않는다. 렌더러를 만들 때(`IDE-006`) 이 id를 팀 색으로
채운다.

등번호는 마커 SVG에 그리지 않는다. 슬롯 값이라 렌더러가 `valueFontSizeMm`
크기로 얹는다. 두 스타일 세트 다 5mm로 맞췄다 — 필드의 `minScale`(0.5)에서
2.5mm 하한에 정확히 닿는다(여유 없음, 6절 참고).

### 전술 대형

4-4-2 · 3-5-2 · 4-3-3 · 4-2-3-1 네 개가 있다. 좌표는 `src/assets/games/soccer/index.ts`의
`FORMATIONS`에 있고, 배열의 첫 자리는 언제나 골키퍼다 — 슬롯 id(`home-player-1`
등)가 대형과 무관하게 고정이라, 어느 프리셋을 골라도 1번 슬롯이 골키퍼여야
어긋나지 않는다. 원정 진영은 `mirrorPositions`로 좌우 반전해 만든다.

#### 두 팀은 필드 전체에 섞여 선다 (2026-09-05 재작업)

처음에는 두 팀을 각자 진영 절반에 세웠다. 실제 축구의 킥오프 배치를 따른
것이었는데, **그 배치로는 경기를 할 수 없었다.**

선수 마커는 운동장에 인쇄되어 움직이지 않는다. 규칙은 패스가 자기 팀 선수에게
닿아야 이어지고, 슛도 공이 자기 팀 선수 위에 있을 때만 되게 되어 있다. 상대 골대
쪽에 자기 팀 선수가 하나도 없으면 공을 앞으로 보낼 방법이 없다 — 홈 팀 최전방이
x=130이고 상대 골대가 골라인 근처라, 슛을 하려면 한 번에 140mm 넘게 튕겨야 했다.

그래서 두 팀이 **번갈아 서도록** 다시 잡았다. x는 `FORMATION_LANES`의 다섯 값만
쓰고, 원정은 그것을 뒤집은 값을 쓴다:

```
홈    30    60           135         200 220
원정          77    97          162        237 267
```

- 레인 사이가 최소 17mm로 마커 폭(13mm)보다 넓다. **두 팀이 서로 다른 대형을
  골라도 마커가 부딪히지 않는 근거가 이것이다** — y를 어떻게 잡든 안전하므로
  대형을 늘릴 때 조합을 다시 따지지 않아도 된다.
- 홈 최전방(x=220)에서 상대 골대까지 55mm다. 슛이 성립하는 거리다.
- 골키퍼 x(30 · 267)는 골대 자리를 피하면서 **골 에어리어 안**이다(위 참고).
- **골키퍼를 뺀 10명이 운동장 1/3마다 둘 이상**이다. 한 구역에 몰리면 그 밖에서
  패스를 받아 줄 사람이 없어 공이 앞으로 나가지 못한다. 4-2-3-1의 공격형
  미드필더 레인(200)이 중원이 아니라 상대 진영에 있는 이유가 이것이다 —
  중원에 두면 상대 진영에 공격수 한 명만 남아 4-4-2(2명)·4-3-3(3명)보다
  앞이 헐거워진다.

| 대형    | 1/3마다 선수 수 |
| ------- | --------------- |
| 4-4-2   | 4 / 4 / 2       |
| 3-5-2   | 3 / 5 / 2       |
| 4-3-3   | 4 / 3 / 3       |
| 4-2-3-1 | 4 / 2 / 4       |

경기가 성립하는 조건은
[`__tests__/formations.test.ts`](../src/assets/games/soccer/__tests__/formations.test.ts)가
지킨다 — 각 팀이 상대 진영에 선수를 두는가, 최전방이 슛 사거리 안인가, 모든
대형이 정해진 레인만 쓰는가. 스키마 검증(`parseGame`)은 여기에 더해 **다른
그룹의 프리셋과도** 겹치지 않는지 본다.

## 12. 남은 실물 확인

프린터가 없어 채우지 못한 것들이다. `IDE-004`·`IDE-010`에 ⚠︎로 남아 있다.

- [ ] 100%로 뽑아 운동장이 297×210mm인지 자로 재기
- [ ] 골대 전개도를 오려 접어 실제로 세워지는지, 공이 입구로 들어가는지
- [ ] 공 12mm가 연필로 튕기기 적당한지 — 크거나 작으면 `BALL.diameterMm`을 고친다
- [ ] 일반 용지에서 필드 표면이 얼마나 버티는지
- [ ] 각 파트의 `minScale`에서 글자가 실제로 읽히는지
- [ ] 선수 마커를 흑백으로 뽑았을 때 화살촉(팀)·이중 테(골키퍼)가 실제로
      눈에 띄는지 — 지금은 도형이 기하로만 비대칭임을 확인했다
