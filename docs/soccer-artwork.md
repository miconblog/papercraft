# 축구 게임판 도안

`IDE-004`(필드·부속·골대)와 `IDE-010`(선수 마커·전술 대형)의 작도 결과다. 치수의
**원본은 코드**(`src/assets/games/soccer/dimensions.ts`)이고 이 문서는 왜 그
값이 되었는지를 적는다. 둘이 어긋나면 코드가 맞다.

인쇄 규격은 [`print-spec.md`](print-spec.md), 도안 데이터 모델은
[`game-authoring.md`](game-authoring.md)를 따른다.

---

## 1. 만드는 법

도안 SVG는 **손으로 쓰지 않고 코드가 만든다.** 슬롯 좌표(도안 정의)와 그림(SVG)이
같은 치수 상수를 읽어야 어긋나지 않기 때문이다.

```
src/assets/games/soccer/
  dimensions.ts      ← 모든 실측 치수. 고칠 곳은 여기 하나다
  rules.ts           ← 게임 방법 텍스트. 도안 정의의 `rules`로 나가 화면에 그려진다
  artwork/           ← 파트별 SVG 생성기
  index.ts           ← 도안 정의 (dimensions.ts를 읽는다)
public/games/soccer/*.svg   ← 산출물. 커밋한다
```

```bash
npm run artwork     # SVG를 다시 만든다
npm run test:run    # 커밋된 SVG가 생성기와 같은지, 기하가 맞는지 검사
```

산출물이 낡으면 테스트가 어느 파일인지 알려 준다.

## 2. 파트와 치수

| 파트          | 종류        | 크기(mm)    | 배율 범위 | 표시                 |
| ------------- | ----------- | ----------- | --------- | -------------------- |
| `field`       | `board`     | 297 × 210   | 0.5–4     | 없음                 |
| `score-sheet` | `cutout`    | 210 × 148.5 | 0.7–2     | 오림선               |
| `goals`       | `buildable` | 280 × 192   | 0.8–2     | 오림선·골접기·산접기 |

`goals`가 A5(210×148.5)에서 **280×192**로 커졌다(2026-09-06). 뚜껑이 붙어 전개도
한 벌이 135×116mm가 되면서 접는 법 글까지 얹으면 한 벌밖에 못 앉혔는데, **그 글을
소개 페이지로 옮겨**(2026-09-08 사용자 요청) 두 벌이 나란히 들어간다 — 270mm에
좌우 2mm·사이 6mm다. 시트에 남는 것은 그림 도해 다섯 컷뿐이고, **골대 둘에 종이
한 장**이면 된다.

세로 176 → 192는 **뚜껑을 두 겹으로 되돌리면서**(2026-09-08) 전개도가 16mm
길어진 몫이다.

297×210(=A4 그 자체)이 아니라 280×190인 것은 **인쇄 여백이 사용자가 고르는 값**
이기 때문이다(`marginMm`, 기본 0). 여백을 조금만 주면 297×210짜리는 곧바로 두
장으로 쪼개진다 — 운동장이 여백 5mm에서 A4 2장이 되는 것이 그래서다. 조립물이
쪼개지면 이어 붙인 자리에서 전개도가 어긋난다. 280×192는 **여백 8mm까지 한 장을
지킨다.**

### 뺀 파트 둘 (2026-09-05)

**게임 방법(`rules-card`)과 공 마커(`ball-markers`)를 출력물에서 뺐다**(사용자
요청). 종이 세 장이 두 장으로 줄었다.

| 뺀 것     | 지금 어디에 있나                                                  |
| --------- | ----------------------------------------------------------------- |
| 게임 방법 | 도안 정의의 `rules` → 소개 페이지(`/games/soccer/rules`)가 그린다 |
| 공 마커   | 준비물로 돌렸다 — "공으로 쓸 납작하고 작은 것 하나(지름 12mm쯤)"  |

규칙을 도안 정의로 옮긴 것은 **인쇄물 구성과 규칙의 수명이 다르기 때문**이다.
어느 파트를 뽑든 규칙은 읽을 수 있어야 하는데, 인쇄 파트에 매여 있으면 그 장을
빼는 순간 규칙도 사라진다. 스키마의 `rules` 필드가 그 자리다(`lib/schema/rules.ts`).

공은 지름만 남겼다(`BALL.diameterMm` 12mm). 골문 크기를 정한 근거가 그 값이고
(`지름 × 2 < 골문 폭`), 준비물 안내가 같은 숫자를 그대로 알려 준다 — 시트를 안
뽑으므로 크기를 아는 길이 그 문장뿐이다. 테스트가 둘이 어긋나지 않게 지킨다.

### 점수 기록칸은 판 · 이름 빈칸이다 (2026-09-08)

표 안은 전부 비어 있다. 예전에는 두 팀 칸 위에 파랑·빨강 **색 막대**를 얹어
"파랑 팀 = 파란 테두리 마커"를 종이에서 맞물리게 했는데, 그 막대를 뺐다(사용자
요청). 팀 이름을 아이가 직접 쓰는 자리라 색이 미리 정해져 있으면 오히려 걸린다 —
어느 칸이 어느 팀인지도 그 손글씨가 정한다.

머리글은 **왼쪽 첫 칸 하나뿐**이다. 사선을 긋고 위에 "이름", 아래에 "판"을 적는
성적표식 칸이다:

```
┌────────┬──────────┬──────────┐
│＼  이름 │          │          │   ← 오른쪽 두 칸은 머리글까지 비어 있다
│ 판  ＼  │          │          │
├────────┼──────────┼──────────┤
│   1    │          │          │
```

칸 하나가 두 방향을 말해 준다 — 세로로 읽으면 판 번호, 가로로 읽으면 그 팀
이름이다. 글자는 줄 번호와 같은 3.6mm다. 사선이 칸을 가르므로 더 키우면 선에
닿고, 이만하면 30×12mm 칸에서 두 글자가 선을 피해 앉는다.

그래서 **팀 색 슬롯의 배치가 하나도 남지 않았다.** 값은 그대로 살아 운동장 마커를
칠한다 — 마커 색은 배치가 아니라 그룹의 `colorSlotId`를 통해 읽히기 때문이다.
스키마는 원래 슬롯마다 배치를 하나 이상 요구했는데, **그룹의 색 슬롯만 예외**로
열었다(`schema/game.ts`). 배치도 없고 어느 그룹의 색 슬롯도 아닌 슬롯은 여전히
`parseGame`이 막는다.

에디터에서도 따라온 결과가 있다 — 점수 기록칸을 고르면 이제 **고칠 값이 하나도
없어** 옵션 줄이 통째로 사라진다. 팀 색은 운동장에서만 보인다.

### 골 에어리어는 골키퍼 마커를 담는 칸이다 (2026-09-05)

값이 세 번 움직였다. 전부 **골키퍼 마커를 담기 위해서**다:

| 깊이     | 왜                                                             |
| -------- | -------------------------------------------------------------- |
| 32mm     | 골대가 골라인 안쪽 16mm를 깔고 앉아 골키퍼가 그 앞에 섰다      |
| 16mm     | 골대를 골라인 밖으로 빼 필드를 비우며 실제 축척(5.5m)으로 복귀 |
| **26mm** | 마커가 15 → 24mm로 커지면서 `19 + 12 = 31`을 품어야 했다       |

폭은 **골문 폭에서 잡는다**. 골문이 70mm로 커지면서(2026-09-06) 예전 78mm 안에
골대가 거의 꽉 차 골포스트와 골 에어리어 선이 겹쳐 보였다. 골포스트 좌우로
16mm씩 남겨 **102mm**로 넓혔다 — 실제 정의(골포스트에서 좌우로 5.5m)를 이 축척으로
옮긴 값이다. 페널티 에어리어 폭도 115 → **140mm**로 따라 넓혔다. 그러지 않으면
두 선 사이가 6mm밖에 남지 않는다.

절대 크기가 실제보다 큰 것은 **골대와 마커가 실제 축척보다 크기 때문**이다 —
사람과 골대를 담는 칸이라 그쪽 크기를 따라간다.

`__tests__/formations.test.ts`가 "골키퍼가 골 에어리어 안에 온전히 들어가는가"를
지킨다.

### 골대 자리 눈금 (2026-09-05)

골대가 골라인 **바깥**에 서면서 종이 위에 놓을 자리가 하나도 안 보이게 됐다.
눈대중으로는 가운데 맞추기가 어렵다는 사용자 지적으로 눈금을 넣었다.

- **골포스트 눈금 둘** — 중앙에서 ±27.5mm(골문 폭의 절반). 골라인을 가로질러
  안쪽 2mm · 바깥 4mm로 긋는다. 여기에 골대 **앞 모서리의 좌우 끝**을 맞춘다
- **가운데 눈금 하나** — 골라인에서 안쪽으로 2.5mm만. 골포스트 눈금보다 짧게 둔
  것은 **셋을 같은 길이로 두면 어느 것이 골포스트인지 헷갈리기** 때문이다
- 바깥으로 4mm만 나가는 것은 종이 여백이 6mm뿐이라 재단에서 잘리지 않게
  2mm를 남긴 것이다

입술을 안으로 접어 넣은 뒤로(2026-09-08) **운동장 위로 나오는 종이가 없다.** 그래서
눈금의 안쪽 2mm가 골대 옆에 그대로 보인다 — 그 전에는 입술이 덮었다. 바깥 4mm는
골대 바닥에 깔리므로, 실제로 보고 맞추는 것은 안쪽 2mm다.

**맞출 것은 앞 모서리의 좌우 끝뿐이다.** 골대가 뒤로 얼마나 나가는지는 맞출 필요가
없으므로 바닥 넓이를 파선 상자로 그리지 않는다 — 예전에 그렇게 그렸을 때 골
에어리어 안에 사각형이 하나 더 겹쳐 골라인 근처가 삼중선이 됐다.

**필드를 초록으로 칠하지 않는다.** 잉크를 크게 먹고, 공이 미끄러지는 면이라
잉크가 두꺼우면 연필 자국이 더 남는다. 사용자가 만든 판처럼 라인만 초록이다
(#2f7d32 — 흑백으로 뽑아도 회색 선으로 남는다).

## 4. 골대 — 왜 이 구조인가

```
       ┌──────────┐          뚜껑 겉장 55×16 — 접어 넣어 두 겹이 된다
     ┌─┼──────────┼─┐        귀 20×10 · 뚜껑(천장) 55×16 · 귀 20×10
     └─┤          ├─┘        홈 6mm — 귀를 탭에서 뗀다
    ┌──┼──────────┼──┐       탭 10×26 · 뒷벽 55×32 · 탭 10×26
    └──┤          ├──┘       홈 6mm — 탭을 옆벽에서 뗀다
 ┌──┬──┼──────────┼──┬──┐    겹 8×32 · 옆벽 32×32(사선) · 바닥 55×32 · 옆벽 · 겹
 └──┴──┤          ├──┴──┘
       │   입술   │           안으로 접어 바닥에 포갠다 (55×20)
       └──────────┘
```

전개도 한 벌 **135×116mm**. 접으면 **골문 55×32mm, 바닥 깊이 32mm**의
**뚜껑 달린 쟁반**이 된다. 사용자 표현으로 "국자", 생김새로는 **쓰레받기**다.

### 지붕을 없앤 것이 전부를 풀었다 (2026-09-06)

3번(바닥 없는 상자)은 지붕이 문제였다. 지붕을 옆벽에 붙여야 상자가 모양을
유지하는데, 그 방법이 둘 다 막혔다:

| 시도                           | 왜 물렀나                                                 |
| ------------------------------ | --------------------------------------------------------- |
| 지붕 탭에 **풀칠**             | 6–7세 아이가 풀 마르기를 기다리며 벽을 붙들고 있어야 했다 |
| 옆벽에 **칼집**을 내 탭을 끼움 | **가위로 낼 수 없다.** 그럴 바에는 풀이 낫다(사용자 지적) |

지붕이 있어야 했던 이유는 크로스바를 만들고 옆벽 둘을 붙들어 주는 것이었다.
그런데 사용자가 아이와 만들어 쓰던 골대는 **지붕이 벽에 붙어 있지 않았다** —
사진 두 장 모두 위쪽 큰 면이 뒤로 젖혀진 채였다. 붙박이 지붕이 아니라 뒷벽에
경첩처럼 달린 **뚜껑**이었던 것이다(2026-09-08에 알아차렸다 — 아래 참고).

일단 지붕을 통째로 없애자 붙일 것이 사라졌고, 다음이 한꺼번에 따라 나왔다:

- **지붕 창이 필요 없다.** 3번에서 창을 낸 목적(골이 눈에 남게 하기)이 구조로
  해결된다
- **풀칠면도 칼집도 없다.** 오릴 곳은 바깥 윤곽 하나뿐이라 **가위만으로 끝난다**
- **접는 방향이 거의 하나다.** 벽 셋을 세우는 것도, 겹을 내리는 것도, 탭을 대는
  것도 전부 인쇄면이 안으로 오는 골접기(`fold-valley`)다. 뒤에 뚜껑이 돌아오면서
  귀 둘도 2026-09-08부터 같은 방향이다(그전엔 벽을 바깥에서 감싸는 산접기였다).
  반대로 접는 곳은 **뚜껑을 두 겹으로 포개는 한 줄뿐**이다 — 아래 참고

### 뚜껑은 돌아왔지만 지붕은 아니다 (2026-09-08)

뚜껑 없는 쟁반은 **골포스트를 맞고 튄 공이 그대로 밖으로 나갔다**(사용자 지적).
벽 높이가 공 지름의 두 배뿐이라 위쪽으로 튀면 막을 것이 없다.

그래서 뚜껑을 다시 덮었는데, 3번의 지붕과는 다르다:

|              | 3번의 지붕 (2026-09-05)               | 지금의 뚜껑 (2026-09-08)         |
| ------------ | ------------------------------------- | -------------------------------- |
| 붙는 곳      | 뒷벽 위 → 앞으로 접어 옆벽에 **고정** | 뒷벽 위 → 앞으로 접어 **얹기만** |
| 여미는 법    | 풀칠탭, 나중엔 옆벽 칼집              | 양옆 **귀를 옆벽 바깥에 씌운다** |
| 안을 보는 법 | 지붕에 창을 오려냄                    | 창이 없다 — **골문으로 본다**    |
| 공 꺼내기    | 창으로 집는다                         | **뚜껑을 젖힌다**                |

핵심은 **경첩**이다. 뚜껑이 뒷벽에 붙어 있으니 따로 고정할 필요가 없고, 양옆
귀만 상자 뚜껑처럼 벽을 감싸면 닫힌다. 붙일 것이 없으니 풀도 칼도 돌아오지
않았다. 공을 꺼낼 때는 뚜껑을 젖혔다가 도로 덮으면 된다 — 사진 속 골대가 두 장
다 뚜껑을 젖힌 채로 찍혀 있었던 이유다.

#### 그 뚜껑이 다시 절반으로 줄었다 (같은 날)

처음에는 바닥 깊이와 같은 32mm로 쟁반 위를 **통째로** 덮었다. 그러자 이번에는
**공이 들어갔는지 보이지 않는다**는 지적이 왔다 — 뚜껑을 젖혀 봐야 알 수 있으면
"골이 눈에 남는다"는 이 구조의 목적이 다시 흐려진다.

그래서 **바닥 깊이의 절반(16mm)**만 덮는다. 뒤쪽 절반은 뚜껑, 앞쪽 절반은 열린
채다. 위에서 내려다보면 열린 자리로 안이 바로 보인다.

맞바꾼 것 둘:

| 잃은 것         | 얼마나                                                                                                                                        |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 크로스바 자리   | 뚜껑 앞 모서리가 골문에서 16mm 안쪽으로 물러났다 — 정면에서 보면 골문 **안쪽 천장**에 걸린 바다 (뒤에 접힌 변이 되어 곧기는 하다 — 아래 참고) |
| 튄 공을 막는 힘 | 통째로 덮을 때보다 약하다. 앞쪽 절반으로는 여전히 튀어 나갈 수 있다                                                                           |

앞쪽 절반을 덮는 편이 이 둘에 다 유리하지만, 뚜껑이 **뒷벽 위에 경첩으로**
달려 있어 덮이는 쪽은 뒤쪽으로 정해져 있다. 앞을 덮으려면 경첩을 옮겨야 하는데
앞에는 벽이 없다 — 거기가 골문이다.

#### 줄일 때 남는 절반을 잘라 버린 것이 잘못이었다 (같은 날)

절반으로 줄이면서 뚜껑 판도 16mm로 잘랐다. 접어 보니 **종이 한 겹짜리 천장**이
되어 힘을 못 받았다(사용자 지적 — "뚜껑이 한 겹이라 약해"). 잘린 앞머리가 아래로
처져서, 크로스바 노릇을 하라고 남겨 둔 모서리가 오히려 늘어졌다.

지금은 **자르지 않고 판을 32mm로 되돌린 뒤 한가운데를 접어 포갠다.**

```
   ┌────────┐  ← yLid   겉장 16 (접어 넣으면 안으로 숨는다)
   ├────────┤  ← yFold  ← 여기서 겹친다 = 다 접었을 때의 앞 모서리
   │그물·표식│  ← y0     천장 16 (인쇄면이 남는 쪽)
```

얻은 것 둘:

- **천장이 두 겹**이 된다. 덮는 깊이는 그대로 16mm인데 두께만 배다
- **앞 모서리가 자른 변이 아니라 접힌 변**이 된다 — 크로스바가 처지지 않고 곧게
  선다. 인쇄된 굵은 선과 실제 모서리가 겹쳐 보이는 것도 이 덕이다

##### 이 접기만 산접기다 — 방향을 고를 수 없다

`GOAL_NET_SIZE`의 `lidDepthMm * 2`와 `goals.ts`의 `mountainFolds`가 이 한 줄이다.

| 겹치는 방향             | 인쇄면이 어디로 가나                                                          |
| ----------------------- | ----------------------------------------------------------------------------- |
| 골접기(인쇄면끼리 마주) | 인쇄면 둘이 안에 갇힌다 — 겉도 안도 무지. 그물도 `daddyscraft.com`도 사라진다 |
| **산접기(인쇄면 바깥)** | 아래 절반의 인쇄면이 위로 남는다 → 뚜껑을 덮으면 그 면이 **골문 천장**이 된다 |

그래서 도안 전체에서 반대로 접는 곳이 여기 하나 생겼다. 접는 순서(`rules.ts`)가
그 예외를 따로 한 줄로 짚는다.

딸려 온 좌표 변화 셋:

- **귀는 겹치고 난 뒤의 뚜껑에만 붙는다**(`yFold`~`earBottom`). 겉장까지 올라가면
  포갤 때 귀가 같이 말려 들어가 옆벽에 닿지 못한다
- **크로스바가 `yLid`에서 `yFold`로 옮겨 왔다.** 겹치는 접는선과 나란히 붙어
  헷갈리므로, 띠 한가운데가 아니라 아래쪽 3/4(=3mm)에 얹어 간격을 벌렸다
- **그물은 천장 절반에만 친다.** 겉장은 숨는 면이라 잉크가 보이지 않는다

#### 옆벽 사선 — 쓰레받기가 되는 자리 (같은 날)

뚜껑이 절반이 되자 **옆벽 앞쪽 위에 얹힐 것이 없어졌다.** 벽만 덩그러니 서서
쟁반이 어정쩡해졌는데, 사용자가 손으로 접어 보고 답을 찾아 사진으로 보내 왔다 —
**옆벽을 사선으로 접어 넘긴다.**

```
옆에서 본 모습

   ┌────────┐              뚜껑 (바닥의 절반)
   │        ＼              사선: 뚜껑 앞 모서리 → 바닥 앞 모서리
   │          ＼
   └────────────┴───────    바닥 + 입술
   뒷벽
```

앞이 낮아지는 **쐐기**가 된다 — 쓰레받기 그대로다. 얻은 것이 셋이다:

- **뚜껑 앞 모서리가 골포스트 자리에 남는다.** 그 높이까지가 골문이고 그 앞은
  흘러내리므로, 정면에서 골대로 읽힌다
- **앞이 트여 있어** 공이 들어갔는지 위에서 바로 보인다
- **넘어가는 삼각형이 안쪽에 든 귀와 겹을 함께 문다** — 잠금이 하나 더 늘었다

두 끝점은 고를 여지가 없다. **뚜껑 앞 모서리가 닿는 벽 위쪽 점**과 **바닥 앞
모서리**를 이어야 넘긴 삼각형의 두 변이 뚜껑과 바닥에 각각 맞아떨어진다. 깊이
16mm 동안 높이 32mm를 내려가는 2:1 기울기다. 테스트가 두 끝점을 좌표로 지킨다 —
뚜껑 깊이나 바닥 깊이를 고치면 이 선도 따라온다.

테스트가 `뚜껑 깊이 × 2 = 바닥 깊이`를 지킨다. 한쪽을 고칠 때 다른 쪽도 같이
보라는 뜻이다.

#### 귀는 바깥에서 안으로 들어왔다 (2026-09-08)

처음에는 상자 뚜껑처럼 귀가 옆벽을 **바깥에서** 감쌌다. 잡히기는 했지만 귀 둘이
겉에 나와 있어 지저분했고, 이 도안에서 유일하게 반대로 접는 자리라 설명도 한 줄
더 들었다. 사용자 제안으로 **안으로 넣어 겹에 물린다**.

|           | 바깥 (전)                | 안 (지금)                           |
| --------- | ------------------------ | ----------------------------------- |
| 접는 방향 | 산접기 — 유일한 예외     | 골접기 — **전부 한 방향**           |
| 잡는 힘   | 벽을 감싸는 마찰         | **겹이 눌러 문다** — 탭과 같은 잠금 |
| 겉모습    | 귀 둘이 벽 바깥에 나온다 | 겉면에 나오는 것이 없다             |
| 길이      | 8mm                      | 12 → **20mm** (아래 참고)           |

#### 서로 피하게 짰다가, 일부러 물리게 뒤집었다 (같은 날)

**이 도안에서 뜻이 한 번 뒤집힌 값이 여기 있다.**

귀가 안으로 들어오면서 귀와 모서리 탭이 **같은 옆벽 안쪽 면**을 나눠 쓰게 됐다.
처음 계산은 "겹치면 그 자리만 종이가 넉 겹이 되어 겹이 안 닫힌다"였고, 그래서
둘이 **서로를 피하게** 깊이 16mm를 갈라 줬다:

```
옆벽 안쪽 면 (뒷벽에서부터의 깊이)          ← 처음 (피한다)
  0 ────────── 10 ── 16 ──────────── 32
  │   모서리 탭   │  귀  │   (빈 면)
```

접어 보니 그게 헐거웠다. 사용자 지적 — **"겹이 탭을 물고, 귀가 탭을 물어서 서로
맞물려야 할 것 같다."** 나란히 서기만 하면 서로를 잡아 주는 것이 없어, 겹 하나가
탭과 귀를 다 감당해야 했다. 겹이 조금 들리면 둘 다 풀린다.

그래서 **일부러 겹치게** 뒤집었다:

```
옆벽 안쪽 면 (뒷벽에서부터의 깊이)          ← 지금 (문다)
  0 ─────── 6 ─── 10 ──── 16 ──────── 32
  │  모서리 탭 (0–10)  │       (빈 면)
        └ 귀 (6–16) ┘         ← 4mm 겹쳐 탭을 타고 넘어간다
  ═══════════════════════════════════  겹 (윗머리 8mm, 전 구간)
```

셋이 **사슬**이 된다 — `1번 탭`을 `2번 귀`가 물고, 그 둘을 `3번 겹`이 문다. 하나를
당겨도 나머지가 붙잡는다.

값 셋이 이 사슬의 고리이고, 테스트(`탭·귀·겹이 사슬처럼 맞물린다`)가 넷을 다
지킨다:

| 값                       | 지금        | 왜 그 값인가                                                                                                                    |
| ------------------------ | ----------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `lidEarInsetMm` (물러남) | 10 → **6**  | `cornerTabMm`보다 짧아야 겹치는 폭(4mm)이 생긴다. **6이 하한** — 이게 곧 귀와 탭 사이의 홈이라 가위가 들어갈 깊이는 남아야 한다 |
| `lidFlapMm` (귀 길이)    | 12 → **20** | `cornerTabMm × 2`. 귀가 탭을 **가로질러** 내려가야 하는데 탭 길이만큼만 내려오면 모서리에서 끝나 잡을 것이 없다                 |
| `cornerTabMm` (탭 길이)  | 10          | 물림을 더 키우려면 물러남이 아니라 **이 값**을 늘린다 — 물러남은 이미 하한이다                                                  |

대가는 처음 계산이 걱정하던 그것이다: 4×8mm 구석이 **종이 넉 겹**이 된다(벽 + 탭 +
귀 + 겹). 일반 용지에서는 겹이 닫히는 것을 확인했지만 두꺼운 종이에서는 §12의
확인 항목이다.

귀가 물러난 자리(6mm)는 **모서리 홈을 겸한다.** 가위가 들어갈 최소 깊이와 같으므로
홈을 따로 팔 필요가 없다 — 대신 여기가 하한이라 더는 못 줄인다.

#### 맞물리는 셋은 이름이 아니라 번호다 (같은 날)

시트에서 이 세 면은 `탭`·`귀`·`겹`이 아니라 **`1`·`2`·`3`**으로 적힌다(사용자
요청). 구조가 사슬이라 **"무엇이 무엇을 먼저 무는가"가 이름보다 중요하고**, 번호가
곧 그 차례다. 접는 순서 글도 "1번 탭을 …", "2번 귀를 내려 1번 위에 …"로 부른다.

덤도 있다. 이름 대신 한 글자라 좁은 면(겹은 폭 8mm)에도 5mm로 크게 넣을 수 있어
이름보다 잘 보이고, 세로로 돌려 쓸 필요가 없다. 번호와 이름의 대응은 시트 머리글
한 줄과 도해 ③에 있다.

### 모서리 홈 넷 — 이 전개도의 급소 (2026-09-08)

**상자 모서리는 종이가 붙어 있는 채로는 접히지 않는다.** 처음 그린 전개도에서
뚜껑 귀·모서리 탭·옆벽이 위아래로 한 장으로 이어져 있었고, 셋은 접히는 방향이
제각각이라 하나를 접으면 나머지가 딸려 왔다. 사용자가 **"뒷벽과 옆벽을 동시에
세우려면 어딘가 오려야 하는 것 아니냐"**고 짚어 알았다.

| 맞닿은 곳           | 붙어 있던 길이 | 왜 문제인가                               |
| ------------------- | -------------- | ----------------------------------------- |
| 뚜껑 귀 ↔ 모서리 탭 | 8mm            | 귀는 바깥으로, 탭은 안으로 접힌다         |
| 모서리 탭 ↔ 옆벽    | 12mm           | 탭은 뒷벽을 따라, 옆벽은 바닥을 따라 선다 |

고친 방법은 **탭 위아래에 6mm 홈을 파는 것**이다. 홈은 바깥 윤곽의 일부라 따로
칼집을 낼 필요가 없다 — 오림선을 따라가다 홈으로 들어갔다 나오면 된다. 6mm는
가위 날이 들어가 방향을 바꿀 만한 최소 깊이로 잡았다.

그만큼 탭이 짧아지지만(24 → 18mm) **겹이 무는 윗머리 8mm는 그대로 덮는다.**
남는 6mm는 뒷모서리 맨 아래에 생기는 틈인데, 공이 12mm라 빠져나가지 못한다.

이 규칙은 테스트가 지킨다 — **맞닿은 변은 접는선이거나 아예 떨어져 있거나 둘 중
하나**여야 한다(`맞닿은 변은 모두 접는선이다`). 면을 하나 더할 때 이 규칙을
어기면 도안은 멀쩡해 보이는데 접히지 않는다.

### 뒷모서리는 겹이 문다 — 풀도 칼도 없이

남은 문제는 뒷모서리 둘이다. 바닥에서 접어 올린 뒷벽과 옆벽 사이에는 종이가
없으므로 무엇으로든 이어야 한다.

1. 뒷벽 양 끝에 **1번 탭**(10×26)을 붙여 두고, 앞으로 접어 옆벽 안쪽에 댄다
2. 뚜껑에서 내려온 **2번 귀**(20mm)가 그 탭의 뒷머리를 4mm 타고 넘어가 문다
3. 옆벽 위의 **3번 겹**(8mm)을 안쪽으로 180° 접어 내리면 1·2의 윗머리를 한꺼번에
   덮는다

겹은 두 가지를 한다 — 탭과 귀를 물어 모서리를 닫고, 얇은 종이 벽의 윗머리를 두
겹으로 만들어 세워 둔다. 사용자가 만든 골대의 테두리가 두꺼웠던 것이 이 겹이다.

앞모서리는 잠그지 않는다. 앞은 통째로 골문이라 잠글 것이 없고, 겹으로 뻣뻣해진
옆벽과 닫힌 뒷모서리 둘이면 쟁반이 모양을 잡는다.

### 입술 — 안으로 접어 바닥에 포갠다

3번까지 바닥이 없었던 이유는 **바닥을 깔면 종이 두께만큼 턱이 생겨 미끄러져 오는
공이 골문에서 걸린다**는 것이었다. 입술이 그 문제를 없앤다.

처음에는 입술을 **운동장 위에 얹었다**(2026-09-06). 바닥과 한 장으로 이어져 있으니
턱이 없다는 계산이었다. 그런데 2026-09-08에 사용자가 **안으로 접어 넣자**고 했고,
그쪽이 더 낫다:

|                | 밖으로 얹기 (전)        | 안으로 접기 (지금)                               |
| -------------- | ----------------------- | ------------------------------------------------ |
| 앞 모서리      | 입술 앞의 **자른 변**   | 바닥 앞의 **접힌 면** — 더 부드럽다              |
| 공이 넘는 단차 | 자른 변 하나(올라감)    | 접힌 면 하나(올라감) + 입술 뒤 끝(**내려감**)    |
| 운동장         | 55×20mm를 종이가 덮는다 | **덮지 않는다** — 골대가 골라인 밖에 온전히 선다 |
| 바닥           | 한 겹                   | 앞쪽 20mm가 **두 겹** — 밀어도 덜 우그러진다     |

공이 넘는 자리가 자른 변에서 접힌 면으로 바뀐 것이 요점이다. 안쪽 끝의 단차는
**내려가는** 쪽이라 걸리지 않는다 — 골대가 골라인 밖에 서는 것과 같은 이치다.

놓는 방법은 그대로 둘이다:

- 골라인 밖에 놓고 **골대 앞 모서리를 골라인에 댄다.** 앞 모서리 좌우 끝을 눈금에
  맞추면 골문 가운데가 맞는다
- 운동장을 **스케치북에 붙여 쓴다면**, 골문 폭만큼 오려 낸 자리에 쟁반을 끼운다.
  국자를 꽂듯 넣고 빼므로 치울 때 접어 둘 필요가 없다

입술 길이(20mm)는 **바닥 깊이(32mm)를 넘지 않아야 한다** — 넘으면 접었을 때 뒷벽에
닿아 들뜬다. 테스트가 지킨다.

### 접는 순서는 시트가 아니라 소개 페이지에 있다 (2026-09-08)

접는 법 일곱 줄이 시트의 오른쪽 단을 통째로 쓰고 있었다. 그 자리를 비우면 전개도
두 벌이 나란히 들어가므로, **글을 도안 정의의 `rules`로 옮겼다**(사용자 요청).
`/games/soccer/rules`의 "게임 방법"에 **골대 접는 법** 절로 나온다.

| 어디에      | 무엇이                                                            |
| ----------- | ----------------------------------------------------------------- |
| 소개 페이지 | 접는 순서 일곱 줄 (`GOAL_ASSEMBLY_STEPS` → `RULES`)               |
| 전개도 시트 | 그림 도해 다섯 컷 · 면 이름 · "접는 순서는 소개 페이지에서" 한 줄 |

**그림은 시트에 남겼다.** 전개도 두 벌 아래에 어차피 빈 띠가 생기고, 한 장짜리
파트라 그림을 넣어도 종이가 늘지 않는다. 글로 설명하기 가장 어려운 두 동작
(1을 2가 무는 것 · 그 둘을 3이 무는 것)이 그 그림에 있다.

면 이름은 2.6 → **3.2mm**로 키웠다. 순서가 "뚜껑·겹·탭·입술"을 그대로 부르는데
이름이 시트에서 안 읽히면 순서를 따라갈 수 없다. 3.2mm면 최소 배율 0.8에서도
2.56mm라 6절의 하한을 지킨다.

> 이 문서가 3.2mm를 적어 둔 동안 `goals.ts`는 2.6mm에 머물러 있었다(2026-09-08에
> 발견해 맞췄다). 키우니 긴 문구 둘이 골문 폭(55mm)을 넘어 같이 줄여야 했다 —
> **글자 크기와 문구 길이는 한 쌍**이다. 여기를 다시 건드리면
> `estimateTextWidthMm`으로 55mm를 넘는지부터 재라.

### 그물과 인쇄면

인쇄면이 **쟁반 안쪽**을 향한다(3번까지는 바깥이었다). 골문으로 들여다보는 면이
안쪽이기 때문이다. 그물 격자는 뚜껑과 벽 셋의 안쪽에 친다 — 골문 네 면이 모두
그물로 둘러싸여야 골대로 읽힌다.

바닥과 입술에는 격자를 넣지 않는다. 공이 지나가고 멈추는 면이라 비워 두어야 공이
눈에 띄고, 입술은 운동장 위에 얹히므로 잉크가 있으면 라인과 겹쳐 지저분하다.
면 이름은 **글자 뒤에 흰 바탕을 깔아야** 그물 위에서 읽힌다.

**뚜껑 면에는 이름 대신 `daddyscraft.com` 표식이 들어간다**(2026-09-08 사용자
요청). 접으면 이 면이 골문 안쪽 천장이 되어 골문으로 들여다볼 때 눈에 들어온다 —
종이에 남는 유일한 출처 표시라 면 이름과 같은 3.2mm로 둔다. 뚜껑은 크로스바(굵은
선)가 붙은 맨 위 띠라 이름이 없어도 어느 면인지 헷갈리지 않는다.

조립이 성립하는지는 테스트가 기하로 확인한다 — 벽 셋의 높이가 같음, 뒷벽 폭 =
바닥 폭, 옆벽 길이 = 바닥 깊이, **뚜껑 깊이 × 2 = 바닥 깊이**, 뚜껑이 뒷벽 위에
붙음, 귀 깊이 = 뚜껑 깊이 − 물러남, 귀 < 옆벽 폭, **귀 물러남 < 탭 길이**(물린다)
· **귀 물러남 ≥ 홈**(가위) · **귀 길이 = 탭 길이 × 2**,
귀 길이 > 겹 너비, 탭 높이 = 뒷벽 높이 − 홈, 탭 높이 > 겹 너비, 탭 너비 > 겹 너비,
겹 너비 < 벽 높이, 입술 폭 = 바닥 폭 · 입술 ≤ 바닥 깊이, **맞닿은 변이 전부 접는선임**,
**옆벽 사선이 뚜껑 앞 모서리와 바닥 앞 모서리를 이음**, 오림선이 윤곽뿐임,
면끼리 겹치지 않음.
**⚠︎ 실제로 오려 접어 보는 것은 남아 있다.**

### 크기의 기준은 실제 골대가 아니라 사진이다 (2026-09-06)

처음 골문은 **39×13mm**였다. 실제 골대(7.32×2.44m)의 3:1을 그대로 옮긴 값이다.
아이와 종이로 뽑아 만들어 보니 **너무 작아 골이 안 들어갔다**(사용자 지적).

첫 원인은 공이었다. 크로스바 아래가 13mm인데 공 지름이 12mm다 — 공 하나가
**1mm 여유로** 지나가야 했다. 튕겨서 굴리는 공이 그 틈을 통과할 리 없다. 실제
골대의 3:1은 **공까지 같은 축척일 때만** 뜻이 있는데, 이 판의 공은 축척
(2.85mm/m로 0.6mm)보다 19배 크다.

그래서 공 지름 기준으로 52×26mm까지 키웠는데, 사용자가 한 번 더 물렀다 —
**아이와 하는 종이 게임이라 실제 골대보다 커야 하고, 사진 속 손으로 만든 골대와
같은 크기여야 한다**는 것이었다. 그래서 기준을 축척도 공도 아닌 **사진 실측**으로
바꿨다.

재는 방법은 사진 안에 있었다. 운동장에 인쇄된 **골포스트 눈금 두 개가 정확히
39mm 간격**이므로 그것을 자로 삼아 축척 12.0 px/mm를 얻고(가운데 눈금까지 재면
19.46mm — 참값 19.5와 0.2% 차이라 믿을 만하다), 같은 사진 속 수제 골대를 쟀다:
폭 약 68mm · 높이 약 55mm · 깊이 약 27mm.

| 값        | 처음 | 공 기준 | 사진 실측 | 지금     | 근거                                |
| --------- | ---- | ------- | --------- | -------- | ----------------------------------- |
| 골문 폭   | 39mm | 52mm    | 70mm      | **55mm** | 사용자 지정. 공 지름의 4.6배        |
| 골문 높이 | 13mm | 26mm    | 24mm      | **32mm** | 공 지름의 2.7배 = 크로스바 아래까지 |
| 바닥 깊이 | 14mm | 18mm    | 32mm      | **32mm** | 공 지름의 2.7배. 얕으면 도로 뱉는다 |
| 입술      | —    | —       | 20mm      | **20mm** | 운동장에 얹혀 눈금까지 닿는 길이    |

### 마지막 한 번 더 — 55×32mm (2026-09-08)

사진에서 잰 70×24는 **종이에 뽑기 전의 수치**였다. 실물을 놓고 사용자가 고른 값이
**55×32**다. 폭이 줄고 높이가 올라 골문이 납작한 가로 구멍에서 **1.7:1**에
가까워졌다 — 실제 골대의 3:1보다 뭉툭하지만, 공(12mm)이 실제 축척보다 19배 큰
판에서는 세로가 넉넉한 쪽이 들어가는 맛이 낫다.

높이 32는 **바닥 깊이와 같은 값**이라 접으면 옆벽이 정사각이 된다. 어느 변이
어디인지 헷갈릴 수 있어 시트에 면 이름을 적어 둔 이유가 하나 늘었다.

폭 55mm는 실제 축척(20.9mm)의 **약 2.6배**다. 공이 실제 축척보다 19배 크다는 것을
생각하면 여전히 공에 비해 작은 골대다. 그러면서도 골라인(필드 짧은 변 198mm)의
절반은 넘지 않아야 한다는 하한을 테스트가 지킨다.

**골 에어리어(102mm)는 그대로 뒀다.** 골문이 70일 때는 골대가 그 안을 69% 채워
골포스트와 선이 겹쳐 보였는데, 55가 되면서 54%로 내려가 실제 축구장의 비율
(7.32/18.32 = 40%)에 오히려 가까워졌다. 전개도만 고치면 되는 변경이었다.

## 5. 공

- **지름 12mm**, 한 시트에 24개(6×4, 중심 간격 16mm)
- 골문 폭 55mm의 **4.6분의 1** — "뚜렷이 작게"를 테스트가 강제한다
  (`지름 × 4 ≤ 골문 폭`)
- 골문 높이 32mm의 2.7분의 1이라 벽에 걸리지 않고 들어간다 (`지름 × 2 ≤ 높이`)
- 12mm는 **가위로 오릴 수 있는 하한**과 **골문을 지날 상한** 사이에서 잡았다.
  바닥 깊이(32mm)의 3분의 1이 안 되어 쟁반 안에 넉넉히 멈춘다.
  ⚠︎ 연필로 튕기는 맛은 종이에 뽑아 봐야 안다

24개는 잃어버리거나 찢어질 때를 위한 여분이다. `defaultCopies`가 2라 기본으로
48개가 나온다.

## 6. 가독성 최소 배율

기준을 이렇게 정했다 — **그 파트를 쓰는 데 꼭 읽혀야 하는 글자가 종이 위에서
2.5mm 이상**. 2.5mm는 가정용 프린터에서 한글이 뭉개지지 않는 하한으로 잡은 값이다.

| 파트          | 필수 글자 | 크기  | minScale | 그 배율에서 |
| ------------- | --------- | ----- | -------- | ----------- |
| `field`       | 등번호    | 7mm   | 0.5      | 3.5mm       |
| `score-sheet` | 판 번호   | 3.6mm | 0.7      | 2.52mm      |
| `goals`       | 면 이름   | 3.2mm | 0.8      | 2.56mm      |

`goals`의 필수 글자가 **조립 안내에서 면 이름으로 바뀌었다**(2026-09-08). 접는
순서가 소개 페이지로 옮겨 가면서 시트에서 가장 작은 필수 글자가 면 이름이 됐고,
순서가 "뚜껑·겹·탭·입술"을 그대로 부르므로 이름이 읽혀야 순서를 따라갈 수 있다.
그래서 면 이름을 2.6 → 3.2mm로 키워 minScale 0.8을 지켰다.

부차적인 글자(조립 도해 라벨 2.2mm, 시트 부제 3mm)는 최소 배율에서 2.5mm 아래로
내려간다. 그것들 없이도 도안을 쓸 수 있어 하한을 정하는 데 넣지 않았다.

> **⚠︎ 이 표는 디지털 기준이다.** 2.5mm라는 하한 자체를 종이로 확인하지 못했다
> (이 환경에 프린터가 없다 — `IDE-002`와 같은 사유). 실측하면 값이 바뀔 수 있고,
> 바뀌면 `dimensions.ts`가 아니라 각 파트의 `minScale`을 고친다.

## 7. 용지

운동장은 공을 반복해서 튕기고 미끄러뜨리는 면이다. 규칙문의 준비물 절과 파트
설명에 **120g/m² 이상**을 권한다. ⚠︎ 일반 복사용지(80g/m²)가 실제로 얼마나 빨리 해지는지는
실물로 확인하지 못했다 — 권장값은 안전한 쪽으로 잡은 것이다.

## 8. 게임 방법 텍스트

`src/assets/games/soccer/rules.ts`에 있고, 도안 정의의 `rules`를 거쳐 **소개
페이지가 그린다**(2026-09-05 이전에는 `rules-card` 파트로 인쇄했다).
**사용자가 확인한 규칙만** 규칙 절에 넣는다:

- 패스 시도는 한 턴에 최대 3번, 성공하면 3번으로 초기화
- 3번 안에 연결 못 하면 턴오버, 상대 선수에 닿으면 즉시 턴오버
- 슛은 공이 자기 팀 선수 위에 있을 때만, 패스 시도 중 전환 불가
- 점수 계산은 목표 점수제·시간제 **둘 다 선택지로** 안내(기본값 없음)
- 말미에 "기본 규칙이니 자유롭게 바꿔서 즐기세요"

아직 확인되지 않은 것(**공이 밖으로 나갔을 때 · 핸들링의 정확한 적용 조건 · 그 밖의
파울**)은 규칙으로 단정하지 않고 마지막 "시작 전에 정해 두면 좋은 것"에 넣었다.
확인이 오면 규칙 절로 올린다. 테스트가 이 경계를 지킨다.

## 9. 참고 자료와 저작권

작도의 바탕이 된 자료는 두 개다.

| 자료                        | 출처                                                                  | 저작권                   |
| --------------------------- | --------------------------------------------------------------------- | ------------------------ |
| ① 옛 인쇄본 게임판 스크린샷 | 사용자가 2026-09-03 대화에 첨부. **원 발행처·연도는 확인되지 않았다** | 불분명 — 복제하지 않는다 |
| ② 사용자가 만든 스케치북 판 | 사용자가 직접 그려 만든 판을 찍은 사진. 2026-09-03 대화에 첨부        | 사용자 본인의 것         |

두 자료 모두 저장소에 두지 않았다. ①은 권리가 불분명하고, ②는 사용자 개인의
사진이라 공개 저장소에 올릴 이유가 없다.

**②를 기준으로 삼았다** — 가로 방향, 원형 마커, 오려 접어 세우는 종이
골대. ①의 세로 구성은 따르지 않았다. (골대는 2026-09-05에 입체 터널에서 평면
프레임으로 다시 잡았다 — 4절 참고.)

### 옛 인쇄본을 복제하지 않았음

- 필드 라인은 실제 축구 경기장 규격(FIFA 경기 규칙의 표준 치수)을 비례로 줄인
  것이다. 어느 인쇄본에서 옮긴 값이 아니다
- 프레임(점수 트랙·게임 방법)은 ①의 배치를 따르지 않았다 — 점수 트랙은 별지
  부속으로, 게임 방법은 화면으로 옮겼다
  (`IDE-002`가 정한 보드/부속 분리 규격을 따른 결과다)
- 게임 방법 문장은 사용자가 구술한 규칙을 옮겨 쓴 것이다
- **선수 그림(`IDE-010`)도 새로 그렸다.** ①을 참고하지 않았다 — 저장소에
  두지도 않았으니 옮겨 그릴 자료 자체가 없었다. 아래 11절의 픽토그램은 옛
  인쇄본의 인물 그림과 무관한, 이 도안만의 단순 도형이다. 나중에 사용자가 ①
  사진을 다시 보여 주며 "선수마다 자세가 다르고 더 다이나믹했으면" 한다고
  해서 자세를 여러 개로 늘렸지만(2026-09-06), 옮겨 그린 것은 여전히 없다 —
  가져온 것은 "선수마다 다른 동작을 한다"는 구성뿐이다

## 11. 선수 마커와 전술 대형 (`IDE-010`)

마커는 `src/assets/games/soccer/artwork/player-markers.ts`가 짓는다.

**스타일 세트가 자세, 변형이 모양이다.** 세트는 자세마다 하나씩 있고
(`player-marker-run` · `player-marker-strike` … · `goalkeeper-marker`) 슬롯에
역할로 배정된다. 변형은 세 가지(`circle` · `illustration` · `outline`)로 세트마다
똑같이 있고, `marker-style` 슬롯 하나가 모든 세트를 동시에 바꾼다 — 사용자가
고르는 것은 모양이지 자세가 아니다.

세트를 자세마다 나눈 것은 취향이 아니라 구조 때문이다. 마커 아트워크는 변형에
붙고 변형은 세트에 붙으므로, 슬롯마다 다른 그림을 쓰려면 세트를 나누는 수밖에
없다. 세트가 달라도 변형 id와 크기는 같아 슬롯끼리 자세를 바꿔 끼워도 배치가
어긋나지 않는다. 빈 원은 자세와 무관해 **파일 하나를 모든 세트가 나눠 쓴다**.

### 속을 비운다 — 빈 원 (2026-09-05), 기본은 색칠용 선수 그림 (2026-09-06)

**6–7세 아이와 하는 판**이라는 것이 이 도안의 전제로 들어왔다(사용자). 아이가
번호를 직접 쓰고 색칠하는 것 자체가 놀이의 일부라, 인쇄물이 그 자리를 미리
채워 버리면 안 된다. 그래서 셋을 바꿨다:

`marker-style`의 **기본값은 색칠용 선수 그림(`outline`)** 이다(2026-09-06 사용자
요청). 같은 전제에 가장 맞는 모양이고 자세가 있어 판이 살아 보인다. 빈 원은
번호를 크게 쓰고 싶을 때 고르는 선택지로 남는다. 아래는 빈 원을 만들 때의
기록이다.

| 무엇    | 전                      | 후                         |
| ------- | ----------------------- | -------------------------- |
| 원 채움 | 팀 색(`pc-marker-fill`) | **없음** — 흰 속, 테두리만 |
| 등번호  | 기본값 1–11이 인쇄됨    | **기본값 없음** — 빈 칸    |
| 원 지름 | 12mm                    | **15mm**                   |

- **테두리가 팀 색을 받는다**(홈 파랑 · 원정 빨강, 굵기 0.7mm). 채우지 않으면서
  두 팀을 가르는 유일한 길이다. 채움은 `none`이 아니라 **흰색으로 못 박는다** —
  비워 두면 밑에 깔린 필드 라인이 원을 가로지르고, 레이어의 팀 색을 물려받으면
  아이가 칠할 면이 메워진다.
- **등번호 슬롯을 `number`에서 `text`로 바꿨다.** `number` 슬롯은 빈 값을 받지
  못하는데 이 도안의 기본값은 비어 있어야 한다. 넣고 싶은 사람은 에디터에서
  넣을 수 있고, 값이 비면 렌더러가 글자를 아예 얹지 않는다(미리보기·인쇄 같은
  규칙).
- **팀 색 슬롯은 한 번 뺐다가 되살렸다.** 채움이 사라지자 색이 갈 곳이 없어
  뺐는데, 사용자가 "원의 색상은 빨강과 파랑으로 구분해 달라"고 해 테두리로
  되돌아왔다. 지금 쓰이는 곳은 **마커 테두리와 화살촉뿐**이다 — 점수 기록칸의
  색 막대는 2026-09-08에 뺐다(아래 참고).

### 크기가 네 번 움직였다

12 → 15 → 24 → **20mm**.

15mm였을 때 사용자가 **어릴 때 가지고 놀던 종이 축구판 사진**을 보여 줬다.
그 판에서 선수 그림은 **필드 짧은 변의 약 1/8**을 차지한다 — 우리 필드 짧은
변이 198mm이므로 약 24mm다. 그 값으로 키웠다가, 실제로 그려 놓고 보니 커서
**20mm로 되돌렸다**(사용자 요청).

그래서 지금 값은 **상한이 아니라 취향에 맞춘 값**이다. 24mm를 담으려고 벌려 둔
여유가 두 곳에 남아 있다:

- 레인 사이 최소 간격 **26mm**(17 → 26으로 벌렸다, 11절 아래). 20mm에는 6mm가
  남는다. 되돌리지 않은 것은 마커 사이가 넉넉한 편이 아이 손에 낫기 때문이다.
- 골 에어리어 깊이 **26mm**(16 → 26). 골키퍼 레인 x=19에서 `19 + 10 = 29`이므로
  3mm가 남는다.

이보다 키우려면 필드를 넓히는 수밖에 없는데 이미 A4를 꽉 채웠다.

선수 그림은 **18×22**로 원보다 조금 작다. 두 모양은 같은 슬롯에 바꿔 끼우는
것이라 크기가 비슷해야 배치 인상이 유지되고, 그림이 세로로 길어 원과 폭을 맞추면
세로가 먼저 필드를 벗어난다. 겹침 판정은 둘 중 큰 쪽(원 20mm)이다.

#### 선수마다 자세가 다르다 (2026-09-06)

처음에는 달리는 그림 한 벌로 스물두 명을 다 찍었다. 사용자가 보여 준 옛
인쇄본(1절 ①)은 선수마다 자세가 달라 판이 살아 보이는데, 같은 그림이 줄지어 선
우리 판은 심심하다는 지적이었다.

그래서 그림을 **뼈대에서 짓는다**. `artwork/player-markers.ts`의 `POSE_ANGLES`가
관절 각도만 적고(상체 기울기 · 팔꿈치 · 무릎), `figureShapes`가 그 각도로 도형을
낸다. 자세를 더할 때 도형을 새로 그리지 않고 각도 여덟 개를 적으면 된다.

지금 있는 자세는 달리기 · 질주 · 슛 · 패스 · 헤딩 · 수비 여섯에 골키퍼
세이브 하나다. 배정은 **기본 대형(4-4-2)의 역할**을 따른다(`index.ts`의
`POSE_BY_PLAYER`) — 골키퍼는 세이브, 수비는 낮은 자세, 중원은 달리기·패스,
공격은 슛과 헤딩이다. 사용자가 고르는 값이 아니다.

자세는 **슬롯**에 붙지 대형에 붙지 않는다. 대형을 바꾸면 같은 선수가 다른
레인으로 옮겨 가 역할과 자세가 어긋날 수 있지만, 자세는 판을 살리는 장식이지
규칙에 쓰이는 값이 아니다 — 대형마다 다시 배정하면 프리셋을 고를 때마다 그림이
튄다.

##### 상자에 맞춰 넣는다

자세마다 팔다리가 뻗는 범위가 다르다. 각도만 적어 두면 어떤 자세는 마커 상자를
넘고(질주가 그랬다) 어떤 자세는 한쪽으로 쏠린다. 상자를 넘으면 이웃 마커와
겹친다 — 겹침 판정은 상자로만 하기 때문이다. 그래서 각도를 손으로 맞추는 대신
`fitToBox`가 나온 도형의 경계를 재서 필요한 만큼만 줄이고 상자 한가운데로
옮긴다. 마커의 기준점이 상자 중심이므로, 가운데 맞춤은 곧 "슬롯 좌표에 선수가
선다"는 뜻이기도 하다.

`player-markers.test.ts`가 모든 자세에 대해 상자를 넘지 않는지 확인한다.

#### 그림이 보는 방향

그림은 **오른쪽(공격 방향)을 본다**. 발끝·머리·앞으로 뻗은 팔이 다 그쪽이다.
원정 마커는 렌더러가 통째로 뒤집으므로 두 팀 다 상대 골대를 본다.

한 번 반대로 읽힌 적이 있다(2026-09-06). 그때 그림은 손으로 찍은 좌표 한 벌
이었는데, 크게 뻗은 다리를 앞으로 내딛는 다리로 그린 것이 사람 눈에는 차고 나온
**뒷다리**로 읽혔다 — 두 팀 다 자기 골대를 보고 선 꼴이었다. 지금은 무릎·팔꿈치
각도를 따로 주므로 굽힌 앞다리와 뻗은 뒷다리가 구분되고, 발끝이 방향을 못 박는다.

### 색이 붙는 자리 — `pc-marker-team` 레이어

렌더러는 이 레이어 하나의 **`fill`과 `stroke`를 둘 다** 갈아 끼운다. 마커에
따라 색이 붙는 자리가 다르기 때문이다:

| 변형               | 색이 붙는 곳         | `filled` |
| ------------------ | -------------------- | -------- |
| 빈 원              | 테두리 · 화살촉      | `false`  |
| 선수 그림          | 실루엣 전체(채움)    | `true`   |
| 선수 그림 · 색칠용 | 부위마다 두른 윤곽선 | `false`  |

색칠용 윤곽선은 실루엣과 **같은 도형**을 속만 비워 낸 것이다(2026-09-06 사용자
요청) — 아이가 칠할 판이니 그림도 칠할 수 있어야 한다. 몸을 부위마다 닫힌
도형으로 내는 것이 두 벌을 한 뼈대로 뽑는 열쇠다: 실루엣에서는 색이 같아 이음매가
안 보이고, 윤곽선에서는 그 경계가 그대로 옷 선이 된다. 뒤쪽 팔다리 → 앞쪽 다리
→ 반바지 → 목 → 셔츠 → 앞쪽 팔 → 머리 → 머리카락 차례로 그려 흰 채움이 뒤
도형의 안쪽 선을 덮는다.

#### 옷을 입히고 모서리를 둥글렸다 (2026-09-06)

처음 뼈대 그림은 각진 사각형 여섯 개를 이은 것이라 로봇처럼 보였다("좀더 양질의
퀄러티로" — 사용자). 두 가지로 고쳤다:

- **모서리를 둥글린다.** 다각형마다 `roundMm`을 두고 꼭짓점을 제어점 삼은 2차
  곡선으로 잇는다(`roundedPath`). 팔다리 끝은 폭의 절반으로 둥글려 캡슐이 되고
  무릎·팔꿈치가 부드럽게 꺾인다. 인쇄 파서는 `Q`를 3차 곡선으로 받아 PDF까지
  곡선 그대로 간다.
- **옷과 손, 머리카락을 입힌다.** 반팔 소매·반바지·양말·신발·손·앞머리를
  살 위에 얹는 도형으로 더했다. 실루엣에서는 한 덩어리로 녹고, 윤곽선에서는
  옛 인쇄본처럼 셔츠·반바지·양말·신발이 갈려 아이가 따로 칠할 수 있다. 눈·입은
  그리지 않는다 — 5mm 머리에 0.45mm 선으로 찍으면 얼룩이 된다.
- 비율은 옛 인쇄본의 아이들처럼 머리가 크고 팔다리가 짧게 잡았다(머리 지름 ≈
  키의 1/4). 신발은 정강이에 직각으로 내서, 슛처럼 정강이가 앞으로 뻗으면 발끝이
  위를 본다.

윤곽선 굵기는 0.7 → **0.45mm**다. 손·양말·앞머리처럼 1mm 안팎의 부위가 생겨
0.7mm를 두르면 그 부위가 선으로 메워진다. 필드 최소 배율(0.5)에서 0.23mm로
인쇄 하한(0.12mm) 위다.

`filled`는 도안이 선언하는 값이고(`schema/styles.ts`), **등번호 색을 가른다** —
채워진 마커는 배경 밝기에 맞춰 반전하고, 빈 원은 배경이 흰 종이라 팀 색을 그대로
쓴다. 빈 원에 반전 규칙을 쓰면 파란 테두리 원 안에 **흰 글자**가 찍혀 사라진다.

레이어 안에서 색을 받지 **말아야** 하는 도형은 제 값을 명시해 덮어쓴다 — 빈 원의
`fill="#ffffff"`가 그것이다.

### 흑백에서 팀·골키퍼가 구분되는 이유

팀 색이 명도가 비슷하면 흑백에서 구분되지 않는다. 색에 기대지 않는 표식이
따로 있다:

- **팀** — 마커가 공격 방향을 본다. 원정 마커는 세로 중심선 기준으로 **좌우
  반전**해서 쓴다 — 대형 좌표를 `mirrorPositions`로 뒤집는 것과 같은 이치다.
  반전은 도안이 `group.mirrorMarkers`로 선언하고 렌더러가 수행한다(2026-09-05
  구현) — 미리보기는 `transform="scale(-1,1)"`, 인쇄는 좌표를 뒤집는다
  (`src/lib/print/draw.ts`의 `mirrorDrawsX`).
  두 팀이 필드 전체에 섞여 서기 때문에 **위치로는 팀을 알 수 없고**, 흑백으로
  뽑으면 테두리 색도 구분되지 않는다.
  방향을 싣는 자리는 변형마다 다르다. **빈 원**은 대칭이라 실을 데가 없어
  오른쪽에 화살촉을 붙였다(원을 키울 때 같이 키웠다 — 돌출 1.1 → 1.5mm, 각도
  ±22° → ±26°). **선수 그림**은 자세 자체가 비대칭이라 화살촉이 없다 — 발밑에
  삼각형을 하나 더 붙여 보니 몸이 가리키는 방향과 경쟁해 오히려 방향이
  흐려졌다(2026-09-06). 자세가 충분히 치우쳤는지는 테스트가 "뒤집었을 때 얼마나
  어긋나는가"로 잰다.
- **골키퍼** — 빈 원은 안쪽에 테를 하나 더 둘러 과녁 모양을 만들고, 선수 그림은
  장갑 낀 손과 세이브 자세로 필드 선수와 다른 실루엣이 된다. 아이가 칠할 면은
  두 테 사이에 링으로 남는다.

두 표식 다 `src/assets/games/soccer/__tests__/player-markers.test.ts`가 기하로
확인한다(비대칭인지, 골키퍼 원이 하나 더 있는지, 원이 비어 있고 테두리가 굵은지).
**⚠︎ 실제 인쇄물에서 눈으로 구분되는지는 프린터가 없어 확인하지 못했다.**

등번호는 마커 SVG에 그리지 않는다. 슬롯 값이라 렌더러가 `valueFontSizeMm`
크기로 얹는다. 모든 스타일 세트가 7mm다 — 원이 커지면서 5 → 6 → 7mm로 올렸고,
필드의 `minScale`(0.5)에서 3.5mm라 2.5mm 하한에 여유가 넉넉하다(6절 참고).

### 전술 대형

4-4-2 · 3-5-2 · 4-3-3 · 4-2-3-1 네 개가 있다. 좌표는 `src/assets/games/soccer/index.ts`의
`FORMATIONS`에 있고, 배열의 첫 자리는 언제나 골키퍼다 — 슬롯 id(`home-player-1`
등)가 대형과 무관하게 고정이라, 어느 프리셋을 골라도 1번 슬롯이 골키퍼여야
어긋나지 않는다. 원정 진영은 `mirrorPositions`로 좌우 반전해 만든다.

#### 골키퍼를 뺀 열 명이 반반으로 선다 (2026-09-06)

사용자 요청 — "골키퍼 제외하고 자기 진영에 5명, 상대 진영에 5명". 필드를
반으로 가르면 어느 쪽이든 홈 다섯 · 원정 다섯 · 골키퍼 하나가 있다. 2026-09-05의
"섞여 서기"와 같은 방향이되, 그때는 대형마다 반반이 아니었다(4-4-2가 자기
진영 여덟). 지금은 **모든 대형이 반반**이고 테스트가 그것을 센다.

레인은 열둘이고 홈·원정이 번갈아 쓴다 — 홈 19 · 45 · 114 · 160 · 206 · 229,
원정은 그 거울상. 이웃 간격 23mm(양 끝 26)가 마커 폭 20mm보다 넓어 두 팀의
y가 같아도 겹치지 않는다. 더 벌릴 자리는 없다 — 골키퍼 사이 259mm에 레인
열둘이 들어가야 해서 23이 상한이다. 마커를 키우면 이 배치가 깨진다.

대형마다 중원이 하프라인을 사이에 두고 갈린다. 4-3-3은 수비 넷 + 수비형 중원
하나가 자기 진영, 중원 둘 + 공격 셋이 상대 진영이다. 대형은 현대 축구에서
흔한 여섯 개다 — 4-3-3(기본) · 4-2-3-1 · 4-4-2 · 3-5-2 · 3-4-3 · 4-1-4-1.
버튼 여섯 개 × 두 팀이 팀 줄을 다 먹어 **셀렉트 박스**로 바꿨고, 마커를
손으로 옮기면 "직접 배치"로 보인다.

같은 날 잠깐 각 팀을 자기 진영 절반에 몰아 세웠다가(요청을 "열한 명 다 자기
진영"으로 잘못 읽었다) 곧 바로잡았다.

#### 두 팀은 필드 전체에 섞여 선다 (2026-09-05 재작업)

처음에는 두 팀을 각자 진영 절반에 세웠다. 실제 축구의 킥오프 배치를 따른
것이었는데, **그 배치로는 경기를 할 수 없었다.**

선수 마커는 운동장에 인쇄되어 움직이지 않는다. 규칙은 패스가 자기 팀 선수에게
닿아야 이어지고, 슛도 공이 자기 팀 선수 위에 있을 때만 되게 되어 있다. 상대 골대
쪽에 자기 팀 선수가 하나도 없으면 공을 앞으로 보낼 방법이 없다 — 홈 팀 최전방이
x=130이고 상대 골대가 골라인 근처라, 슛을 하려면 한 번에 140mm 넘게 튕겨야 했다.

그래서 두 팀이 **번갈아 서도록** 다시 잡았다. x는 `FORMATION_LANES`의 다섯 값만
쓰고, 원정은 그것을 뒤집은 값을 쓴다:

```
홈    19  45          124            199   225
원정        72   98          173          252 278
```

- 레인 사이가 최소 26mm로 마커 폭(20mm)보다 넓다. **두 팀이 서로 다른 대형을
  골라도 마커가 부딪히지 않는 근거가 이것이다** — y를 어떻게 잡든 안전하므로
  대형을 늘릴 때 조합을 다시 따지지 않아도 된다.
- 홈 최전방(x=225)에서 상대 골라인까지 66mm다. 슛이 성립하는 거리다.
- 골키퍼 x(19 · 278)는 골문 바로 앞이면서 **골 에어리어 안**이다(위 참고).
  30 → 14 → 19로 두 번 움직였다 — 골대를 골라인 밖으로 뺄 때 당겼고, 마커가
  24mm로 커지면서 다시 조금 밀렸다(2026-09-05).
- 레인 값을 마커 크기에 맞춰 다시 잡았다. 간격 다섯이 대칭이라
  (`d−g`, `297−f−d`, `f−a`, `m+a−297`, `297−2m`) 그 값들만 26 이상이면 열
  레인 전체가 안전하다.
- **골키퍼를 뺀 10명이 운동장 1/3마다 둘 이상**이다. 한 구역에 몰리면 그 밖에서
  패스를 받아 줄 사람이 없어 공이 앞으로 나가지 못한다. 4-2-3-1의 공격형
  미드필더 레인(200)이 중원이 아니라 상대 진영에 있는 이유가 이것이다 —
  중원에 두면 상대 진영에 공격수 한 명만 남아 4-4-2(2명)·4-3-3(3명)보다
  앞이 헐거워진다.

| 대형    | 1/3마다 선수 수 |
| ------- | --------------- |
| 4-4-2   | 4 / 4 / 2       |
| 3-5-2   | 3 / 5 / 2       |
| 4-3-3   | 4 / 3 / 3       |
| 4-2-3-1 | 4 / 2 / 4       |

경기가 성립하는 조건은
[`__tests__/formations.test.ts`](../src/assets/games/soccer/__tests__/formations.test.ts)가
지킨다 — 각 팀이 상대 진영에 선수를 두는가, 최전방이 슛 사거리 안인가, 모든
대형이 정해진 레인만 쓰는가. 스키마 검증(`parseGame`)은 여기에 더해 **다른
그룹의 프리셋과도** 겹치지 않는지 본다.

## 12. 남은 실물 확인

프린터가 없어 채우지 못한 것들이다. `IDE-004`·`IDE-010`에 ⚠︎로 남아 있다.

- [ ] 100%로 뽑아 운동장이 297×210mm인지 자로 재기
- [ ] 골대 전개도를 오려 접어 쟁반이 서는지, 공이 입술을 타고 들어와 안에
      멈추는지 — **가위만으로 되는지**가 이번 판의 핵심 확인 사항이다
- [ ] **1·2·3이 사슬처럼 물리는지**(2026-09-08에 서로 피하던 것을 뒤집었다).
      귀가 탭을 4mm 타고 넘어가 무는지, 그 둘을 겹이 함께 덮는지를 본다.
      헐거우면 겹을 8 → 10mm로 늘리거나 탭을 10 → 12mm로 늘린다 — 귀 물러남(6mm)은
      이미 가위 하한이라 더 못 줄인다
- [ ] **넉 겹이 된 구석에서 겹이 닫히는지.** 귀와 탭이 겹치는 4×8mm 자리는 벽 +
      탭 + 귀 + 겹으로 종이가 넉 겹이다. 처음에 둘을 갈라 놓았던 이유가 이것이라,
      두꺼운 종이에서 겹이 들뜨면 그 종이에서는 탭을 줄이는 쪽이 맞다
- [ ] **번호(1·2·3)만 보고 차례를 따라갈 수 있는지.** 이름을 빼고 번호만 남겼으므로
      (2026-09-08 사용자 요청), 시트 머리글 한 줄과 도해 ③이 그 대응을 실제로
      전달하는지 아이와 같이 확인한다
- [x] **옆벽 사선이 쓰레받기 모양을 만드는지** — 사용자가 손으로 접어 확인했다
      (2026-09-08). 도안의 사선은 그 접기를 좌표로 옮긴 것이다
- [ ] **넘긴 삼각형이 귀와 겹을 실제로 무는지.** 사선 접기가 잠금을 겸하는데,
      종이가 두꺼우면 삼각형이 도로 펴질 수 있다
- [ ] **뚜껑을 반으로 접은 두 겹이 실제로 버티는지**(2026-09-08 사용자 지적 —
      "뚜껑이 한 겹이라 약해"로 넣었다). 접힌 앞 모서리가 곧게 서는지, 두 겹이
      벌어지지 않는지를 본다. 벌어지면 겉장 끝에 물림 탭을 내야 하는데 그러면
      "가위와 접기만"이 깨지므로, 그 전에 두꺼운 종이를 먼저 시도한다
- [ ] **겹친 뚜껑이 옆벽 사이에 들어가는지.** 아래층(천장 절반)이 골문 폭과
      같은 55mm라 벽 안쪽에 딱 맞는다 — 걸리면 뚜껑 폭을 1mm 줄인다
- [ ] **뒤쪽 절반만 덮고도 튄 공이 안에 남는지.** 통째로 덮으면 안이 안 보이고
      절반만 덮으면 앞으로 튈 수 있다 — 둘 사이에서 절반을 골랐다(2026-09-08
      사용자 요청). 자주 튀어 나가면 뚜껑 깊이를 16 → 22mm쯤으로 되돌린다
- [ ] 쟁반 뒤쪽 26mm가 종이 밖 책상에 놓일 때, 그리고 운동장을 스케치북에 붙여
      쟁반이 한 단 낮아질 때 공이 입술에서 걸리지 않는지
- [ ] 공 12mm가 연필로 튕기기 적당한지 — 크거나 작으면 `BALL.diameterMm`을 고친다
- [ ] 일반 용지에서 필드 표면이 얼마나 버티는지
- [ ] 각 파트의 `minScale`에서 글자가 실제로 읽히는지
- [ ] 선수 마커를 흑백으로 뽑았을 때 화살촉(팀)·이중 테(골키퍼)가 실제로
      눈에 띄는지 — 지금은 도형이 기하로만 비대칭임을 확인했다
- [ ] 지름 20mm 원에 6–7세 아이가 번호를 쓰고 색칠할 만한지 — 24mm까지는 지금
      배치로 담을 수 있다(레인 간격 26mm). 그 이상은 필드를 넓혀야 하는데 이미
