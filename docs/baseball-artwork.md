# 야구 게임판 도안

`IDE-014`의 작도 결과다. 치수의 **원본은 코드**
(`src/assets/games/baseball/dimensions.ts`)이고 이 문서는 왜 그 값이 되었는지를
적는다. 둘이 어긋나면 코드가 맞다.

인쇄 규격은 [`print-spec.md`](print-spec.md), 도안 데이터 모델은
[`game-authoring.md`](game-authoring.md)를 따른다. 축구 게임판과 겹치는 규약
(레이어 id·마커 중심 기준점·자세 세트)은 [`soccer-artwork.md`](soccer-artwork.md)에
먼저 적혀 있다 — 여기서는 **다른 점만** 적는다.

---

## 1. 만드는 법

```
src/assets/games/baseball/
  dimensions.ts      ← 모든 실측 치수. 고칠 곳은 여기 하나다
  rules.ts           ← 게임 방법 텍스트
  artwork/           ← 파트별 SVG 생성기
  index.ts           ← 도안 정의 (dimensions.ts를 읽는다)
src/assets/shared/
  svg.ts             ← SVG 문자열 도구 (축구와 공용)
  figure.ts          ← 인물 그림 엔진 (축구와 공용)
public/games/baseball/*.svg   ← 산출물. 커밋한다
```

```bash
npm run artwork baseball   # 이 게임의 SVG만 다시 만든다
npm run artwork            # 모든 게임
npm run test:run
```

## 2. 원본

옛 인쇄본 둘을 바탕으로 했다. 〈프로야구판〉(값 30원)에서 부채꼴과 판정선의
얼개를, 〈별나라 BASEBALL〉에서 **큰 내야 다이아몬드와 아웃선**을 가져왔다
(둘 다 세로 포스터다). 원본에서 그대로 가져온 것:

- **부채꼴 야구장에 그려진 판정선** — 바깥 호가 "홈런선", 안쪽 호가 "2루타선",
  내야 마운드 앞 호가 "아웃선"이다.
- **흙색 띠로 그린 정규 규격의 내야 다이아몬드.** 〈별나라〉는 다이아몬드가 종이
  폭의 61%를 차지하고, 담장 쪽 부채꼴 귀퉁이는 종이 밖으로 나간다.
- **오려 세우는 선수** — 〈게임요령〉 1번이 "오려있는 선수를 일으켜 세워서 수비진을
  만든다"였다.
- **판 옆의 공격진 벤치와 스코어보드.**

**방향도 원본을 따른다 — A4 세로다.** 한 번 가로로 그렸다가 사용자가 세로로
되돌렸다(2026-09-08). 세로가 맞는 이유는 종이 모양이 아니라 **게임의 크기**다:
홈에서 담장까지가 멀수록 공을 날려 보낼 거리가 길어지고, 그 거리가 곧 안타와
홈런을 가르는 여유다. 가로로 눕히면 담장이 홈에서 180mm였는데 세로로 세우니
246mm가 됐다.

바꾼 것은 셋이다:

- **스코어보드를 별지로.** 판에 적으면 판이 한 경기밖에 못 산다(§6). 별지는 A4
  세로 한 장에 표 다섯 벌이다(2026-09-08 사용자 요청 — A5 두 벌로는 종이가 남았다).
- **판정을 규칙으로 못 박음.** 원본은 "수비진에 부딪히거나 아웃선을 못 나가면
  아웃"까지만 적고 나머지를 아이들 합의에 맡겼다. 합의가 매번 달라지면 형제끼리
  싸운다.
- **종이 밖은 파울.** 〈별나라〉는 "운동장에 닿지 않은 공은 아웃"이었는데 파울로
  눌렀다(2026-09-08 사용자 결정) — 세게 치는 아이가 매번 아웃을 당하면 게임이
  재미없어진다.

## 3. 파트와 치수

| 파트          | 종류        | 크기(mm)  | 배율 범위 | 표시            |
| ------------- | ----------- | --------- | --------- | --------------- |
| `field`       | `board`     | 210 × 297 | 0.5–4     | 없음            |
| `score-sheet` | `cutout`    | 210 × 297 | 0.7–2     | 오림선          |
| `stands`      | `buildable` | 287 × 165 | 0.8–2     | 오림선 · 산접기 |

`stands`는 **A4 가로 한 장에 두 팀 스무 명**이다(2026-09-08 사용자 요청). 앞서는
카드 열 장짜리 160×150 시트를 두 벌 뽑게 했는데, A4에 얹으면 종이가 절반 넘게
남았다. **스탠드는 커질 수 없다** — 판 위 마커 자리에 서는 물건이라 카드 폭이 마커
폭(20mm)에서 크게 벗어나면 내야에 여섯 명이 서지 못한다. 그래서 남는 자리를 키우기가
아니라 **두 번째 팀**으로 채웠다: 287×165는 카드 스무 장(25×60mm)을 10×2로 앉히고
줄마다 팀 이름 띠를, 위에 제목 띠를 얹은 크기다. **한 줄이 한 팀**이라 뽑는 장수가
두 장에서 한 장으로 줄었다(`defaultCopies` 1).

한 줄 열은 판에 서는 수비 여덟(§7.5)에 **포수와 지명타자**를 더한 한 팀 전부다.
둘 다 그라운드에 세우지 않지만 카드는 낸다 — **뒷면이 타자**라 카드가 곧 타순이기
때문이다(§7.6).

287×165는 A4 가로(297×210)에 5mm를 남기고 앉는다 — 인쇄 여백을 5mm까지 올려도
타일이 갈라지지 않는다.

## 4. 내야는 규격대로, 담장은 종이 밖으로

홈플레이트는 (105, 274)이고 모든 선이 그 점을 중심으로 그려진다. **종이 아래 끝에
최대한 붙였다**(2026-09-08 사용자 요청) — 남긴 23mm는 홈 뒤 **백네트 자리**다.
반지름 19mm인 호가 293mm까지 내려오고 종이 끝까지 4mm가 남는다. (처음에는 이
자리를 포수 마커가 정했는데, 같은 날 포수를 판에서 빼면서 백네트가 하한을
물려받았다.) 연필 쥔 손은 종이 밖 책상 위에 놓이면
되고, 그 대신 담장까지가 그만큼 멀어진다.

**내야 다이아몬드가 정규 규격(정사각형, 파울 각 90°)이다.** 한 변 95mm라
폭이 134mm로 종이 폭의 64%다 — 〈별나라 BASEBALL〉에서 잰 61%와 같은 크기다.
앞선 판은 부채꼴 전체를 종이에 넣으려고 파울 각을 ±36°로 눌렀는데, 사용자가
되돌렸다(2026-09-08): "홈플레이트와 1·2·3루의 내야 다이아몬드가 경기장 규격대로
충분히 표현되고, 확장되는 나머지는 A4를 벗어나도 된다."

그래서 **담장 쪽 부채꼴 귀퉁이는 종이 밖에 있다.** 종이에 남는 것은 내야 전체와
외야의 가운데 띠이고, 파울라인은 1·3루에서 뻗어 종이 좌우 끝(y=145)에서 잘린다.
종이 밖으로 나간 공은 판정할 곳이 없으니 파울이다(§5).

| 거리         | mm  |
| ------------ | --- |
| 홈 → 1·3루   | 95  |
| 홈 → 2루     | 134 |
| 홈 → 마운드  | 64  |
| 홈 → 아웃선  | 48  |
| 홈 → 2루타선 | 165 |
| 홈 → 홈런선  | 225 |
| 홈런선 위 띠 | 25  |

내야는 **흙색 띠**(1.6mm)로 그린다. 판정선(0.9mm)보다 굵고 색도 달라 "여기까지가
내야"라는 것이 한눈에 읽힌다. 홈–1루·홈–3루 변은 파울라인과 같은 자리라 파울라인은
베이스에서 종이 끝까지만 초록으로 긋는다 — 같은 자리에 두 선을 겹쳐 긋지 않는다.
베이스는 흰 채움의 정사각형으로 띠 위에 얹어 모서리가 베이스로 읽히게 했다.

## 5. 판정선 넷 — 색으로 가른다

게임 규칙 전체가 **판에 그려진 선 넷**으로 끝난다. 전부 홈을 중심으로 한 원호다 —
내야가 정규 규격이 되면서 담장도 실제처럼 홈에서 같은 거리에 두는 것이 맞고,
종이를 벗어나도 된다고 정한 지금은 타원으로 욱여넣을 이유가 없다.

| 선       | 색             | 반지름 | 넘으면                         |
| -------- | -------------- | ------ | ------------------------------ |
| 파울라인 | 초록 `#2f7d32` | —      | 파울                           |
| 아웃선   | 빨강 `#dc2626` | 48     | **못 넘으면** 아웃 (내야 땅볼) |
| 2루타선  | 파랑 `#1d4ed8` | 165    | 2루타 (안이면 안타)            |
| 홈런선   | 초록 `#2f7d32` | 225    | 홈런 (그 위 띠에 멈춰야 한다)  |

**선마다 색이 다르다**(2026-09-08 사용자 요청). 같은 색이면 어느 호가 어느 선인지
이름표를 읽어야 아는데, 공이 멈춘 순간 아이가 보는 것은 이름표가 아니라 색이다.
이름표도 선과 같은 색으로 붙여 흑백으로 뽑아 색이 사라져도 글자가 남는다.

**아웃선**은 〈별나라 BASEBALL〉 규칙 4번에서 왔다. 마운드 바로 앞(반지름 48)을
지나는 호를 다이아몬드 안에서만 그린다 — 힘없이 구른 공은 내야 땅볼 아웃이다.

**2루타선·홈런선은 종이보다 커서** 좌우 끝에서 잘린다. 인쇄 렌더러가 클립을
받지 않으므로 호를 잘리는 점에서 시작해 잘리는 점에서 끝낸다(`edgeCrossingYMm`).
홈런선은 종이 위 끝에서 25mm(좌우 끝에서는 48mm) 아래를 지나고, 그 위 띠가
홈런이 멈출 자리다 — 종이 밖으로 나가면 파울이라 담장 너머가 종이 안에 있어야
홈런이 나온다.

굵기는 넷이 같다(0.9mm). 타석·백네트 같은 장식선(0.5mm)보다 굵어 판이 선
무더기로 보이지 않는다.

## 6. 판 위에 남는 것 — S·O 카운터 하나

타순표(공격진 벤치)와 아웃·주자 표시칸을 파울 지역에 두었다가 **뺐다**(2026-09-08
사용자 요청 — "일단 없애고"). 그 자리를 비우니 홈플레이트를 종이 끝까지 내릴 수
있었다(§4).

대신 왼쪽 아래 파울 지역에 **스트라이크·아웃 카운터**를 넣었다(같은 날 요청).
처음에는 사용자가 적어 준 대로 S 둘 · B 넷 · O 셋이었는데, **실제로 해 보고
줄였다**(같은 날 확인 — "B는 필요없고, S와 O만 있으면 되고 카운트도 2개씩만
있으면 되더라"):

```
S ○ ○
O ○ ○
```

볼은 기본 규칙에 투구가 없어 셀 일이 없었다. 남은 둘이 **셋이 아니라 둘인** 이유는
따로 있다 — 스트라이크 셋째는 삼진 아웃이고 아웃 셋째는 공수 교대라, 마지막 하나를
놓는 순간 칸이 통째로 비워진다. 그러니 셋째 자리는 그릴 필요가 없다. 동전을 얹어
세고, 타자가 바뀌면 S를, 공수가 바뀌면 둘 다 치운다.

자리는 파울라인(y = x + 169) 아래다. 오른쪽 위 모서리(31.7, 255)가 그 선보다
54mm 아래이고 홈 언저리 선에 닿지 않는다. 볼 칸을 넣고 싶은 집은 종이 한쪽에
따로 센다(`rules.ts` 하우스 룰 절).

그 밖에 한 타석 동안 바뀌는 것은 동전이 기억한다:

- 주자 — 그 베이스 위에 동전을 얹는다.
- 이닝별 점수 — 별지 스코어보드. 판에 적게 두면 판이 한 경기밖에 못 산다.

파울라인 바깥 두 삼각형에는 "파울"이라고만 적어 두었다.

## 7. 선수 스탠드 — 텐트형

카드 한가운데를 산접기로 접으면 두 면이 마주 보며 ∧ 로 선다. **풀도 칼도 탭도
없다** — 축구 골대가 다섯 번 고쳐 가며 얻은 결론
([`soccer-artwork.md` §4](soccer-artwork.md))을 처음부터 따랐다.

위쪽 면은 그림을 **180° 돌려** 그린다. 접으면 그 면이 뒤로 넘어가 뒤집히므로,
미리 뒤집어 두어야 세웠을 때 양쪽에서 다 바로 보인다. 이름표는 앞면에만 넣는다 —
인쇄 렌더러가 요소 단위 회전을 받지 않아 글자는 돌려 그릴 수 없고, 세우면 어차피
한쪽 이름만 보인다.

그림은 **윤곽선으로만** 낸다. 두 팀이 한 줄씩 나눠 갖고 각자 칠하는 것을 전제로 한
부속이라 색을 미리 넣으면 그 전제가 깨진다. 대신 줄마다 "첫 번째 팀 / 두 번째 팀"
이름 띠를 얹어, 어느 줄을 어느 색으로 칠할지를 종이가 말하게 했다. 이 이름은 게임
그룹 이름(수비 팀 · 공격 팀)과 다르다 — 그쪽은 이닝마다 바뀌는 **역할**이고, 두 줄은
경기 내내 같은 아이가 갖는 **한 벌**이다.

## 7.5 포수와 타자는 그라운드에 없다 (2026-09-08)

사용자 요청으로 **포수와 타자를 판에서 뺐다.** 마커도, 스탠드도, 자세도 없앴다.

둘이 서는 자리가 곧 홈플레이트 언저리인데, 거기는 **공을 놓고 연필로 튕기는
자리**다. 포수를 홈 뒤에 세우면 힘없이 구른 공이 매번 포수에 맞아 아웃이 되고
(§2의 판정 — "수비 선수에 부딪히면 아웃"), 타석에 타자를 세우면 튕기는 손이
걸린다. 판이 규칙과 싸우는 자리라 사람을 치웠다.

따라 없어진 것:

| 없앤 것                           | 왜                                        |
| --------------------------------- | ----------------------------------------- |
| `defense-catcher` · `batter` 슬롯 | 판에 설 자리가 없다                       |
| `batter-circle` 빈 원             | 흑백에서 공수를 가를 표식이 필요 없어졌다 |
| 공격 팀 그룹과 그 색 슬롯         | 색을 받을 마커가 없다                     |
| `batting-area` 영역               | 그 안에 놓을 마커가 없다                  |

없앤 것은 **판 위의 자리**뿐이다. `crouch`(포수) 자세와 배트 소품은 한 번 걷어
냈다가 스탠드가 아홉 장·양면이 되면서 되살렸다(§7.6) — 다만 마커 스타일 세트가
아니라 **스탠드 전용 자세**(`STAND_ONLY_POSES`)로 두어, 판 마커 아트워크 파일은
여전히 나오지 않는다.

**남긴 것은 선이다.** 타석 둘·포수 자리·백네트는 그대로 그린다 — 실제 야구장에
그어진 선이고, 홈 뒤가 비면 판이 야구장으로 읽히지 않는다. 백네트는 파울 판정의
경계이기도 하다(§2).

수비 번호도 남겼다. 자리 순서(0…7)와 야구의 수비 번호(1·3·4…9)가 어긋나므로
`DEFENSE_POSITIONS`가 `number`를 따로 적고, 슬롯 이름표가 그것을 쓴다 — **2번이
비어 있는 것이 포수가 없다는 표시**다.

## 7.6 카드 열 장, 앞은 수비 뒤는 타자 (2026-09-08)

사용자 요청으로 스탠드를 다시 짰다: **한 팀 열 장**(투수·1루수·2루수·3루수·
유격수·좌익수·중견수·우익수·포수·지명타자)이고, **뒷면은 모두 방망이를 든
타자**이며 그 타격 자세가 **열 다 다르다.**

두 가지가 한꺼번에 풀린다.

- **포수와 지명타자가 카드로 돌아온다.** 그라운드에는 여전히 세우지 않지만
  (§7.5) 타순에는 들어간다. 지명타자는 **투수 대신** 치므로, 타순 아홉은
  투수 카드를 빼고 짠다 — 지명타자가 있는 이유가 그것이다.
- **판에서 뺀 타자가 뒷면으로 돌아온다.** 타자 마커는 홈플레이트 언저리를
  막아서 없앴는데, 뒷면 타자는 판 위가 아니라 **판 옆에 늘어서는 타순표**다.

타격 자세 열은 앞 다섯이 한 스윙을 시간 순으로 자른 것이고(대기 → 준비 →
스윙 → 임팩트 → 팔로스루) 나머지 다섯이 그 밖의 순간이다(번트 · 퍼올리기 ·
기다리기 · 겨누기 · 뛰어나가기). 열을 가르는 것은 대부분 `batDeg`다 — **배트가
어디를 가리키느냐**가 한 동작의 어느 순간인지를 말한다.

**앞면이 타자인 카드는 지명타자 하나뿐이다**(`bat-shoulder` — 배트를 어깨에
걸치고 선다). 이름표가 붙는 면인데 수비를 나가지 않는 자리라 수비 자세랄 것이
없어, 차례를 기다리는 타자를 그렸다.

`bat-wait`(기다리기)만 한 번 고쳐 잡았다. 배트를 몸 옆으로 곧게 내리니(94°)
다리를 관통한 것처럼 보였는데 — 배트는 다리보다 나중에 그려도 흰 채움이 겹치는
구간을 덮지 못한다 — 앞쪽으로 비스듬히(68°) 내보내 발 앞을 짚게 했다.

## 8. 선수 그림 — 공용 엔진에 야구 소품

뼈대에서 도형을 짓는 방식은 축구와 같고, 그 코드는 `src/assets/shared/figure.ts`로
꺼내 두 게임이 나눠 쓴다. 야구가 새로 낸 것은 **각도표와 소품 넷**뿐이다:

| 소품           | 어떻게                                                        |
| -------------- | ------------------------------------------------------------- |
| 모자           | 머리카락 자리를 대신하는 돔 + 챙. 상체 기울기만큼 같이 기운다 |
| 글러브         | 손끝에 얹는 둥근 네모(2.9mm). 축구 골키퍼 장갑(2mm)보다 크다  |
| 배트           | 손잡이에서 배럴로 굵어지는 막대. 방향은 자세가 직접 적는다    |
| 포수 장비      | 마스크(헬멧 + 그물) · 가슴 보호대 · 정강이 보호대 (§8.5)      |
| 긴 바지·스타킹 | `pantsRatio` 0.92 · `sockRatio` 0.9 (축구는 0.55 · 0.48)      |

배트 방향을 팔 각도에서 유도했더니 **어깨 위로 세운 배트가 머리를 가로질러
얼굴을 지웠다.** 그래서 자세가 `batDeg`를 직접 적고, 배트를 머리보다 먼저 그려
머리의 흰 채움이 겹치는 구간을 덮게 했다. (타자를 판에서 빼며 한 번 걷어 냈다가
스탠드 뒷면이 타자가 되면서 되살린 소품이다 — §7.5 · §7.6.)

자세는 **판 마커 다섯 + 스탠드 전용 열**이다.

| 어디에 쓰나       | 자세                                  | 아트워크 파일 |
| ----------------- | ------------------------------------- | ------------- |
| 판 마커           | `pitch`·`field`·`throw`·`catch`·`run` | 나온다        |
| 스탠드 앞면(포수) | `crouch`                              | 안 나온다     |
| 스탠드 뒷면       | `bat-ready` … `bat-dash` 아홉         | 안 나온다     |

판 마커 자세는 **포지션에 배정된다**(`DEFENSE_POSITIONS`) — 사용자가 고르는 값이
아니다. 사용자가 고르는 것은 모양(빈 원 · 그림 · 색칠용)이고, 선택 슬롯 하나가
여덟 자리를 동시에 바꾼다. 스탠드 전용 자세는 스타일 세트가 아니라서 마커
아트워크로 나오지 않고, 스탠드 생성기가 자세 id로 도형을 바로 받아 쓴다
(`fittedShapes`).

**편은 판이 아니라 스탠드에서 갈린다.** 축구는 두 팀이 필드에 섞여 서서 마커를
좌우 반전해 편을 갈랐지만(`mirrorMarkers`), 야구 판에 서는 것은 수비 여덟뿐이다.
그래서 반전도, 흑백에서 공수를 가를 표식도 필요 없다 — 손에 든 것은 전부
글러브이고 빈 원도 한 가지다. 두 팀이 색으로 갈리는 자리는 오려 세우는 스탠드다(§7).

## 8.5 포수만 정면으로 앉는다 (2026-09-08)

사용자 요청으로 포수를 다시 그렸다: **마스크와 보호 장비를 걸치고, 바른 자세로
정면으로 앉는다.**

옆에서 본 쪼그린 자세로는 "웅크린 야수"와 구분되지 않았다. 얼굴을 그리지 않는
그림이라 포수를 포수로 만드는 것은 **장비의 실루엣**뿐인데, 옆모습에서는 그
실루엣이 팔다리에 가린다. 정면으로 앉히니 마스크·가슴·정강이가 한 화면에 다
보인다.

각도표는 그대로 쓴다. 다른 자세는 모두 오른쪽을 보고 서지만, 포수는 팔다리
각도를 **좌우 대칭**(θ와 180−θ)으로 적어 정면이 된다 — 같은 관절 계산이 그대로
정면 그림을 만든다. 상체는 세운다(`leanDeg` 0, "바른자세").

새로 그린 도형은 셋이다.

| 장비          | 어떻게                                                                |
| ------------- | --------------------------------------------------------------------- |
| 마스크        | 머리보다 큰 헬멧 원(3.05mm) 위에 그물 테를 얹고 살 둘을 가로로 지른다 |
| 가슴 보호대   | 어깨선 밖으로 0.6mm 나가는 사다리꼴 + 이음매 둘                       |
| 정강이 보호대 | 무릎에서 발목까지 덮는 통(2.9mm) + 무릎 덮개 원                       |

**그리는 차례가 곧 겹치는 차례다.** 윤곽선 변형에서는 나중 도형의 흰 채움이 앞
도형을 덮으므로, 보호대는 팔다리·셔츠 뒤에 두어 "입은 것"이 되게 했다. 그물살은
가장 마지막이다 — 살이 보이는 것이 마스크로 읽히는 유일한 단서라 선 굵기(0.45)
보다 얇게 두지 않았다.

두 발은 바깥을 본다. `shoeShape`은 발끝을 정강이에 **직각**으로 내므로 각도만
뒤집어서는 왼발이 오른쪽을 보는데, 왼쪽 신발만 발목 x를 축으로 좌우를 뒤집어
(`mirrorX`) 해결했다.

## 9. 수비 시프트

축구의 전술 대형과 달리 **팀별로 한 벌씩 필요하지 않다.** 필드에 서는 것은 수비
여덟뿐이라 프리셋도 수비 그룹에만 있고, `formationId`도 쓰지 않는다 — 프리셋 UI가
`label`만으로 읽히는지 확인하는 첫 게임이다.

| 시프트          | 무엇이 다른가                                |
| --------------- | -------------------------------------------- |
| 기본 수비       | 슬롯 기본 좌표이기도 하다                    |
| 내야 전진       | 내야 넷이 홈 쪽으로 나온다(번트·스퀴즈 대비) |
| 장타 경계       | 외야 셋이 담장까지, 코너 내야가 라인 쪽으로  |
| 당겨치기 시프트 | 내야·외야가 통째로 1루 쪽으로 몰린다         |

어느 시프트든 **외야 셋 · 내야 다섯**을 지킨다(2루타선 기준). 외야수는 2루타선과
홈런선 사이(홈에서 180–220mm)에 서고, 2루수·유격수는 1·2루 / 2·3루 베이스라인
**뒤**에 선다. 그 조건이 깨지면
한쪽으로 친 타구를 잡을 사람이 없어 경기가 성립하지 않는데, 스키마는 겹침만 보고
그것까지는 알지 못한다 — 그래서 도안 쪽 테스트
(`src/assets/games/baseball/__tests__/artwork.test.ts`)가 지킨다.

## 11. 남은 실물 확인

- ⚠︎ 텐트형 스탠드가 실제로 서는가 — 카드 25×60mm, 보통 프린터 용지 기준.
- ⚠︎ 튕긴 공이 세운 스탠드에 부딪혔을 때 스탠드가 넘어지는가(넘어져도 아웃 판정에는
  지장이 없지만 매번 다시 세워야 하면 놀이가 끊긴다).
- ⚠︎ 아웃선 48mm·2루타선 175mm·홈런선 249mm가 재미있는 간격인가 — 아웃·안타·
  2루타·홈런의 빈도. 특히 홈런선 위 띠(25mm)에 공을 멈출 수 있는가.
- ⚠︎ 종이 밖으로 나가는 공이 얼마나 잦은가 — 잦으면 "종이 밖 = 파울"이 게임을
  지루하게 만든다. 그때는 홈런선을 내리거나 A3로 뽑는다.
- ⚠︎ 홈플레이트가 종이 끝에서 23mm라 연필 쥔 손이 책상 위에 놓인다 — 책상 끝에
  종이를 붙여 놓아야 하는지, 스케치북에 붙이면 표지가 걸리는지.
- ⚠︎ 포수·타자를 뺀 뒤(§7.5) 홈 언저리가 실제로 손 놀리기 편해졌는가, 그리고
  수비 여덟으로도 타구를 잡을 사람이 모자라지 않는가.
