# 세계일주 주사위놀이 도안

`IDE-015`의 작도 결과다. 치수의 **원본은 코드**
(`src/assets/games/world-tour/dimensions.ts`), 도시와 경로의 원본도 코드
(`src/assets/games/world-tour/cities.ts`)이고 이 문서는 왜 그 값이 되었는지를
적는다. 둘이 어긋나면 코드가 맞다.

인쇄 규격은 [`print-spec.md`](print-spec.md), 도안 데이터 모델은
[`game-authoring.md`](game-authoring.md)를 따른다. 축구·야구와 겹치는 규약
(레이어 id·표시선)은 [`soccer-artwork.md`](soccer-artwork.md)에 먼저 적혀 있다.

## 1. 만드는 법

```
src/assets/games/world-tour/
  dimensions.ts      ← 모든 실측 치수. 고칠 곳은 여기 하나다
  cities.ts          ← 도시 113개 · 경로 차례 · 프리셋 등급 · 특수칸
  projection.ts      ← 로빈슨 도법 · 태평양 중심 · 지도 끝 분할 (순수 계산)
  rules.ts           ← 게임 방법 텍스트
  artwork/
    land.json        ← Natural Earth 해안선 (단순화본, 생성됨)
    landmask.ts      ← 땅·바다 1mm 격자
    layout.ts        ← 칸 배치 — 점은 제자리, 원은 바다로
    board.ts         ← 게임판 (도시 목록에서 그린다)
    dynamic.ts       ← 값(켠 도시·차례·지도만) → 판. 서버 렌더러 등록소가 부른다
    pieces.ts        ← 말과 주사위 한 장 (아래 둘을 모은다)
    tokens.ts        ← 말 여섯
    dice.ts          ← 종이 주사위 전개도
  search/
    world-cities.json ← Natural Earth 세계 도시 7,342곳 (생성됨, 서버 전용)
    search.ts        ← 풀 + 세계 도시 검색
  index.ts           ← 도안 정의
public/games/world-tour/*.svg   ← 산출물. 커밋한다
scripts/fetch-natural-earth.mts ← land.json을 다시 만든다 (네트워크 필요)
```

```bash
npm run artwork world-tour   # 이 게임의 SVG만 다시 만든다
npm run fetch:land           # 해안선 데이터를 다시 받는다 — 보통 돌릴 일 없다
npm run fetch:cities         # 검색용 세계 도시 데이터를 다시 받는다 — 마찬가지
npm run test:run
```

위 띠에 제목과 특수칸 범례, 가운데에 세계지도와 화살표로 이어진 칸, 아래에

- **특수칸은 색 상자.** 급행 노랑 · 후퇴 분홍은 원본 색이다.
- **태평양 중심 지도.** 원본도 유럽이 왼쪽 끝, 북아메리카가 오른쪽 끝이다.
- **종이 주사위와 말은 오려 만든다.**

원본과 다르게 한 것(2026-09-08 사용자 결정):

- **그림 지도 대신 실제 지형.** Natural Earth 해안선이다.
- **도시 수를 고른다** — 50 · 60 · 70 · 80 · 90 · 100. 원본은 63칸 고정.
- **판 크기가 도시 수를 따른다** — A4 · A3 · A2. 원본은 4절 한 장.
- **서울 출발, 제주를 거쳐 서울 도착.** 원본은 일본에서 출발해 웰링턴에서 끝난다.
- 도시 이름만 적고 나라는 적지 않는다. 나라는 지도 위 위치가 말한다.

## 3. 지도

### 3.1 투영 — 로빈슨, 동경 150° 중심

- **로빈슨**: 등장방형은 고위도가 크게 늘어나 북극해 구간의 칸이 실제보다 멀어
  보이고, 메르카토르는 그린란드가 아프리카만 해진다. 로빈슨은 학교 지도책의
  세계 전도가 쓰는 절충안이라 아이 눈에 익다. 위도 5°마다의 표를 선형 보간한다.
- **동경 150° 중심**: 서울 → 태평양 → 남아메리카가 끊기지 않아야 한다. 0° 중심
  지도에서는 이 첫 구간이 종이 좌우로 갈라진다. 지도의 좌우 끝은 서경 30°다 —
  아이슬란드(24°W)는 왼쪽에 온전히 남고, 브라질 동쪽 끝(35°W)은 오른쪽에 남는다.
  그린란드와 남극은 갈라진다. 어느 중심을 잡아도 둘 중 하나는 갈라진다.

### 3.2 지도 끝에서 자르기

폴리곤 고리의 경도를 중심 기준 상대 경도로 옮기고, 이웃한 점이 180°보다 크게
뛰지 않도록 ±360°를 더해 연속선으로 만든 뒤(`unwrapRing`), ±360° 옮긴 사본
셋을 각각 [−180°, 180°]로 잘라 모은다(`splitAtEdges`). 지도 끝에 걸친 땅은
두 조각이 된다.

**극을 감싸는 고리(남극)** 는 한 바퀴 돌아 양 끝이 360° 벌어진다. 그대로 닫으면
닫는 변이 대륙을 가로지른다. 고리를 지도 끝 자오선을 지나는 자리에서 다시
시작하게 돌리고 양 끝에서 극점으로 내려가는 변 둘로 닫는다 — 그 변 둘이
정확히 지도 끝에 놓여야 자른 조각의 경계와 겹쳐 **지도 안쪽에 틈새 선이 남지
않는다**. 처음에는 고리의 시작 경도(동경 150° 부근)에 틈새를 넣었다가 남극
반도 옆에 사선이 그려져 고쳤다(2026-09-08).

투영한 뒤 지도 상자로 한 번 더 자른다 — 인쇄 렌더러는 클립을 받지 않으므로
도안이 종이 밖으로 나가는 도형을 만들면 안 된다.

### 3.3 데이터

Natural Earth `ne_50m_land`(퍼블릭 도메인). 110m에는 한반도·일본·타이완의
윤곽이 뭉개지고 제주·하와이·괌이 없다 — 도시 칸이 바다 한가운데 찍히면 지리
공부라는 목적이 무너진다. 1.6MB짜리 원본을 저장소에 두는 대신 Douglas–Peucker
0.1°(종이 위 0.08mm)로 단순화하고 긴 변 0.12° 아래의 섬은 버려 243KB로
줄였다(꼭짓점 6만 → 1.3만). 구멍(카스피해)은 남긴다 — 한 폴리곤의 고리를 한
`<path>`에 넣으면 nonzero 채움에서 반대 방향 고리가 구멍이 된다.

### 3.4 잉크

바다는 칠하지 않는다. 종이의 3분의 2가 바다라 채우면 잉크를 통째로 먹는다.
땅만 옅은 모래색(`#efe4c6`), 해안선 0.22mm. 흑백으로 뽑으면 땅이 옅은 회색이
되어 여전히 바다와 갈린다.

## 4. 판의 얼개 — 종이는 도시 수를 따른다

| 도시 수       | 종이 | 크기 (mm) | A4  | 지도 높이 |
| ------------- | ---- | --------- | --- | --------- |
| 50            | A4   | 297 × 210 | 1장 | 150.62    |
| 60 · 70       | A3   | 420 × 297 | 2장 | 213.01    |
| 80 · 90 · 100 | A2   | 594 × 420 | 4장 | 301.24    |

사용자 제안(2026-09-08)이다 — "도시 갯수가 늘어나면 A4 2장으로 확대하고 더
늘어나면 최대 4장까지". **배율로 키우는 것과 다르다.** 배율은 A4에서 이미
밀려난 배치를 그대로 키울 뿐이다. 칸(6.6mm)·말(13mm)·이름 글자(2.3mm)·화살표는
실물 치수로 두고 **지도만** 키우므로 같은 유럽 땅에 칸이 들어갈 자리가 두 배·
네 배가 되고, 칸이 실제 위치 가까이 앉는다(6절의 실측).

A4 기준 틀은 세 띠다:

| 띠        | y (mm, A4)   | 내용                                   |
| --------- | ------------ | -------------------------------------- |
| 제목·범례 | 0 – 25       | 제목 9mm, 특수칸 범례 다섯(두 열)      |
| 지도      | 25 – 175.62  | 로빈슨 세계 전도, 폭 297 = 높이 150.62 |
| 놀이 안내 | 175.62 – 210 | 놀이 요령 두 줄 · 경로 · 지도 출처     |

A3는 A4의 √2배, A2는 2배라 **띠·지도·제목 글자는 이 틀에 배율 k(1 · √2 · 2)를
곱한 것**이다(`frameFor`). 범례의 표식 견본만은 판 위 표식과 같은 실물 크기다.
A4 여러 장으로 나누는 일은 인쇄 파이프라인이 한다(`IDE-007`).

지도 높이 150.62는 로빈슨 가로세로비(≈ 1.972)에서 나온 값이다. A4 가로에
세계 전도를 폭 가득 놓으면 위아래 59mm가 남고, 그 자리가 원본이 제목 띠와
설명문을 두었던 곳이다.

## 5. 도시와 경로

**배열의 차례가 곧 기본 경로다.** 서울 → 태평양 → 남아메리카 → 북아메리카 →
북극해 → 유럽 → 아프리카 → 서남아시아 → 남·동남아시아 → 오세아니아 → 동아시아
→ 서울. 동아시아 구간은 사용자가 준 차례에 없었지만, 시드니에서 한국까지 한
칸으로 뛰지 않으려고 넣었다. 제주는 뺐다(2026-09-08) — 서울과 함께 적기엔 너무
조밀하다. **실제 경로는 사용자가 만들기 화면에서 정한다** — 도시를 켜고 끄고
차례를 바꾸면 그 목록이 곧 경로이고, 여기 차례는 켤 때 끼어드는 자리와
프리셋의 차례를 정한다.

프리셋은 **중첩**이다 — 50 · 60 · 70 · 80 · 90 · 100. 도시마다 `rank`(처음
들어오는 프리셋)가 있고 `rank ≤ N`이 프리셋 N이다. `rank 0`은 토글(`IDE-016`)로만
켜는 도시다. 서울·제주는 고정. 풀은 113개다.

설계 중 바꾼 것:

- **북극해는 알래스카 → 북극점 → 무르만스크다.** 처음엔 레이캬비크·누크·
  이칼루이트를 북극해 구간으로 잡았는데, 태평양 중심 지도에서 그 셋은 대서양
  양쪽에 갈라져 있어 화살표가 종이 끝을 넘어야 했다. 원본도 알래스카에서
  북극해를 건너 스칸디나비아로 갔다. 북극점은 도시가 아니지만 중앙 자오선
  꼭대기에 두었다 — 원본의 북극곰 자리다.
- **앵커리지는 50 프리셋이다.** 70으로 두었더니 50개 판에서 샌프란시스코 →
  북극점 화살표가 북태평양을 통째로 건넜다. 대신 헬싱키를 60으로, 괌을 70으로
  내렸다.
- **유럽 차례는 50개 판이 깨끗하게 나오도록 잡았다** — 모스크바 → 베를린 →
  암스테르담 → 런던 → 파리 → 로마 → 마드리드. 처음엔 모스크바 다음이 런던이라
  그 화살표가 암스테르담·베를린을 가로질렀다. 60 이상에서 들어오는 도시(헬싱키·
  스톡홀름·오슬로·레이캬비크·빈…)는 그 사이에 끼워 넣는다.
- 사이판은 뺐다. 괌과 200km라 종이 위에서 2mm다.
- **90·100 프리셋**을 위해 토글 전용이던 도시 20개를 올리고 12개(부산·하노이·
  양곤·바르셀로나·뮌헨·코펜하겐·하르툼·루안다·덴버·보스턴·메데인·수바)를 토글
  전용으로 더했다.

특수칸 열넷의 자리와 이유는 `cities.ts`의 `SPECIALS`에 있다. 종류는 넷 —
급행·후퇴·다시·쉼. 급행·후퇴는 **주사위를 다시 굴려 그 수만큼** 앞·뒤로 간다
(2026-09-08 사용자가 규칙을 바꿨다 — 처음엔 적힌 번호로 갔고 "또 한 번"도
있었다). 목적지가 없으니 도시를 켜고 꺼도 아무것도 안 밀린다.

## 6. 칸 배치 — 점은 제자리, 원은 바다로

실제 위치대로 원을 놓으면 원이 **도시의 자리를 가린다**. 아이가 배워야 할 것이
바로 그 자리다(2026-09-08 사용자 지적 — "숫자는 가능한 지도 밖이나 위치와 관계
없는 곳으로"). 그래서:

1. **실제 위치에는 점**(반지름 0.9, 흰 테)을 찍는다. 점은 움직이지 않는다.
2. **번호 원은 가까운 빈 바다에** 앉힌다. 지도 상자를 1mm 격자로 나눠 땅·바다를
   판별해 두고(`landmask.ts`, 폴리곤 주사선 채움·짝수홀수 규칙으로 카스피해 같은
   구멍은 바다), 원의 중심부(반지름의 55%)가 바다인 자리를 찾는다. 원 전체를
   요구하면 A4에서 지중해·발트해·홍해가 다 탈락해 로마가 발트해로 밀려난다.
3. 바다가 멀면(값 기준 5mm 넘게) **땅에 앉힌다** — 모스크바·덴버·델리 같은 내륙
   도시와, 영국해협(A4에서 폭 1mm)이 바다로 안 잡히는 런던이 그렇다.
4. 원과 점은 **언제나 가는 선으로 잇는다**.

자리는 **탐욕 배치**로 정한다. 경로 차례대로 한 도시씩, 실제 위치에서 가까운
격자점부터 훑어 조건을 다 만족하는 자리 가운데 **값이 가장 작은** 곳에 앉힌다.
값 = 실제 위치까지 거리 + 0.4 × 앞 칸까지 거리 — 뒤엣것이 없으면 가장 가까운
빈 바다만 좇아 경로가 지그재그가 된다. 조건은:

- 발자국(원 + 이름표 + 표식)이 지도 안에 있고 먼저 앉은 발자국과 겹치지 않는다.
- 원·표식이 어느 도시의 점도 덮지 않는다(1차에서는 이름표도).
- 이 원의 이음선과 앞 칸에서 오는 화살표가 먼저 앉은 원을 지나지 않고, 이 원이
  먼저 그어진 선 위에 앉지 않는다 — 선이 원 아래를 지나면 길이 그 칸을 들르는
  것처럼 보인다.

앞서 쓰던 "겹치면 반씩 밀어내기" 반복은 점을 장애물로 두자 표류했다 — 원이 점과
이웃 원 사이에서 튕기며 카이로 원이 로마까지 흘러갔다. 탐욕 배치는 진동이 없고,
같은 입력이면 같은 배치이며(커밋된 SVG가 생성기와 같아야 한다), 빈 자리가 있으면
반드시 찾는다. 결과(2026-09-08):

| 도시 수 | 종이 | 바다에 앉은 원 | 평균 밀림 | 최대 밀림     |
| ------- | ---- | -------------- | --------- | ------------- |
| 50      | A4   | 37             | 8.6mm     | 19.1mm        |
| 70      | A3   | 55             | 8.5mm     | 28.0mm (파리) |
| 100     | A2   | 78             | 8.0mm     | 18.2mm        |

점을 덮지 않으려면 원이 최소 5.4mm는 떨어져야 하므로 평균이 그 위다. 원이 어느
도시의 점도 덮지 않는 것은 테스트가 프리셋 여섯 전부에서 본다.

| 치수         | 값                | 왜                                                           |
| ------------ | ----------------- | ------------------------------------------------------------ |
| 칸 반지름    | 3.3mm             | 두 자리 번호(3mm)가 들어가고 말(13mm)이 덮어도 이름이 남는다 |
| 서울 반지름  | 4.6mm             | "출발/도착" 두 줄                                            |
| 이름 글자    | 2.3mm             | 100%에서 읽히는 하한                                         |
| 실제 위치 점 | 0.9mm + 흰 테 0.5 | 땅색 위에서 도드라진다                                       |
| 점 둘레 여유 | 1.2mm             | 원·표식이 이 안으로 못 들어온다                              |
| 발자국 여유  | 0.9mm             |                                                              |
| 화살표       | 0.7mm, 화살촉 2.4 | 원본처럼 빨강. 이웃 칸이 붙어 있어도 화살촉은 반드시 그린다  |

이름표 뒤에는 흰 바탕을 깐다. 화살표와 해안선이 글자를 지나가도 읽힌다.

## 7. 말과 주사위

**말은 지름 13mm 원판**이다. 세우는 말(텐트형)은 칸 간격 8mm 안에서 이웃 칸을
가리므로 쓰지 않았다. 색 테와 모양(동그라미·세모·네모·별·하트·마름모)이 말을
가르고, 색은 사용자가 고른다(레이어 `pc-token-<n>`에 `paint`). 이름은 아래쪽
흰 면에 `text` 배치로 찍힌다. 번호는 흰 면 안에 둔다 — 색 테 위에 찍으면 어두운
색에서 안 보인다.

**주사위는 한 변 22mm 십자 전개도**, 풀칠면 일곱. 축구 골대·야구 스탠드와 달리
풀을 쓴다 — 정육면체는 풀 없이 닫히지 않고, 던지는 물건이라 끼워 맞춘 모서리가
벌어지면 굴러가지 않는다. 마주 보는 면의 눈을 더하면 7이다.

**둘은 A6 가로(148×105) 한 장이다**(파트 `pieces`, 2026-09-11 사용자 요청). 처음엔
말(A7)과 주사위(120×100)가 따로라 종이가 두 장 나왔는데, 둘 다 두꺼운 종이에
뽑는 작은 부속이다. 위 18mm가 제목 띠, 왼쪽에 전개도(94×66), 오른쪽에 말이
2×3으로 앉는다. 주사위의 접는선·풀칠면이 있어 파트는 조립물이다.

## 8. 값에서 그때 그리기 — 동적 파트

사용자가 "전체 도시 목록에서 체크한 도시만, 조정한 차례대로" 판에 보이길
원했다(2026-09-08). 미리 그려 둔 SVG로는 안 된다 — 2^113개 집합을 그려 둘 수
없다. 그래서:

- **목록 슬롯 `cities`**(스키마의 새 종류 `list`)가 켠 도시 id를 차례대로 든다.
  서울은 고정(`fixed`), 최소 5개. 프리셋 여섯(50~100)은 등급(`rank`)에서 나온다.
- **틀 슬롯 `board-frame`**(choice)이 `map`이면 제목·안내 띠 없이 **지도만**
  낸다 — 판 높이가 지도 높이(A4에서 150.62mm)가 된다.
- 게임판 파트는 `dynamic`이다. 크기는 켠 도시 수가 정하는 단계(`sizeSteps` =
  `PAPER_STEPS`)에서 스키마가 계산하고, 그림은 `artwork/dynamic.ts`가 그린다.
  등록소 `lib/games/dynamic-artwork.ts`가 서버에서 부른다 — 미리보기는
  `POST /api/games/world-tour/artwork`, 내보내기는 같은 함수. 두 길이 같은
  함수라 화면과 PDF가 같은 그림이다.
- 서울이 목록 가운데 있어도 서울부터 시작하도록 돌린다. 번호는 목록 차례다.
- **검색해서 더한다**(2026-09-08 사용자 요청). 풀 밖의 도시는 Natural Earth
  `ne_10m_populated_places`(7,342곳, 한국어 이름·나라 포함, 퍼블릭 도메인)에서
  서버가 찾는다(`search/search.ts`, 데이터는 `npm run fetch:cities`). 찾은 도시는
  `{ id: 'ne-<id>', label, data: { lon, lat } }`로 목록 값에 실려 저장되고, 렌더러가
  그 경위도로 칸을 그린다. 풀의 도시와 같은 곳(이름이 같거나 0.5° 안)은 풀의
  옵션으로 접는다 — 파리가 둘 나오면 안 된다. 외부 지오코더를 쓰지 않는 이유는
  같은 질의에 늘 같은 답이 나와야 하고 테스트에서도 돌아가야 해서다.
- 정적 `board.svg`는 기본값(50개, 띠 포함)으로 그린 파일이고 썸네일이 쓴다.
  다른 프리셋의 정적 파일은 없앴다.

## 9. 스키마와의 관계

**마커 슬롯이 하나도 없다.** 말은 놀이 중에 움직이므로 인쇄물이 자리를 기억할
이유가 없고, 칸은 도안이 정한다. `styleSets`·`presets`가 비어 있는 첫 게임이다.
스키마는 고치지 않았다.

스키마를 두 번 넓혔다(`IDE-016`). 1단계 **파트 변형**(`variants`)으로 도시 수
프리셋 사이를 오갔고, 2단계 **목록 슬롯 + 동적 파트**로 개별 도시 토글과 차례
편집을 받았다(8절). 축구·야구는 손대지 않고 그대로 통과한다.
